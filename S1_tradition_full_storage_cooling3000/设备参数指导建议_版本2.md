## 二、冷水机组性能数据 —— 4°C 额定文件生成

### 2.1 问题回顾

三台冷机共享同一份性能文件（Samp_C1/C2/C3.Dat 内容完全一致），额定点均为 CHWT=7°C / CWT=30°C。蓄冷机组（冷机 3）实际出水 4°C，导致容量虚高 6.7%。

### 2.2 两种修正方案

**方案 A（推荐，已执行）：生成 4°C 额定性能文件**

已生成 `Samp_C3_4C.Dat`，位于 `full_storage/Samp_C3_4C.Dat`。

编制逻辑：将原文件所有 capacity ratio 除以 0.9334，所有 COP ratio 除以 0.9394，使额定点移至 CHWT=4°C / CWT=30°C。关键验证点：

| 工况 (CHWT/CWT) | 原 capacity | 新 capacity | 原 COP | 新 COP |
|---|---|---|---|---|
| 4/30（新额定点） | 0.9334 | **1.0000** ✓ | 0.9394 | **1.0000** ✓ |
| 7/30（旧额定点） | 1.0000 | **1.0716** | 1.0000 | **1.0645** |

使用方式：

1. 在 TRNSYS Studio 中打开冷机 3（Unit 35）的属性面板
2. 将 `Logical Unit - Performance Data` 对应的文件从 `Samp_C3.Dat` 改为 `Samp_C3_4C.Dat`
3. **额定容量保持 10,800,000 kJ/hr（3000 kW）不变**——因为现在额定点就是 4°C，不需要放大

**方案 B（备选）：维持 7°C 额定文件，上调额定量**

如果不想换文件，可将冷机 3 的 Rated Capacity 从 10,800,000 → **11,570,000 kJ/hr**（≈3,214 kW），使 4°C 工况实得 3,000 kW。

### 2.3 权衡

| | 方案 A（换文件） | 方案 B（调容量） |
|---|---|---|
| 操作复杂度 | 中等（需在 Studio 中改文件引用） | 低（改一个数字） |
| 概念清晰度 | 高——铭牌容量=额定点容量 | 中——铭牌标 3214 kW 但实际只出 3000 |
| 7°C 工况行为 | 冷量=3214 kW（超出设计） | 冷量=3000 kW |
| 推荐 | ✅ | 可接受 |

## 三、蓄水罐散热参数 —— 何处修改、影响分析

### 3.1 当前设置分析

你的 Type534 蓄水罐散热涉及**两个层面**：

**层面 1：散热系数（在 Example_534.dat 中设置）**

你提到已设置：
- Node Edge Loss Coefficient：每个节点 = **5 kJ/hr-m²-K**
- Top Loss Coefficient：**5 kJ/hr-m²-K**（推测）
- Bottom Loss Coefficient：**5 kJ/hr-m²-K**（推测）

当前工作区的 `Example_534.dat` 中 node edge loss coefficient 仍显示为大部分 3（仅第 15 节点为 5），可能是因为：
- 你修改的是 `D:\Trnsys18\T\...\S1_tradition_full_storage_cooling3000\Example_534.dat`（已被 TRNSYS 载入）
- 本地工作区副本未同步

> **修改位置**：用文本编辑器打开 `Example_534.dat`，找到第 43-67 行（25 个节点的 edge loss coefficient），统一改为 5。Top/Bottom Loss Coefficient 在该文件的更前面——第 5 行当前是 `0`（总体散热系数），如果 Type534 版本支持独立顶/底系数，它们通常在节点散热系数之前或之后的单独字段。

**层面 2：散热环境温度（在 dck 中，初始值设置）**

在 Project11.dck 中，Unit 7 的输入 5（Top Loss Temperature）、输入 6-30（Edge Loss Temperature，25 个节点）、输入 31（Bottom Loss Temperature）全部标记为 `[unconnected]`，使用初始值 **20°C**。

这意味着：无论水箱水温是 4°C 还是 12°C，模型都用 20°C 作为环境温度计算散热。

> **修改位置**：在 TRNSYS Studio 中打开 Type534 组件属性，找到 **Inputs** 标签页，为 "Top Loss Temperature"、"Edge Loss Temperature"（每个节点）和 "Bottom Loss Temperature" 连接一个气象数据来源（例如天气文件的干球温度），或直接设置常数。

### 3.2 散热影响量化

按你的设置（edge/top/bottom loss coeff = 5 kJ/hr-m²-K，环境温度 = 20°C）：

| 部位 | 面积 (m²) | 平均 ΔT (K) | 散热量 (kJ/hr) |
|---|---|---|---|
| 侧壁（25 节点） | ~910 | ~10 | 910 × 5 × 10 = **45,500** |
| 顶部 | ~141 | ~16 | 141 × 5 × 16 = **11,280** |
| 底部 | ~141 | ~16 | 141 × 5 × 16 = **11,280** |
| **合计** | | | **68,060 kJ/hr ≈ 18.9 kW** |

- 日散热量 ≈ 18.9 × 24 = **454 kWh**
- 占蓄冷量比例 ≈ 454 / 17,577 = **2.6%**
- 24h 损失不到 3%，在工程合理范围（通常 2-5%）

### 3.3 建议

| 参数 | 当前 | 建议 | 理由 |
|---|---|---|---|
| Node Edge Loss Coeff | 5（声称）/ 3（文件） | **统一为 5** | 5 对应约 100mm 聚氨酯保温，合理 |
| Top Loss Coeff | 5（声称）/ 0?（文件） | **5** | 与侧壁保温等级一致 |
| Bottom Loss Coeff | 5（声称）/ 0?（文件） | **3-5** | 底部通常保温略薄，但若地面有混凝土层可略低 |
| Edge Loss Temperature | 20°C（固定） | **连接天气文件干球温度** | 20°C 代表室内/机房温度，如果水罐在室外或半室外，应接实时气温 |

## 四、Unit 33 用户回水泵 —— 并联方案设计

### 4.1 现有问题

Unit 33（用户回水泵）当前额定流量 **236,000 kg/hr**，功率 94,000 kJ/hr（26.1 kW）。Type114 为定速泵，开启后流量不可调。

但实际运行中，供应侧总流量有三种情况：

| 运行模式 | 供应侧构成 | 总流量 (kg/hr) |
|---|---|---|
| 模式 A：1 台基载冷机 | 冷冻水泵 1 (Unit 10) | **150,300** |
| 模式 B：2 台基载冷机 | 冷冻水泵 1 + 2 (Unit 10+13) | **300,600** |
| 模式 C：水箱释冷 | 供冷水泵 (Unit 6) | **322,200** |

当前 236,000 是三种流量的折中值，不匹配任何一个，会导致质量不平衡。

### 4.2 核心发现：300,600 与 322,200 只差 7%

| 流量 A | 流量 B | 差异 |
|---|---|---|
| 300,600（2 冷机） | 322,200（水箱） | +7.2% |

这个差异足够小，可以共用一台泵，而不需要三台独立泵。

### 4.3 推荐方案：2 台并联泵

```
建筑回水 (Unit 28)
    ├── 并联泵 A（小泵）──┐
    └── 并联泵 B（大泵）──┤
                          ↓
                    混合器 (Type11h)
                          ↓
                    分流器 (Unit 29)
```

| 泵编号 | 额定流量 (kg/hr) | 额定功率 (kJ/hr) | 额定功率 (kW) | 扬程 (m) | 对应模式 |
|---|---|---|---|---|---|
| **Pump_33_small** | 150,300 | 60,700 | 16.86 | ~41.1 | 模式 A（1 冷机） |
| **Pump_33_large** | 322,200 | 130,000 | 36.11 | ~41.1 | 模式 B（2 冷机）/ 模式 C（水箱） |
| 两泵同时开 | **472,500** | 190,700 | 52.97 | ~41.1 | 未来联合供冷模式 |

> 扬程与冷冻水侧其他水泵一致（41.1 m），水力设计协调。

### 4.4 控制策略

```
IF 蓄冷时段 THEN
    IF Load < 1550 kW THEN
        Pump_33_small = ON,   Pump_33_large = OFF   → 流量 150,300 ✓
    ELSE
        Pump_33_small = OFF,  Pump_33_large = ON    → 流量 322,200 (≈300,600) ⚠
ELSE (非蓄冷时段)
    IF Tank_Has_Cold THEN
        Pump_33_small = OFF,  Pump_33_large = ON    → 流量 322,200 ✓
    ELSE
        IF Load < 1550 kW THEN
            Pump_33_small = ON,   Pump_33_large = OFF   → 流量 150,300 ✓
        ELSE
            Pump_33_small = OFF,  Pump_33_large = ON    → 流量 322,200 (≈300,600) ⚠
```

**关于 2 冷机模式的 7% 流量偏差：**

大泵输出 322,200，两冷机各分约 161,100（而非设计 150,300）。每台冷机流量偏大 7%，CHW ΔT 从 8K 降至约 7.5K。Type666 冷机模型根据实际流量和进口温度计算出口温度，不会因此出错——只是 ΔT 略小于设计值，不影响冷量输出。

> 在工程仿真精度范围内，7% 的流量偏差是可接受的。如果你希望严格精确，可以添加第三台泵（150,300），但控制逻辑变复杂，ROI 不高。

### 4.5 在 TRNSYS Studio 中的实施步骤

1. 删除或禁用现有 Unit 33（236,000 kg/hr）
2. 添加两个新的 Type114 水泵：
   - Pump_33_small：额定流量 150300，功率 60700
   - Pump_33_large：额定流量 322200，功率 130000
3. 添加一个 Type11h 混合器（Tee-Piece Flow Mixer, mode=1），接收两泵出口
4. 将混合器出口连接至原 Unit 33 的下游（分流器 Unit 29）
5. 在 Equation 中添加控制信号：
   ```
   PumpSmall_ON = (mode_is_1chiller)
   PumpLarge_ON = (mode_is_2chiller) OR (mode_is_tank)
   ```
   将这两个信号分别接入 Pump_33_small 和 Pump_33_large 的 Control Signal 输入
