# 传统集中供冷系统：冷机直供10°C、蓄冷4°C动态设定修改指南

## 1. 修改目标与当前状态

目标运行逻辑：

| 运行模式 | 冷机冷冻水出水设定值 | 冷机状态 | 主要供冷路径 |
|---|---:|---|---|
| 蓄冷模式 `ChargeMode=1` | 4°C | 两台开启 | 冷机 → 蓄冷罐 |
| 释冷模式 `TankMode=1` | 冷机关闭，设定值仅作备用 | 两台关闭 | 蓄冷罐 → 建筑 |
| 冷机直供 `ChillerMode=1` | 10°C | 两台开启 | 冷机 → 建筑 |
| 停机 `OffMode=1` | 10°C，设定值不参与制冷 | 两台关闭 | 无 |

当前工程中两台 Type666 的第5输入均为：

```text
0,0  ! [unconnected] CHW Set Point Temperature
```

虽然 Type666 的初始输入值中第5项为4°C，但这只是初始值，不是动态控制。因此当前模型无论蓄冷还是冷机直供，实际上都没有通过 Equation 改变冷冻水出水设定值。

## 2. 最小修改方案

建议只修改以下位置：

1. `传统_新修改/Project11.dck` 的 Unit34 Equation：新增动态冷冻水设定值。
2. Unit9 Type666：第5输入接 `CHW_SP`。
3. Unit12 Type666：第5输入接同一个 `CHW_SP`。
4. 同步检查输出、日志和冷机性能表调用范围。

不建议新增独立控制Unit，因为Unit34已经集中定义了 `ChargeMode`、`TankMode`、`ChillerMode` 和两台冷机启停信号，新增Unit反而会增加信号追踪和收敛复杂度。

## 3. Unit34 Equation 修改

### 3.1 修改方程数量

当前为：

```text
EQUATIONS 48
```

新增以下4条Equation后改为：

```text
EQUATIONS 52
```

建议放在现有 `T_cold_sp`、`T_warm_ref`、`dT_dead` 之后，模式判断之前或之后均可，但必须保证在冷机输入引用前已经定义。

### 3.2 推荐新增公式

```text
T_CHW_CHARGE = 4 ! 蓄冷模式冷机冷冻水出水设定值，°C
T_CHW_DIRECT = 10 ! 冷机直接供建筑时的冷冻水出水设定值，°C
T_CHW_OFF = 10 ! 冷机关闭或释冷模式下的备用设定值，°C；此时不产生制冷
CHW_SP = max(4,min(10,T_CHW_CHARGE*ChargeMode + T_CHW_DIRECT*ChillerMode + T_CHW_OFF*(TankMode+OffMode))) ! 两台Type666共用的动态冷冻水出水设定值
```

公式含义：

- `ChargeMode=1` 时，`CHW_SP=4°C`；
- `ChillerMode=1` 时，`CHW_SP=10°C`；
- `TankMode=1` 或 `OffMode=1` 时，冷机关闭，`CHW_SP=10°C` 只是备用值；
- `max/min` 将输出限制在4–10°C，防止模式信号出现瞬态叠加时产生不合理设定值。

如果你希望停机时保留4°C备用值，也可以把 `T_CHW_OFF=4`，但这不改变停机能耗；从模式切换的连续性看，停机备用值设为10°C更接近下一次直供工况。

### 3.3 模式互斥检查

Unit34中现有：

```text
ChargeMode = ChargeWindow*Chg_bySOC
TankMode = LoadWindow*TankCanCover*(1-ChargeMode)
ChillerMode = LoadWindow*(1-TankCanCover)*(1-ChargeMode)
OffMode = (1-ChargeMode)*(1-TankMode)*(1-ChillerMode)
```

理论上四种模式应满足：

```text
ChargeMode + TankMode + ChillerMode + OffMode = 1
```

因此动态设定值切换的前提是模式互斥。建议保留或新增监测量：

```text
ModeSumCheck = ChargeMode+TankMode+ChillerMode+OffMode
```

验收时应满足 `ModeSumCheck=1`；如果不是1，先修正模式逻辑，不要直接调冷机设定温度。

## 4. Type666输入连接修改

### 4.1 Unit9 冷机1

在 `UNIT 9 TYPE 666` 的 `INPUTS 6` 中，将：

```text
0,0  ! [unconnected] CHW Set Point Temperature
```

替换为：

```text
CHW_SP  ! Unit34:动态冷冻水出水设定值，蓄冷4°C、直供10°C
```

完整相关输入应为：

```text
14,1       ! 分流阀-2 outlet1温度 → 冷机1冷冻水入口温度
14,2       ! 分流阀-2 outlet1流量 → 冷机1冷冻水流量
53,1       ! 冷却水泵1-1出口温度 → 冷机1冷却水入口温度
53,2       ! 冷却水泵1-1出口流量 → 冷机1冷却水流量
CHW_SP     ! Unit34动态冷冻水出水设定值
Chiller1_ON ! Unit34冷机1启停信号
```

### 4.2 Unit12 冷机2

将：

```text
0,0  ! [unconnected] CHW Set Point Temperature
```

替换为：

```text
CHW_SP  ! Unit34:动态冷冻水出水设定值，蓄冷4°C、直供10°C
```

完整相关输入应为：

```text
14,3       ! 分流阀-2 outlet2温度 → 冷机2冷冻水入口温度
14,4       ! 分流阀-2 outlet2流量 → 冷机2冷冻水流量
54,1       ! 冷却水泵2-1出口温度 → 冷机2冷却水入口温度
54,2       ! 冷却水泵2-1出口流量 → 冷机2冷却水流量
CHW_SP     ! Unit34动态冷冻水出水设定值
Chiller2_ON ! Unit34冷机2启停信号
```

两台冷机必须共用同一个 `CHW_SP`，否则蓄冷和直供时两台冷机可能产生不同的冷冻水出水温度，Unit14的50%分流会失去对称性。

### 4.3 初始输入值

当前仿真从 `START=3216 h` 开始，而 `3216 mod 24=0`，通常处于0:00–8:00蓄冷窗口。因此两台 Type666 的初始输入第5项建议仍保持4：

```text
12.22 215000 30.0 399600 4 0
```

Equation开始计算后，`CHW_SP`会按照当前模式动态切换。若以后修改START到白天直供时段，则初始第5项应同步改为10，避免第一个迭代步出现4→10的非物理跳变。

## 5. 必须理解的流量与回水温度问题

当前Unit34使用：

```text
DTCHW = 8
MREQ = LoadKW*3600/(CpW*DTCHW)
MDCHREQ = 1.10*MREQ
```

这里的 `DTCHW=8 K` 是建筑负荷流量换算所采用的设计供回水温差，不是Type666的冷冻水出水设定值。

### 推荐做法：保留DTCHW=8 K

如果保持当前公式不变，直供模式下：

```text
供水温度 = 10°C
设计温差 = 8 K
建筑回水温度 ≈ 18°C
```

Type682会根据：

```text
Q_load = m*CpW*(T_return-T_supply)/3600
```

自动得到约18°C的建筑回水。这样不会改变现有供冷泵额定流量和控制信号，属于本次修改的最小、稳定方案。

### 不推荐做法：把DTCHW改成2 K

只有当你明确要求建筑回水仍保持12°C时，才有：

```text
DTCHW_DIRECT = 12-10 = 2 K
```

但在约3140 kW峰值负荷下：

```text
MREQ = 3140*3600/(4.19*2) ≈ 1,348,926 kg/h
1.10*MREQ ≈ 1,483,819 kg/h
```

这远超两台供冷泵合计430,000 kg/h，也远超两台Type666单台冷冻水流量配置。因此不能在现有设备规模下把直供温度提高到10°C、同时强行保持12°C回水。

采用当前8 K设计温差时，3140 kW峰值负荷对应：

```text
MREQ ≈ 337,232 kg/h
1.10*MREQ ≈ 370,955 kg/h
```

仍低于430,000 kg/h总额定流量，现有供冷泵容量可以覆盖。

## 6. 蓄冷罐相关逻辑是否需要联动修改

### 不需要修改的变量

以下变量描述的是水箱状态，不是建筑直供冷机设定值，应继续保持：

```text
T_cold_sp = 4
T_warm_ref = 12
SOC = max(0,min(1,(T_warm_ref-[7,5])/(T_warm_ref-T_cold_sp)))
TankFull = lt([7,18],T_cold_sp+0.5)*lt([7,30],T_cold_sp+dT_dead)
TankEmpty = gt([7,42],T_warm_ref-dT_dead)*gt([7,30],T_warm_ref-3)
```

不能因为建筑直供设为10°C，就把 `T_cold_sp` 改成10°C。否则会把水箱“冷态”判定从4°C错误地放宽到10°C，蓄冷量SOC、蓄满和释冷许可都会失真。

### 需要重点确认的变量

`T_warm_ref=12°C` 是水箱暖态参考温度，同时原注释中也把它近似当作设计回水温度。直供温度改为10°C后，建筑直供回水在当前8 K流量设计下约为18°C，因此这两个概念不应再混写：

- `T_warm_ref=12°C`：继续作为蓄冷罐状态参考值；
- 建筑直供回水：由Type682按实际流量和负荷计算，约为18°C；
- 若要表达建筑回水设计值，应新增独立变量，例如 `T_RETURN_BUILDING_DESIGN=18`，不要复用`T_warm_ref`。

建议修改注释而不是修改水箱判定公式：

```text
T_warm_ref = 12 ! 蓄冷罐暖态参考温度；不再解释为直供建筑回水温度
```

## 7. 其他设备和信号是否需要联动修改

### 7.1 不需要修改的控制信号

冷机出水设定值变化不改变以下启停关系：

```text
Chiller1_ON = max(ChargeMode,ChillerMode)
Chiller2_ON = max(ChargeMode,ChillerMode)
Tower1_ON = Chiller1_ON
Tower2_ON = Chiller2_ON
```

冷却塔仍必须与对应冷机同步开关。

当前冷却水泵配对也应保持：

```text
Unit53 → CHWP1_CTRL
Unit55 → CHWP1_CTRL
Unit54 → CHWP2_CTRL
Unit56 → CHWP2_CTRL
```

当前文件已经是这一配对；尤其要避免把Unit54误接回`CHWP1_CTRL`。

### 7.2 不建议因为10°C而修改Gamma信号

以下逻辑仍然正确：

```text
Gamma24 = ChargeMode
Gamma29 = ChillerMode
Gamma14 = 0.5*max(ChargeMode,ChillerMode)
```

- 蓄冷时，Unit24将冷机4°C水送入蓄冷罐；
- 直供时，Unit24将冷机10°C水送向建筑；
- 释冷时，Unit29将建筑回水送回蓄冷罐；
- 直供时，Unit29将建筑回水送回两台冷机。

### 7.3 冷却水泵信号的工程限制

当前冷却水泵信号按供冷水泵信号联动，这一简化仍可保留：

```text
CWPump1_ON = CHWP1_CTRL
CWPump2_ON = CHWP2_CTRL
```

但10°C直供会改变冷机容量和COP，冷机排热量也可能改变。因此最终工程模型应检查：

```text
冷却水实际流量 ≥ 冷机排热量所需流量
```

如果采用厂家冷却水流量控制，应根据Type666实际排热量重新计算冷却水泵控制信号，而不是永久假定冷冻水泵与冷却水泵信号完全相同。

## 8. Type666性能表检查

当前 `Samp_C3_1C.Dat` 和 `Samp_C3_2C.Dat` 的冷冻水出水温度数据列为：

```text
4  5  6  7  8  9  10 °C
```

因此4°C和10°C都在性能表范围内，不需要修改Type666性能表插值范围。10°C不是越界输入。

不过，性能表给出的10°C工况能力和COP与4°C不同，改变设定值后应重新检查：

1. 冷机实际制冷量是否满足建筑负荷；
2. 冷机PLR是否仍在性能表有效范围；
3. 供水温度10°C是否满足末端显热和潜热需求；
4. 冷机直供时建筑回水是否出现约18°C；
5. 直供模式下Type666是否出现低温/高温性能表越界警告。

当前Type666文件已有少量性能表独立变量越界警告，主要是冷却水入口温度低于性能表下限16°C，不应误认为是10°C冷冻水设定值导致的全部问题。

## 10. 验收标准

### 10.1 信号验收

必须满足：

```text
ChargeMode=1  → CHW_SP=4
ChillerMode=1 → CHW_SP=10
TankMode=1    → Chiller1_ON=0, Chiller2_ON=0
OffMode=1     → Chiller1_ON=0, Chiller2_ON=0
```

### 10.2 水力验收

检查：

```text
建筑供水温度 ≈ 10°C（直供模式）
建筑回水温度 ≈ 18°C（保留DTCHW=8时）
冷机蒸发器入口温度与回水路径一致
两台冷机冷冻水流量约各承担一半
```

### 10.3 能量验收

分别积分：

```text
冷机耗电
冷却塔耗电
冷却水泵耗电
供冷水泵耗电
释冷/蓄冷水泵耗电
建筑实际供冷量
未满足负荷量
```

不能只看总电耗。10°C直供可能使冷机性能变化，但如果建筑供冷量或末端温度不满足要求，不能把较低电耗认定为节能。

## 11. 最终判断

### 可以直接执行的最小修改

可以在Unit34增加`CHW_SP`，并将Unit9、Unit12的第5输入均改接`CHW_SP`。这是正确且最小的控制修改。

### 本次暂不联动修改

在你接受“直供10°C、仍按8 K设计温差计算流量、建筑回水约18°C”的前提下，暂不修改：

- 水箱4°C冷态判定；
- 水箱12°C暖态判定；
- `MREQ`和泵额定流量；
- 冷机、冷却塔和冷却水泵启停逻辑；
- Unit14、Unit24、Unit29分流信号。

### 必须在结果分析中明确的限制

Type682当前是流体负荷模型，主要执行显热能量平衡，不能证明10°C供水一定满足真实建筑末端的除湿和潜热需求。若研究对象包含湿负荷，必须另外增加末端湿度/潜热模型或把10°C仅作为敏感性工况，而不能直接解释为完整空调舒适性结论。

## 12. 本次检查发现的既有风险

当前日志仍有：

- 约1%的不收敛时步；
- 多台Type110泵质量平衡失败；
- Type31管道流量容量警告；
- Type666性能表独立变量低于数据范围的警告。

这些问题不是本次动态设定值修改才产生的，但在比较4°C蓄冷和10°C直供能耗前，应至少确认模式切换时的不收敛次数没有增加。

**建议验收顺序：先验证`CHW_SP`信号和两台冷机输入，再验证供回水温度，再验证冷量满足率，最后比较能耗。**
