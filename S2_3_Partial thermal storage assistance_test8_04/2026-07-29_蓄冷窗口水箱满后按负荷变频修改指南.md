# 蓄冷窗口内水箱蓄满后按建筑负荷变频的修改指南

日期：2026-07-29  
适用工程：`传统_中央空调/Project11.tpf`、`Project11.dck`  
修改基础：`2026-07-27_净负荷窗口全变频水泵Unit38控制Equation与系统连线复核.md`

## 1. 修改结论与权衡

本次只修改一种工况：

> 处于蓄冷窗口，水箱已经达到停止蓄冷条件，蓄冷窗口尚未结束，并且建筑仍有冷负荷。

原策略在该工况下保持两台冷机运行，同时令 Unit56、Unit57 的控制信号均为 `1`，使两台供冷水泵合计输送 `430000 kg/h`，并由 Unit35 将全部流量送往建筑。该策略满足水量守恒，但会造成低负荷时建筑侧过流、供回水温差降低和水泵能耗偏高。

建议改为：

- 两台冷机仍同时开启，`Chiller1_ON=Chiller2_ON=1`；
- Unit56、Unit57 均接收建筑需求流量对应的同一个 `LoadFrac` 信号；
- 建筑需求流量仍保留 10% 输送裕度；
- Unit35 在水箱已满时仍令全部冷机出水进入建筑，分流比例保持 `1`；
- Unit34 蓄冷支路泵保持 `0`，不再向已满水箱送水；
- 水箱已满且建筑无负荷时，两台冷机和 Unit56、Unit57 均停止。

这样做的代价是两台冷机在低负荷时同时部分负荷运行，机组效率未必优于“单机承担低负荷”的台数控制。但后者需要另外设置单/双机切换阈值、最小蒸发器流量和防频繁启停逻辑，不属于本次最小修改范围。

需要特别区分两个控制层次：`LoadFrac` 直接送给 Unit56、Unit57 的 Type110 水泵控制端，决定冷冻水质量流量；它不是直接送给 Type666 冷机的“制冷量比例”指令。两台冷机仍由 `Chiller1_ON`、`Chiller2_ON` 启停，实际制冷量由建筑负荷、蒸发器水流量和冷冻水出水温度设定共同决定。因此，“用 Unit56、Unit57 传递两台冷机冷量”在模型中的准确实现是“用变频泵流量使两台冷机按需供冷”。

## 2. 本次修改的边界与假设

1. Unit56、Unit57 均为 Type110 变频泵，单台额定流量为 `215000 kg/h`。
2. 两台泵额定总流量为：

   ```text
   215000 + 215000 = 430000 kg/h
   ```

3. 设计冷冻水供回水温差为 `8 K`，水的比热取 `4.19 kJ/(kg·K)`。
4. 负荷信号 `[22,1]` 的单位为 `kJ/h`，现有 Equation 已将其换算为 `kW`。
5. “达到蓄满条件”沿用现有 Unit38 的停止蓄冷判据，即 `Chg_bySOC=0`。它可能由 `SOC>=0.95` 或 `TankFull=1` 触发。本次不改变水箱蓄满判据本身。
6. 本次不改变非窗口释冷、非窗口双冷机直供以及窗口内水箱未满时的“负荷优先、余流蓄冷”逻辑。

## 3. 信号计算原理

现有负荷流量计算为：

```text
MREQ = LoadKW*3600/(CpW*DTCHW)
MLOAD_REQ = 1.10*MREQ
LoadFrac = min(1,max(0,MLOAD_REQ/MCHW_TOTAL_R))
```

其中：

- `MREQ`：不含裕度的建筑需求质量流量，`kg/h`；
- `MLOAD_REQ`：增加 10% 裕度后的建筑需求质量流量，`kg/h`；
- `MCHW_TOTAL_R=430000 kg/h`：Unit56、Unit57 的额定总流量；
- `LoadFrac`：应同时发送给 Unit56、Unit57 的 0～1 归一化信号。

注意，不能把每台泵的信号写成 `MLOAD_REQ/215000`。两台泵并联且均分总需求时，每台实际承担 `MLOAD_REQ/2`，所以单台泵的正确信号为：

```text
(MLOAD_REQ/2)/215000
= MLOAD_REQ/430000
= LoadFrac
```

因此，两台泵使用相同的 `LoadFrac` 后：

```text
Unit56流量 = 215000*LoadFrac
Unit57流量 = 215000*LoadFrac
两台总流量 = 430000*LoadFrac = MLOAD_REQ
```

当负荷需求超过系统额定总流量时，`LoadFrac` 被限制为 `1`，避免 Type110 收到大于 1 的控制信号。

## 4. Unit38 的最小 Equation 修改

### 4.1 修改前先备份

1. 关闭正在运行的 TRNSYS 求解。
2. 在 Simulation Studio 中对当前工程执行 `Save As`，另存为一个新版本，例如 `Project11_fulltank_vfd.tpf`。
3. 同时保留原 `Project11.dck`，不要直接覆盖唯一可用版本。

### 4.2 打开 Unit38

1. 在 Simulation Studio 主界面双击 Unit38“控制”。
2. 进入 Equation 编辑窗口。
3. 搜索以下变量：`CHWP1_CTRL`、`CHWP2_CTRL`、`Pump32_CTRL`。

当前目录中的 `Project11.dck` 写有 `EQUATIONS 63`。本方案只替换 3 条公式，不增加或删除 Equation，因此 Equation 总数应保持当前实际数值不变。原复核 Markdown 中的 `EQUATIONS 64` 与当前 DCK 不一致，不应仅依据文档标题数盲目改动。

### 4.3 替换 Unit56、Unit57 的控制公式

找到原公式：

```text
CHWP1_CTRL = max(WindowChillerMode,CHWP_Direct_CTRL)
CHWP2_CTRL = max(WindowChillerMode,CHWP_Direct_CTRL)
```

替换为：

```text
CHWP1_CTRL = max(WindowChargeMode,WindowLoadMode*(1-WindowChargeMode)*LoadFrac+CHWP_Direct_CTRL) ! Unit56：水箱未满时满流量蓄冷；窗口内停止蓄冷后及非窗口直供时按负荷变频
CHWP2_CTRL = max(WindowChargeMode,WindowLoadMode*(1-WindowChargeMode)*LoadFrac+CHWP_Direct_CTRL) ! Unit57：与Unit56相同，两台泵均分建筑需求流量
```

公式含义如下：

- 水箱未满、允许蓄冷：`WindowChargeMode=1`，两台泵信号均为 `1`；
- 水箱已达到停止蓄冷条件且建筑有负荷：`WindowChargeMode=0`、`WindowLoadMode=1`，两台泵信号均为 `LoadFrac`；
- 水箱已满且建筑无负荷：两项均为 `0`，两台泵停止；
- 非窗口双冷机直供：沿用 `CHWP_Direct_CTRL=DirectChillerMode*LoadFrac`；
- 非窗口水箱释冷：上述各项均为 `0`，Unit56、Unit57 停止。

原有两条映射公式保持不变：

```text
Pump10_ON = CHWP1_CTRL
Pump13_ON = CHWP2_CTRL
```

### 4.4 同步修改负荷支路流量监测量

当前 DCK 中没有实际的 Unit32，原公式注释也写有“已经删除unit32”；但 `Pump32_CTRL` 仍参与 `FlowSplitError` 质量守恒监测。若只修改 Unit56、Unit57 而不修改该变量，水箱已满时会出现虚假的分流误差。

找到原公式：

```text
Pump32_CTRL = min(1,WindowLoadMode*(WindowChargeMode*LoadFrac+(1-WindowChargeMode))+DirectChillerMode*LoadFrac)
```

替换为：

```text
Pump32_CTRL = min(1,(WindowLoadMode+DirectChillerMode)*LoadFrac) ! 负荷支路等效流量比例；水箱满后不再按1计
```

即使当前模型没有 Unit32，也应保留这次替换，使现有监测式继续成立：

```text
FlowSplitError = Pump32_CTRL+Pump34_CTRL-CHWP1_CTRL
```

### 4.5 以下公式不要修改

```text
Chiller1_ON = max(WindowChillerMode,DirectChillerMode)
Chiller2_ON = max(WindowChillerMode,DirectChillerMode)

Gamma35 = min(1,WindowLoadMode*(WindowChargeMode*LoadFrac+(1-WindowChargeMode))+DirectChillerMode)
Pump34_CTRL = WindowChargeMode*(1-LoadWindow*LoadFrac)
Gamma29 = min(1,WindowLoadMode+DirectChillerMode)
Gamma14 = 0.5*max(WindowChillerMode,DirectChillerMode)
```

保留 `Gamma35` 的原因是：水箱已满后冷机总出水已经由 Unit56、Unit57 降到 `MLOAD_REQ`，此时 Unit35 应取 `1`，把这部分水全部送往建筑，而不是再次乘以 `LoadFrac`。否则建筑实际流量会错误地变成：

```text
MLOAD_REQ*LoadFrac
```

这相当于对负荷比例重复缩放一次，会造成供水不足。

## 5. 控制连线复核

本次不需要重画水路，也不需要新增控制连线。应逐项确认：

| 设备 | 输入端 | 应连接的 Unit38 输出 | 本次处理 |
|---|---:|---|---|
| Unit56 供冷水泵1 | 输入3 Control signal | `Pump10_ON` | 保持连线，仅改变上游公式 |
| Unit57 供冷水泵2 | 输入3 Control signal | `Pump13_ON` | 保持连线，仅改变上游公式 |
| Unit34 蓄冷支路泵 | 输入3 Control signal | `Pump34_CTRL` | 保持不变 |
| Unit35 受控分流器 | 输入3 Control signal | `Gamma35` | 保持不变 |
| Unit58 释冷泵 | 输入3 Control signal | `DischargePump6_ON` | 保持不变 |
| 冷机1、冷机2 | Chiller Control Signal | `Chiller1_ON`、`Chiller2_ON` | 保持两台同时开启 |

现有冷却水泵信号由下列公式跟随 Unit56、Unit57：

```text
CWP1_CTRL = CHWP1_CTRL
CWP2_CTRL = CHWP2_CTRL
CWPump1_ON = CWP1_CTRL
CWPump2_ON = CWP2_CTRL
```

因此水箱满后，四台冷却水泵也会随冷冻水泵按相同比例变频。这里“比例相同”不表示冷却水和冷冻水的实际质量流量相同，而是各自相对于自身额定流量采用相同归一化信号。

## 6. 修改后的五种工况

| 工况 | Unit56/57 | Unit34 | Gamma35 | 建筑等效流量 | 结果 |
|---|---:|---:|---:|---:|---|
| 窗口内、未满、无负荷 | `1` | `1` | `0` | `0` | 全流量蓄冷 |
| 窗口内、未满、有负荷 | `1` | `1-LoadFrac` | `LoadFrac` | `MLOAD_REQ` | 负荷优先，余流蓄冷 |
| 窗口内、已满、有负荷 | `LoadFrac` | `0` | `1` | `MLOAD_REQ` | 两台冷机按负荷直供 |
| 非窗口、水箱可释冷 | `0` | `0` | `0` | 由Unit58承担 | 水箱供冷 |
| 非窗口、水箱不可释冷 | `LoadFrac` | `0` | `1` | `MLOAD_REQ` | 两台冷机按负荷直供 |

窗口内水箱已满且无负荷时，`WindowChillerMode=0`，两台冷机、Unit56、Unit57、冷却塔和冷却水泵均应停止。

## 7. 数值示例

假设某时步建筑冷负荷为 `2000 kW`：

```text
MREQ = 2000*3600/(4.19*8)
     = 214797.1 kg/h

MLOAD_REQ = 1.10*214797.1
          = 236276.8 kg/h

LoadFrac = 236276.8/430000
         = 0.54948
```

水箱已满且仍处于窗口时：

```text
Unit56信号 = Unit57信号 = 0.54948
Unit56流量 = 215000*0.54948 = 118138.4 kg/h
Unit57流量 = 215000*0.54948 = 118138.4 kg/h
总流量 = 236276.8 kg/h
Gamma35 = 1
Unit34信号 = 0
```

建筑得到的总流量恰好等于含 10% 裕度的需求流量，不再得到原策略的 `430000 kg/h`。

## 8. Simulation Studio 操作步骤

1. 另存工程，保留原始 TPF 和 DCK。
2. 双击 Unit38，进入 Equation 编辑器。
3. 用第 4.3 节公式替换 `CHWP1_CTRL` 和 `CHWP2_CTRL`。
4. 用第 4.4 节公式替换 `Pump32_CTRL`。
5. 不新增 Equation，不改变当前 Equation 数量。
6. 点击 `Check` 或确认关闭 Equation 窗口，保证没有重复变量、未定义变量和括号错误。
7. 检查 Unit56 输入3仍连接 `Pump10_ON`，Unit57 输入3仍连接 `Pump13_ON`。
8. 检查 Unit35 输入3仍连接 `Gamma35`，Unit34 输入3仍连接 `Pump34_CTRL`。
9. 生成新的 DCK 后，用文本搜索确认旧的三条公式已经完全被替换，且只各保留一处定义。
10. 运行一个包含“窗口内由未满转为已满且仍有建筑负荷”的短周期测试，再运行全年仿真。

## 9. 仿真验收方法

### 9.1 必须输出或在线观察的变量

建议在 Type65 在线绘图器或结果文件中同时输出：

```text
ChargeWindow
Chg_bySOC
TankFull
LoadKW
MLOAD_REQ
LoadFrac
WindowChargeMode
WindowLoadMode
Chiller1_ON
Chiller2_ON
CHWP1_CTRL
CHWP2_CTRL
Pump10_ON
Pump13_ON
Gamma35
Pump34_CTRL
FlowSplitError
```

同时观察 Unit56、Unit57 的实际出口流量，以及 Unit35 两个出口的实际流量。

### 9.2 目标时步的验收条件

选择满足以下条件的时步：

```text
ChargeWindow = 1
Chg_bySOC = 0
LoadWindow = 1
LoadFrac > 0
```

该时步必须满足：

```text
Chiller1_ON = 1
Chiller2_ON = 1
CHWP1_CTRL = LoadFrac
CHWP2_CTRL = LoadFrac
Pump10_ON = LoadFrac
Pump13_ON = LoadFrac
Gamma35 = 1
Pump34_CTRL = 0
FlowSplitError ≈ 0
```

流量允许按 TRNSYS 迭代容差存在很小误差，但应满足：

```text
Unit56出口流量 + Unit57出口流量 ≈ MLOAD_REQ
Unit35负荷出口流量 ≈ MLOAD_REQ
Unit35蓄冷出口流量 ≈ 0
```

### 9.3 回归检查

修改后还要确认其他工况没有被破坏：

- 窗口内水箱未满且无负荷：Unit56、Unit57、Unit34 均为 `1`；
- 窗口内水箱未满且有负荷：`Gamma35=LoadFrac`，`Pump34_CTRL=1-LoadFrac`；
- 非窗口水箱可用：Unit56、Unit57 为 `0`，Unit58 按需求变频；
- 非窗口水箱不可用：Unit56、Unit57 均为 `LoadFrac`；
- `FlowSplitError` 在所有运行工况下均接近 `0`；
- TRNSYS 日志中不应新增 Type110 质量平衡失败、迭代不收敛或冷机无流量运行警告。

## 10. 最终推荐

本次应采用上述“只替换 3 条 Equation、保持连线不变”的方案。它直接消除水箱蓄满后向建筑输送 `430000 kg/h` 的过流问题，同时保留原有窗口蓄冷、10% 流量裕度、双冷机运行和非窗口控制策略，改动范围最小，也便于通过 `FlowSplitError` 和实际流量完成复核。

若全年结果显示大量时段两台冷机在很低的 `LoadFrac` 下运行，再单独开展冷机台数优化；不要在本次修改中直接加入未经最小流量校核的单机切换逻辑。
