# S1 楼制冷后过冷至 21-22 C 的原因分析与控制优化建议

## 0. 先说权衡和结论

你的目标是室温稳定在 **26 C、相对湿度约 60%**。从目前结果看，S1 楼 4 个功能区很多时段掉到 21-22 C，已经不是“控制略偏紧”，而是明显过冷。  

这里有一个建模权衡：

- 如果追求设备真实运行，应采用“工作日时段启停 + 温度滞回 + 水阀/风机调节 + 冷冻水供水温度重设”的组合。
- 如果只是先让 Type56 热区温度靠近 26 C，最小改动可以先把 Type2b 控制逻辑修正，并把 Type996 风量、水量降下来。
- 如果直接把 7 C 冷冻水、满风量、满水量、无可靠停机逻辑同时接给热区，仿真很容易比真实中央空调更“硬”，造成 21-22 C 的过冷。

**优先判断：当前最主要问题不是单一设备容量，而是控制逻辑和末端满流量运行叠加。**  
建议优先级如下：

1. 先修 Type2b 或用 Equation 临时代替控制器，确保低于 25.5-25.8 C 时末端真正停机。
2. 再把 Type996 的水量、风量从“只要开启就满额”改成分区调节。
3. 再检查 Type56 送风 ACH，尤其厕所和走廊不要按主要空调区强冷。
4. 最后再做冷冻水 7 C 供水重设、新风盘管除湿控制和系统能耗统计。

## 2. 对你列出的 6 个原因逐条判断

## 2.1 控制器关机阈值太低或控制逻辑错误

### 判断

这是最高优先级问题。当前 `Untitled_imported.log` 中 4 个 Type2b 都有 stuck 警告：

- 办公室控制器 stuck 约 21% 时步
- 会议室控制器 stuck 约 23% 时步
- 厕所控制器 stuck 约 16% 时步
- 走廊控制器 stuck 约 18% 时步

当前 Type2b 的接法也不合理。以办公室为例：

```text
Upper input temperature Th = 56,103  室温
Lower input temperature Tl = 0,0     初值 25.5
Monitoring temperature Tin = 56,103  室温
Input control function = 0,0         初值 0
Upper dead band dT = 0,0             初值 0.5
Lower dead band dT = 0,0             初值 0
```

问题是：`Th` 现在接成了室温本身，而不是固定上限设定值或上限参考温度。这样 Type2b 的比较关系会变得自引用，容易 stuck，也容易导致“该停不停、该开不开”。

### 建议

先用明确的温度带控制：

- 开机阈值：`T_zone > 26.5 C`
- 关机阈值：`T_zone < 25.5 C` 或 `25.8 C`
- 目标区间：`25.5-26.5 C`

如果继续用 Type2b，建议每个热区这样接：

| Type2b 输入 | 建议连接 |
|---|---|
| Upper input temperature `Th` | 常数 `26.0` 或 `26.5`，不要接室温本身 |
| Lower input temperature `Tl` | 常数 `26.0` 或 `25.5`，按 Type2b 定义设置 |
| Monitoring temperature `Tin` | 对应热区室温，如 `56,103` |
| Input control function | 用上一步状态或按 Type2b proforma 要求连接，不能长期悬空 |
| Upper dead band `dT` | `0.5` |
| Lower dead band `dT` | `0.5` 或与下限逻辑对应的值 |

如果你暂时不想纠结 Type2b 的具体 proforma，可以先用 Equation 做调试版控制，确认物理系统能否稳定：

```text
ctrl_bgs = [38,1] * max(0, min(1, (TAIR_bgs - 25.5) / 1.0))
ctrl_hys = [38,1] * max(0, min(1, (TAIR_hys - 25.5) / 1.0))
ctrl_cs  = [38,1] * max(0, min(1, (TAIR_cs  - 25.5) / 1.0))
ctrl_zl  = [38,1] * max(0, min(1, (TAIR_zl  - 25.5) / 1.0))
```

然后：

```text
m_bgs = 25260 * ctrl_bgs
m_hys = 12544 * ctrl_hys
m_cs  = 6014  * ctrl_cs
m_zl  = 10482 * ctrl_zl
```

注意：Type996 的 `Cooling Control Signal` 在源码中有 `Gamma_Cool >= 0.5` 才进入制冷逻辑，所以更稳妥的接法是：

```text
cool_bgs = [38,1] * GT(TAIR_bgs, 25.8)
valve_bgs = [38,1] * max(0, min(1, (TAIR_bgs - 25.5) / 1.0))

Type996 Cooling Control Signal = cool_bgs
Type996 Fan Control Signal     = max(0.3*cool_bgs, valve_bgs)
m_bgs = 25260 * valve_bgs
```

如果 TRNSYS Equation 不支持 `GT()` 或 `min/max` 写法，要按你当前版本支持的函数改写。

## 2.2 Type996 风量/水量过大

### 判断

这是第二优先级问题。当前水量、风量是按额定值硬开：

```text
m_bgs = 25260*cool_bgs
m_hys = 12544*cool_hys
m_cs = 6014*cool_cs
m_zl = 10482*cool_zl
```

也就是说，只要 `cool_* = 1`，末端就是满水量运行。结合 7 C 冷冻水，房间很容易被快速拉到 21-22 C。

从负荷统计看，当前设备容量更像按极端峰值设置，而不是按多数运行工况调节。真实中央空调中，即使主机按峰值选型，末端也会通过水阀、风机档位、供水温度或启停滞回来限制实际输出。

### 建议

先做一版保守调参，不改设备结构，只降低水量和风量：

| 区域 | 当前水量 | 第一轮建议水量 | 当前风量 | 第一轮建议风量 |
|---|---:|---:|---:|---:|
| 办公室 | 25260 kg/h | 15000-18000 kg/h | 8167 L/s | 4500-5500 L/s |
| 会议室 | 12544 kg/h | 7000-9000 kg/h | 4056 L/s | 2200-3000 L/s |
| 厕所 | 6014 kg/h | 2500-3500 kg/h | 1944 L/s | 500-900 L/s |
| 走廊 | 10482 kg/h | 5000-7000 kg/h | 3389 L/s | 1000-1800 L/s |

更科学的做法是按 `测试.xls` 的分区 95% 负荷重新定容：

```text
建议末端额定冷量 = 分区 P95 负荷 * 1.10 到 1.20
```

按这个思路，第一轮可参考：

| 区域 | P95 负荷 | 建议额定冷量初值 |
|---|---:|---:|
| 办公室 | 58.1 kW | 65-75 kW |
| 会议室 | 33.0 kW | 36-45 kW |
| 厕所 | 25.0 kW | 25-30 kW |
| 走廊 | 22.0 kW | 25-30 kW |
| 合计 | 133.6 kW | 150-180 kW |

如果你坚持覆盖文件中的极端最大负荷 272 kW，则不要把末端容量直接缩到 150 kW，而应保留设备额定容量，同时必须做水阀调节和供水温度重设。否则峰值能顶住，但多数时段会过冷。

## 2.3 Type56 中送风 ACH 过大

### 判断

当前 Type996 额定风量对应的换气次数偏大，尤其厕所。按体积：

```text
V_BGS = 800 * 4.9 = 3920 m3
V_HYS = 400 * 4.9 = 1960 m3
V_CS  = 99.2 * 4.9 = 486 m3
V_ZL  = 300.034 * 4.9 = 1470 m3
```

按额定风量估算：

| 区域 | 当前风量 | 估算 ACH |
|---|---:|---:|
| 办公室 | 8167 L/s | 约 7.5 ACH |
| 会议室 | 4056 L/s | 约 7.5 ACH |
| 厕所 | 1944 L/s | 约 14.4 ACH |
| 走廊 | 3389 L/s | 约 8.3 ACH |

办公和会议室 7-8 ACH 对强冷工况可以理解，但如果长期按这个风量送 12-14 C 空气，会很快过冷。厕所 14 ACH 更明显不适合按普通舒适空调冷却末端处理，厕所应重点考虑排风和补风，不应作为强制维持 26 C 的主要冷区。

### 建议

第一轮目标 ACH：

| 区域 | 建议 ACH |
|---|---:|
| 办公室 | 3-5 ACH |
| 会议室 | 4-6 ACH，人员密度高时取上限 |
| 厕所 | 以排风/补风为主，冷却送风不宜过大 |
| 走廊 | 2-4 ACH |

在 Type56 的 `VENTILATION` 或 `AIRNODE` 连接中，检查各区是否同时叠加了：

- Type996 送风
- 新风盘管送风
- 额外 infiltration
- 其他通风/耦合风量

如果这些都同时存在，实际 ACH 会高于你认为的末端风量。

## 2.4 冷冻水 7 C 持续供应，但末端没有正确停机

### 判断

7 C 供水本身符合常规冷冻水系统，不是错误；错误在于 7 C 水持续送到过大的末端，而且水阀没有随房间温度关断。  

当前 Type655：

```text
Rated Capacity = 1080000 kJ/h = 300 kW
COP = 3.2
Set Point Temperature 输入未连接，初值 = 7 C
Chiller_on = 任一末端 cool_* 开启
```

当前主机 300 kW 与 Type996 合计 316 kW 基本匹配，说明主机侧不是最大矛盾。真正的问题是末端一旦开机，就用 7 C 冷水满量制冷。

### 建议

保持 7 C 作为设计峰值供水温度，但增加运行重设：

```text
T_chws_set = 7 C     当任一主要区域 T_zone > 27 C
T_chws_set = 8-9 C   当 26 C < T_zone <= 27 C
T_chws_set = 10 C    当所有区域 T_zone < 26 C 且仍需除湿/新风处理
Chiller_on = 0       当所有区域 T_zone < 25.5-25.8 C
```

在 TRNSYS 中，应把 Type655 的 `Set Point Temperature` 从未连接改为 Equation 输出变量，例如：

```text
T_chws_set = 7 + 3*(1 - Chiller_on_mild)
```

或者先简单固定为：

```text
T_chws_set = 8.5
```

用于排查过冷。如果 8.5-9 C 供水后温度明显改善，说明末端出风过冷和水量过大是主因。

## 2.5 硬开关控制没有滞回，或 Type2b 接法不对

### 判断

这与第 2.1 点相关，但要单独强调：  
当前控制实际是：

```text
cool_bgs = [38,1]*[33,1]
cool_hys = [38,1]*[40,1]
cool_cs  = [38,1]*[41,1]
cool_zl  = [38,1]*[42,1]
```

如果 Type2b 输出异常，后面的 Type996 就会被异常驱动。日志里的 stuck 警告已经说明 Type2b 不是可信状态。

### 建议

先不要同时调 10 个参数。建议做一个控制器隔离试验：

1. 暂时不用 Type2b，直接用 Equation 控制一个区，例如办公室。
2. 只运行办公室 Type996，其他三区先关掉。
3. 看办公室是否能稳定在 25.5-26.5 C。
4. 办公室稳定后，再复制到会议室、厕所、走廊。

临时 Equation 示例：

```text
Tset = 26
T_on = 26.5
T_off = 25.5

cool_bgs = [38,1] * GT([56,103], T_on)
valve_bgs = [38,1] * max(0, min(1, ([56,103] - T_off)/(T_on - T_off)))
m_bgs = 18000 * valve_bgs
```

注意：这不是严格滞回，因为 Equation 没有记忆上一时步状态。它适合先排查系统强弱。最终建议仍改回正确 Type2b 或使用带记忆的控制器/控制方程。

## 2.6 新风盘管/风机盘管出风过冷

### 判断

当前 Type996 的送风温度输出是：

```text
Type996 Output 3 = T_Air_Out
```

当前 Type508 新风盘管是 Type508a free-floating：

```text
Free-Floating Mode = 0
Humidity Mode = 2
Fluid Flowrate 未连接，初值 0
```

这意味着 Type508 当前并没有形成可靠的“按 60%RH 或含湿量目标处理新风”的逻辑。另一方面，Type996 若持续送出 12-14 C 的空气，并且风量偏大，就足以把房间拉到 21-22 C。

### 建议

给 Type65 或 Printer 增加以下输出，先判断是否出风过冷：

| 模块 | 输出 | 含义 |
|---|---|---|
| Type996 bgs `Unit 30` | `Output 3` | 办公室末端出风温度 |
| Type996 hys `Unit 35` | `Output 3` | 会议室末端出风温度 |
| Type996 cs `Unit 36` | `Output 3` | 厕所末端出风温度 |
| Type996 zl `Unit 37` | `Output 3` | 走廊末端出风温度 |
| Type996 各区 | `Output 8` | 总制冷量 |
| Type996 各区 | `Output 9` | 显冷量 |
| Type996 各区 | `Output 11` | 风机功率 |
| Type508 `Unit 32` | `Output 3` | 新风盘管出风温度 |
| Type508 `Unit 32` | `Output 4` | 新风盘管出风含湿量 |
| Type508 `Unit 32` | `Output 8` | 新风盘管总冷量 |

经验判断：

- 风机盘管送风长期低于 12 C：过冷风险很高。
- 风机盘管送风 14-18 C：更接近办公舒适空调运行。
- 新风除湿盘管可以有较低盘管温度，但送入房间前通常需要混合、再热或控制新风量，否则也会造成过冷。

如果你要控制 60%RH，Type508a free-floating 不够合适。应考虑 Type508 的控制模式：

- `Mode_Control = 1`：控制出风干球温度。
- `Mode_Control = 2`：控制出风含湿量，即 `W_Air_Want`。
- `Mode_Control = 3`：控制流体出口温度。

你之前提到的 `W_Air_Want = 0.0095 kg/kg` 应接在 Type508 的第 10 个输入。前提是 Type508 参数 1 从 `0` 改成 `2`，也就是含湿量控制模式。Studio 中如果当前 proforma 是 Type508a 且不显示第 10 个输入，通常需要换成对应的 Type508 控制版本，或重新选择支持 controlled outlet humidity ratio 的 proforma。  

但请注意：含湿量 0.0095 kg/kg 大约对应 26 C、60%RH 附近的室内目标，不等于所有送风都要固定到这个含湿量。新风盘管若为除湿，应以新风露点和室内湿负荷核算，避免为除湿而过度降温。

## 3. 建议的具体修改顺序

## 3.1 第一步：确认工作日 8-22 点设备开启逻辑

当前 `工作日8-22` Type14 看起来是按每周 168 小时循环：

- 工作日 8:00-22:00 输出 1
- 工作日其他时间输出 0
- 周末输出 0

当前末端控制又乘了 `[38,1]`：

```text
cool_bgs = [38,1]*[33,1]
cool_hys = [38,1]*[40,1]
cool_cs = [38,1]*[41,1]
cool_zl = [38,1]*[42,1]
```

因此“是否只在工作日 8-22 点开启设备”这个逻辑大方向是有的。  
但是，如果 Type2b stuck 或其他流量没有乘 `[38,1]`，仍可能出现非预期运行。建议把以下量都输出检查：

```text
[38,1] 工作日开关
cool_bgs, cool_hys, cool_cs, cool_zl
m_bgs, m_hys, m_cs, m_zl
Chiller_on
m_chiller
```

判断标准：

- 非工作时段 `[38,1] = 0` 时，四个 `cool_*` 必须为 0。
- 非工作时段四个 `m_*` 必须为 0。
- 非工作时段 `Chiller_on` 必须为 0。
- 非工作时段 Type996 `Output 8` 总制冷量应为 0 或接近 0。

## 3.2 第二步：先修控制，不先修容量

建议先把每个区的控制目标改成：

```text
开机：T_zone > 26.5 C
关机：T_zone < 25.5 C
可接受稳定带：25.5-26.5 C
```

如果过冷仍明显，把关机阈值提高：

```text
开机：T_zone > 26.3 C
关机：T_zone < 25.8 C
```

不建议把关机阈值设到 24 C 或更低。你目标是 26 C，若关机阈值太低，系统会有意允许过冷。

## 3.3 第三步：降低 Type996 第一轮流量

建议先不要一次性重做所有设备参数。先只改 Equation 中实际运行水量，观察室温：

```text
m_bgs = 16000*cool_bgs
m_hys = 8000*cool_hys
m_cs  = 3000*cool_cs
m_zl  = 6000*cool_zl
```

如果仍过冷，再把风量参数降到第一轮建议值：

```text
办公室：8167 -> 5000 L/s
会议室：4056 -> 2500 L/s
厕所：1944 -> 700 L/s
走廊：3389 -> 1500 L/s
```

改风量参数后，要注意 Type996 的性能图谱范围。你当前日志中 `Unit 36 Type996 cs` 已经出现性能图谱第三自变量低于范围的警告，说明厕所末端已经有调用点落在图谱范围外。调太低时要检查 `.log` 是否新增性能图谱警告。

## 3.4 第四步：改 Type655 供水温度输入

当前 Type655 的 `Set Point Temperature` 未连接，只靠初值 7 C。建议接一个 Equation 变量：

```text
T_chws_set = 8.5
```

先固定 8.5 C 做排查。若过冷改善，再做重设：

```text
Tmax_zone = max(max([56,103],[56,104]),max([56,105],[56,106]))
T_chws_set = 10 - 3*max(0,min(1,(Tmax_zone-26)/(1.0)))
```

含义：

- 当最高区温接近 26 C，供水约 10 C。
- 当最高区温到 27 C 或更高，供水约 7 C。

## 3.5 第五步：处理 Type146 风机质量平衡

日志显示：

```text
Type146 Fan mass balance failed during 2496 timesteps
```

当前 Type146：

```text
Rated Volumetric Flow Rate = 1200 L/s
Rated Power = 4000 kJ/h = 1.11 kW
Air Flow Rate 输入未连接，初值 2000
Inlet Air Pressure 输入未连接
Air-Side Pressure Increase 输入未连接
```

建议至少把 `Air Flow Rate` 明确接为一个 Equation 变量：

```text
m_oa_fan = 1200*1.2*3.6*[38,1]
```

但要注意 Type146 第 4 输入单位是质量流量 `MF1`，通常为 kg/h；如果你用 1200 L/s，需要换算：

```text
1200 L/s = 1.2 m3/s
空气密度约 1.2 kg/m3
质量流量 = 1.2*1.2*3600 = 5184 kg/h
```

所以建议：

```text
m_oa_fan = 5184*[38,1]
```

然后连接：

```text
Type146 Input 4 Air Flow Rate = m_oa_fan
```

这样可以先消除质量平衡失败，再判断新风盘管是否真正参与制冷除湿。

## 4. 能耗和输出量应该看哪些

如果要统计中央空调系统能耗，注意区分“冷量”和“电功率”。

### 4.1 主机电功率

Type655：

```text
Output 3 = power，单位 kJ/h
```

换算：

```text
P_chiller_kW = [25,3] / 3600
```

### 4.2 风机盘管风机功率

Type996：

```text
Output 11 = Power_Fan，单位 kJ/h
```

换算：

```text
P_fcu_bgs_kW = [30,11] / 3600
P_fcu_hys_kW = [35,11] / 3600
P_fcu_cs_kW  = [36,11] / 3600
P_fcu_zl_kW  = [37,11] / 3600
```

### 4.3 新风机功率

Type146：

```text
Output 6 = power，单位 kJ/h
```

换算：

```text
P_oa_fan_kW = [31,6] / 3600
```

### 4.4 新风盘管冷量不是电功率

Type508：

```text
Output 8 = Q_Total，单位 kJ/h
Output 9 = Q_Fluid，单位 kJ/h
```

这两个是盘管换热量，不是压缩机电功率。若新风盘管使用同一台 Type655 冷水机供冷，其电耗已经体现在 Type655 `Output 3` 中，不应再把 Type508 冷量当电耗相加。

### 4.5 建议系统总电功率 Equation

如果暂时不建水泵，可以先算：

```text
P_HVAC_kW = ([25,3] + [30,11] + [35,11] + [36,11] + [37,11] + [31,6]) / 3600
```

如果后续加入冷冻水泵和冷却风机，则应再加：

```text
P_total_kW = P_chiller + P_FCU_fans + P_OA_fan + P_CHW_pump + P_condenser_fans
```

Type655 的 `power` 一般已代表风冷冷水机组压缩机及其性能文件内定义的功耗，但是否包含冷凝风机要看该 TESS Type655 性能数据定义。保守做法是把它当作“风冷冷水机组输入功率”，不要再额外凭空加冷凝风机，除非你单独建模。

## 6. 最终建议

当前 S1 过冷最合理的解释是：

```text
Type2b 控制器接法不可靠
+ Type996 一开就是满水量满风量
+ 7 C 冷冻水持续供给
+ 部分热区 ACH 偏大
+ 新风盘管/风机质量流量没有完全闭合
= 室温被拉到 21-22 C
```

建议不要先纠结“主机 300 kW 是否绝对过大”。从 `测试.xls` 看，316 kW 末端容量确实高于多数时段负荷，但峰值 272 kW 又说明系统容量不是完全离谱。真正需要修的是 **部分负荷控制**：

- 末端不要满水量硬开。
- 风机不要满风量硬送。
- 低于 25.5-25.8 C 必须停冷。
- 轻负荷时冷冻水供水温度应提高到 8.5-10 C。
- 新风除湿要单独控制含湿量，不能让新风盘管成为额外强冷源。

按这个顺序修改后，再看 S1 四区能否稳定在 26 C 附近。如果仍然过冷，再考虑重新按 P95 负荷把 Type996 额定冷量整体降到 150-180 kW 量级；如果峰值时段温度压不住，则保留额定容量，但必须使用水阀调节和供水温度重设。
