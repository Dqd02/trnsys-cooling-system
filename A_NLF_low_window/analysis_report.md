# 净负荷（NLF）每日低净负荷时间窗口分析报告

## 1. 概述

对 NLF/ 目录下的 3 个净负荷（Net Load，即负荷减去风光发电后的正值）CSV 文件进行**每日低净负荷时间窗口分析**。

| 文件 | 说明 | 行数 |
|------|------|------|
| NLF_2025_new.csv | 2025 年情景 | 35041 |
| NLF_40TH_new.csv | 40 百分位情景 | 35041 |
| NLF_60TH_new.csv | 60 百分位情景 | 35041 |

每个文件包含全年 8760 小时（**15min 粒度**，每天 96 个数据点）的净负荷数据，共 **35041** 行（多出的 1 行为初始值）。

**核心目标**：找出每天净负荷最低的 **25%** 时段，标记为"相对干净窗口"——在这些时段，电网净负荷最低，能源最干净。

---

## 2. 分析方法与流程

### 步骤 1：数据加载

load_file() 函数读取单列 CSV，兼容 UTF-8/GBK 编码。三个文件均为纯数值单列格式（无表头），直接读取 35041 行。

### 步骤 2：每日低净负荷窗口标记

daily_labeling_low() 函数是核心标记逻辑：

`python
lowest_positions = np.argsort(day_data, kind="stable")[:select_count]
labels[start + lowest_positions] = 1
`

- 从索引 1 开始，按 96 个点为一天切分（全年共 365 天）
- 对每一天按净负荷数值**升序排序**（
p.argsort）
- 取最低的前 ound(96 * PERCENTILE_LOW / 100) 个点
- 标记为 **1**（低净负荷窗口），其余为 **0**

### ⚠️ 关键参数位置（敏感性分析）

`python
PERCENTILE_LOW = 25  # <<<=== 第 46 行，在此处修改
`

位于 nalyze_nlf_low_net_load_window.py 文件第 **46 行**。

| 修改值 | 每天选点数 | 含义 |
|--------|-----------|------|
| 25 | 24 个 | 默认，选每天净负荷最低的 25% 时段 |
| 30 | 29 个 | 窗口更宽松（选最低的 30%） |
| 60 | 58 个 | 窗口跨度更大（选最低的 60%） |
| 10 | 10 个 | 窗口更严格（只选最低的 10%） |

> 选点数计算公式：ound(96 × PERCENTILE_LOW / 100)

### 关于方法选择的说明

本脚本采用 **argsort 排序法**（每天精确取最低 N 个点），而非 
p.percentile 阈值法（data < P25），原因是：

净负荷数据中存在大量 **0 值**（特别是 NLF_60TH 中 0 值占 21.8%）。若用 data < P25：
- 当一天内 0 值超过 25% 时，P25 = 0
- data < 0 为 False，选出的窗口远低于 25%
- 例如 NLF_60TH 用阈值法只能选出约 **16%** 的时段

两种方法的对比：

| 方法 | 每天标记比例 | 适用场景 |
|------|-------------|---------|
| **argsort 法**（本脚本采用） | 严格 ≈ 25% | 工程调度、需要稳定窗口数量 |
| percentile 阈值法 | 可能有偏（低估） | 统计分析、严格百分位含义 |

如需切换为 percentile 阈值法，在 daily_labeling_low() 中替换以下代码：

`python
# 替换为 percentile 方法：
threshold = np.percentile(day_data, PERCENTILE_LOW)
labels[start:end] = (day_data < threshold).astype(int)
`

### 步骤 3：连续性修正

continuity_fix() 消除孤立的标记点：

- **孤立 1**（[0, 1, 0]）→ 中间的 1 变 0
- **孤立 0**（[1, 0, 1]）→ 中间的 0 变 1

修正范围：索引 1 到 n-2，不修改首尾和初始行。

### 步骤 4：验证

- 每天标记比例严格 ≈ 25%（受连续性修正略微波动为 22.9%~27.1%）
- **无孤立点残留**（ssert_no_isolated_points 验证）
- 输出行数保持 35041
- 初始行标记恒为 0

## 5. 时间完整性验证

- ✅ **每日独立标记**：每天单独排序、单独取最低 25%，互不干扰
- ✅ **时间排列不变**：标记文件与原文件行数一致（35041），顺序一致
- ✅ **修正不跨天**：连续性修正仅检查相邻 3 个点，不涉及跨天边界
- ✅ **初始值隔离**：索引 0 始终为 0
- ✅ **无孤立点**：修正后不存在 [0,1,0] 或 [1,0,1] 模式
- ✅ **连续时段**：低净负荷窗口多为连续时间段（受连续性修正保证）
