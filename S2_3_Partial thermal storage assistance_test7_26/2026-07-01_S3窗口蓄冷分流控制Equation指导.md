# S3 窗口蓄冷与负荷分流控制 Equation 指导

分析日期：2026-07-01  
分析对象：`S3/Project11.dck`、`S3/load_year_15min_new.csv`、`S3/CO2_window.csv`、`Type110.txt`、`Type11.txt`  
系统类型：集中供冷水蓄冷系统，4/12 degC 冷冻水，窗口信号驱动的部分负荷分流蓄冷控制。  
审查立场：以建筑与能源系统研究者、审稿人的角度，重点审查设备参数、受控分流器方向、三台变频水泵信号、冷机/冷却塔/冷却水泵联动、流量守恒与控制逻辑可解释性。

---

## 1. 先给审查结论

当前 S3 的系统思路是成立的：两台 3100 kW 冷机在窗口时段提供总冷量，其中一部分通过变频水泵2进入负荷侧，另一部分通过变频水泵1进入蓄冷罐；非窗口时段优先由水箱释冷，水箱不足时只开启冷机1直供。这个策略比“固定夜间全蓄冷”更接近窗口响应型调度，适合研究低碳窗口、电网净负荷窗口或其他外部窗口信号对蓄冷运行的影响。

但有一个关键工程风险：若蓄冷窗口内水箱已满且仍有负荷，你提出“冷机制出的冷量全部进入变频水泵2”。在当前模型中，这意味着两台冷机合计约 `666000 kg/h` 冷冻水可能全部进入负荷侧，对应约 `6200 kW` 供冷能力；而你给出的极端日峰值约 `3050 kW`。这在 TRNSYS 里可以运行，但工程上会形成明显过流量、低温差和负荷侧过供冷倾向。本文先按你的既定逻辑给出可落地 Equation，同时在建议中给出更稳妥的修正方案。

## 2. 当前 S3 关键设备与参数复核

### 2.1 冷量与流量匹配

设计温差：

```text
T_supply = 4 degC
T_return = 12 degC
DeltaT = 8 K
Cp = 4.19 kJ/kg-K
```

单台冷机或单台 333000 kg/h 水泵对应冷量：

```text
333000/3600 x 4.19 x 8 = 3100 kW
```

两台冷机合计：

```text
666000/3600 x 4.19 x 8 = 6201 kW
```

评价：

- 冷机1/2额定冷量均为 `11160000 kJ/h = 3100 kW`，与供冷水泵1/2的 `333000 kg/h` 匹配。
- 变频水泵1/2/3额定流量均为 `666000 kg/h`。Type110 控制信号为 `0.5` 时，输出流量为 `333000 kg/h`，正好匹配单台冷机或释冷水泵流量。
- 极端负荷约 `3050 kW` 时，`333000 kg/h` 可提供约 `3100 kW`，比需求略高，满足你希望“蓄冷时段分到负荷端的冷量比需求稍高一点”的要求。

### 2.2 Type110 变频水泵控制含义

从 `Type110.txt` 可知：

```text
flow_out = control * rated_flow
```

因此三台变频水泵在 S3 中应按下表理解：

| 水泵 | Unit | 额定流量 | 控制信号 0.5 | 控制信号 1.0 | 用途 |
|---|---:|---:|---:|---:|---|
| 变频水泵1 | 34 | 666000 kg/h | 333000 kg/h | 666000 kg/h | 蓄冷罐充冷支路 |
| 变频水泵2 | 32 | 666000 kg/h | 333000 kg/h | 666000 kg/h | 负荷供冷支路/冷机直供支路 |
| 变频水泵3 | 33 | 666000 kg/h | 333000 kg/h | 666000 kg/h | 负荷回水泵 |

审稿意见：  
Type110 会检查泵入口流量与泵输出流量是否一致。也就是说，受控分流器 Unit35 的分流比例必须和变频水泵1/2的控制信号相互匹配，否则容易出现质量不平衡警告或非物理流量。

## 3. Type11f 出口方向与 S3 分流器含义

你给出的 Type11f 公式为：

```text
flow2 = flow * gam
flow1 = flow * (1.d0 - gam)
Output1 = tin
Output2 = flow1
Output3 = tin
Output4 = flow2
```

因此：

- `outlet1 = Output1/Output2 = flow*(1-gam)`
- `outlet2 = Output3/Output4 = flow*gam`
- `gam=0`：全部走 outlet1
- `gam=1`：全部走 outlet2
- `gam=0.5`：两路各 50%

### 3.1 S3 的三个关键分流器

| 分流器 | Unit | 入口 | outlet1 | outlet2 | 控制含义 |
|---|---:|---|---|---|---|
| 分流阀-2 | 14 | 管道-4 Unit31 | 冷机1 | 冷机2 | 两台冷机运行时 `gam14=0.5`；单冷机1运行时 `gam14=0` |
| 分流阀-3 | 29 | 变频水泵3 Unit33 出口 | 蓄冷罐 Port-1 | 合流阀-3 Unit37，再回冷机侧 | 水箱释冷时 `gam29=0`；冷机直供或窗口负荷回冷机时 `gam29=1` |
| 受控分流器 | 35 | 管道-1 Unit25，即冷机1/2供水合流后 | 变频水泵1 Unit34，进入蓄冷罐 | 变频水泵2 Unit32，进入负荷侧 | `gam35` 越大，分给负荷支路越多 |

特别重要：  
受控分流器 Unit35 的 `gam35` 不是“蓄冷比例”，而是“分给变频水泵2/负荷支路的比例”。蓄冷支路比例是 `1-gam35`。

## 4. 当前运行逻辑的合理性审查

### 4.1 窗口内、有负荷、水箱未满

逻辑：两台冷机同时运行，总流量 `666000 kg/h`。其中负荷所需流量进入变频水泵2，剩余流量进入变频水泵1给水箱蓄冷。

这是合理的。因为冷机总流量、分流器、两台变频水泵之间可以形成质量守恒：

```text
Pump1_CTRL = 1 - gam35
Pump2_CTRL = gam35
Pump1_flow + Pump2_flow = 666000 kg/h
```

### 4.2 窗口内、无负荷、水箱未满

逻辑：两台冷机全部给水箱蓄冷。

对应：

```text
gam35 = 0
Pump1_CTRL = 1
Pump2_CTRL = 0
```

这是合理的。

### 4.3 窗口内、水箱已满且有负荷

你提出的逻辑：两台冷机制出的冷量全部进入变频水泵2，服务负荷。

对应：

```text
gam35 = 1
Pump1_CTRL = 0
Pump2_CTRL = 1
Pump3_CTRL = 1
```

这在模型质量守恒上是成立的，但工程上偏激进。因为这会让负荷侧流量达到 `666000 kg/h`，而最大负荷只需要约 `327000 kg/h` 左右。建议在正式论文中将此作为“当前模型假设”，并在敏感性分析中测试“满罐后只开冷机1直供”或“按负荷调节至约 333000 kg/h”的替代策略。

### 4.4 非窗口、有负荷、水箱有冷量

逻辑：水箱释冷，冷机全部关闭。

对应：

```text
释冷水泵 Unit6 = 1
变频水泵3 Unit33 = 0.5
分流阀-3 Unit29 gam29 = 0
```

这与水路一致。释冷水泵额定 `333000 kg/h`，变频水泵3用 `0.5` 正好匹配回水流量。

### 4.5 非窗口、有负荷、水箱冷量不足

逻辑：只开启冷机1，冷机2关闭；冷机1供水全部进入变频水泵2，负荷回水经变频水泵3、分流阀-3、合流阀-3、管道-4、分流阀-2回到冷机1。

对应：

```text
冷机1 = 1
冷机2 = 0
gam35 = 1
Pump2_CTRL = 0.5
Pump3_CTRL = 0.5
gam29 = 1
gam14 = 0
```

这是合理的。注意这里 `Pump2_CTRL` 不是 1，而是 0.5，因为只有冷机1和供冷水泵1运行，进入受控分流器的总流量是 `333000 kg/h`，变频水泵2也应输出 `333000 kg/h`。

## 6. 推荐 Equation 公式

以下公式按当前 S3 逻辑编写。每条公式后给出注释，便于直接迁移到 TRNSYS Studio 的 Equation 模块中。

```text
T_cold_sp = 4
! 设计供冷/蓄冷冷水温度，当前系统按 4 C 冷水输入。

T_warm_ref = 12
! 设计回水温度，用作水箱放空或暖态参考温度。

dT_dead = 1
! 温度判断死区，避免水箱节点温度小幅波动导致频繁启停。

Cp_water = 4.19
! 水的定压比热，单位 kJ/kg-K，与模型中各水侧组件保持一致。

DeltaT_design = T_warm_ref - T_cold_sp
! 设计供回水温差，当前为 8 K。

LoadRaw = [22,1]
! Unit22 读取的负荷原始值，当前负荷文件按 kJ/h 处理。

LoadKW = LoadRaw/3600
! 将负荷从 kJ/h 折算为 kW。

HasLoad = gt(LoadKW,5)
! 有效负荷判断；小于 5 kW 视为无制冷需求或数值噪声。

Window_time01 = max(0,min(1,Window_time))
! 将外部窗口信号限制在 0-1；1 表示蓄冷窗口，0 表示非蓄冷窗口。

IsWindow = gt(Window_time01,0.5)
! 将窗口输入转换为布尔信号；大于 0.5 即认为处于蓄冷窗口。

T_tank_avg = [7,5]
! Type534 输出 5，水箱平均温度，用于估算整体 SOC。

T_node_top = [7,18]
! 水箱冷端/顶部代表节点，用于判断冷区是否已形成。

T_node_mid = [7,30]
! 水箱中部节点，用于判断温跃层推进位置。

T_node_bot = [7,42]
! 水箱暖端/底部代表节点，用于判断水箱是否接近放空。

SOC_raw = (T_warm_ref - T_tank_avg)/(T_warm_ref - T_cold_sp)
! 按平均温度估算水箱蓄冷状态；越接近 4 C，SOC 越高。

SOC = max(0,min(1,SOC_raw))
! 将 SOC 限定在 0-1 范围；0=接近空罐，1=接近满罐。

TankFull = lt(T_node_top,T_cold_sp+dT_dead)*lt(T_node_mid,T_cold_sp+1.5)
! 顶部和中部均接近 4 C 时，认为水箱已基本蓄满。

TankEmpty = gt(T_node_bot,T_warm_ref-dT_dead)*gt(T_node_mid,T_warm_ref-3)
! 底部和中部均偏暖时，认为水箱可用冷量不足。

SOC_DischargeMin = 0.10
! SOC 低于 10% 时禁止继续水箱优先释冷。

SOC_ChargeStop = 0.985
! 代数近似版的蓄冷停止阈值；接近满罐时停止进入水箱支路。

Chg_bySOC = lt(SOC,SOC_ChargeStop)*(1-TankFull)
! 水箱允许蓄冷判据；未接近满罐且节点未满时允许蓄冷。

Dch_bySOC = gt(SOC,SOC_DischargeMin)*(1-TankEmpty)
! 水箱允许释冷判据；SOC 足够且未达到空罐判据时允许释冷。

HourOfDay = time-24*int(time/24)
! 当前仿真时刻在一天内的小时数。

DayNum = int(time/24)
! 从 TRNSYS 绝对时间计算的日序号。

WeekIndex0 = DayNum-7*int(DayNum/7)
! 未校准的周内索引，0-6 循环。

WeekdayOffset = 0
! 星期偏移量；必须按负荷文件首日实际星期校准。

RawWeekIndex = WeekIndex0+WeekdayOffset
! 加入星期偏移后的周内索引。

Weekday = RawWeekIndex-7*int(RawWeekIndex/7)
! 归一化周内索引；建议约定 0=周一，1=周二，...，6=周日。

IsWorkday = lt(Weekday,5)
! 工作日判断；周一至周五为 1，周末为 0。

IsLoadTime = ge(HourOfDay,8)*lt(HourOfDay,22)
! 负荷时间判断；工作日 8:00-22:00 才允许有制冷需求。

LoadWindow = IsWorkday*IsLoadTime*HasLoad
! 有效负荷窗口；周末、非工作时段或无负荷时为 0。

ChargeWindow = IsWorkday*IsWindow
! 有效蓄冷窗口；窗口信号只在工作日生效。

LoadFlowReq = LoadKW*3600/(Cp_water*DeltaT_design)
! 按 4/12 C 温差计算负荷所需质量流量，单位 kg/h。

LoadCtrlRaw = 1.03*LoadFlowReq/666000
! 将负荷所需流量换算为变频水泵2控制信号，并给 3% 裕量。

LoadCtrl = HasLoad*min(0.5,max(0,LoadCtrlRaw))
! 负荷支路推荐控制量；最高限制为 0.5，即 333000 kg/h，约 3100 kW。
```

说明：  
`LoadCtrl` 被限制为 0.5，是因为当前最大负荷约 3050 kW，`0.5` 已对应 3100 kW，略高于峰值。这样既满足负荷，又避免在正常分流蓄冷时把过多流量送到负荷侧。

## 7. 运行模式判定

```text
StorageChargeActive = ChargeWindow*Chg_bySOC
! 窗口内且水箱未满时，允许水箱蓄冷支路运行。

WindowLoadMode = ChargeWindow*LoadWindow
! 窗口内同时有负荷时，负荷支路需要供冷。

WindowChillerMode = ChargeWindow*max(Chg_bySOC,LoadWindow)
! 窗口内只要需要蓄冷或存在负荷，两台冷机就开启；水箱满且无负荷则停机。

TankDischargeMode = (1-ChargeWindow)*LoadWindow*Dch_bySOC
! 非窗口、有负荷且水箱可用时，优先水箱释冷。

Chiller1BackupMode = (1-ChargeWindow)*LoadWindow*(1-Dch_bySOC)
! 非窗口、有负荷但水箱不足时，只开启冷机1直供。

OffMode = (1-min(1,WindowChillerMode+TankDischargeMode+Chiller1BackupMode))
! 停机检查信号；没有蓄冷、释冷或冷机直供时为 1。
```

## 9. 受控分流器与三台变频水泵信号

### 9.1 受控分流器 Unit35

```text
Gamma35 = min(1, WindowLoadMode*(Chg_bySOC*LoadCtrl + (1-Chg_bySOC)*1) + Chiller1BackupMode*1)
! Unit35 受控分流器：
! 窗口内有负荷且水箱未满时，按 LoadCtrl 分给负荷支路；
! 窗口内有负荷且水箱已满时，全部走负荷支路；
! 非窗口冷机1备用直供时，全部走负荷支路。
```

解释：

- `Gamma35=0`：全部进入变频水泵1，去蓄冷罐。
- `Gamma35=LoadCtrl`：按负荷需求分给变频水泵2，其余给水箱。
- `Gamma35=1`：全部进入变频水泵2。

### 9.2 变频水泵1 Unit34

```text
Pump34_CTRL = StorageChargeActive*(1-LoadWindow*LoadCtrl)
! 变频水泵1：
! 窗口内无负荷且水箱未满时为 1，全部 666000 kg/h 进水箱；
! 窗口内有负荷且水箱未满时为 1-LoadCtrl，剩余流量进水箱；
! 水箱满或非窗口时为 0。
```

### 9.3 变频水泵2 Unit32

```text
Pump32_CTRL = WindowLoadMode*(Chg_bySOC*LoadCtrl + (1-Chg_bySOC)*1) + Chiller1BackupMode*0.5
! 变频水泵2：
! 窗口内有负荷且水箱未满时按 LoadCtrl 供给负荷；
! 窗口内有负荷且水箱已满时为 1，即两台冷机流量全部进负荷支路；
! 非窗口水箱不足、冷机1直供时为 0.5，匹配单台冷机 333000 kg/h。
```

### 9.4 变频水泵3 Unit33

```text
Pump33_CTRL = WindowLoadMode*(Chg_bySOC*LoadCtrl + (1-Chg_bySOC)*1) + TankDischargeMode*0.5 + Chiller1BackupMode*0.5
! 变频水泵3：
! 只要负荷侧有流量就开启；
! 窗口内负荷支路回水流量与变频水泵2匹配；
! 水箱释冷和冷机1备用直供均为 0.5，匹配 333000 kg/h。
```

### 9.5 分流阀-3 Unit29

```text
Gamma29 = min(1,WindowLoadMode+Chiller1BackupMode)
! Unit29 分流阀-3：
! 水箱释冷时为 0，回水走 outlet1 回蓄冷罐；
! 窗口内负荷由冷机回路承担或非窗口冷机1直供时为 1，回水走 outlet2 到合流阀-3。
```

### 9.6 分流阀-2 Unit14

```text
Gamma14 = 0.5*WindowChillerMode
! Unit14 分流阀-2：
! 窗口内两台冷机运行时为 0.5，管道-4回水均分给冷机1和冷机2；
! 非窗口冷机1单独直供时为 0，全部回冷机1。
```

## 12. 运行报错与宏观检查

当前 `Project11.log` 未见 fatal error。主要警告包括：

- Type682 在多个 DLL 中重复，TRNSYS 采用第一个实例；这通常不是控制逻辑错误。
- 天气文件中少量辐射一致性警告；这属于天气数据质量问题，不影响本文控制公式判断。

宏观自检要点：

1. 任意时刻，受控分流器 Unit35 的分流比例必须与变频水泵1/2控制信号匹配。
2. 负荷侧有流量时，变频水泵3必须开启，且控制信号应匹配负荷侧回水流量。
3. 水箱释冷时 Unit29 必须 `gam=0`；冷机供负荷时 Unit29 必须 `gam=1`。
4. 两台冷机同时运行时 Unit14 必须 `gam=0.5`；只开冷机1时 Unit14 必须 `gam=0`。
5. 冷却塔和冷却水泵必须与对应冷机同步，不能出现冷机开而冷却侧关，或冷机关而冷却侧长期开的情况。

## 14. 三点可落地改进建议

1. 输出诊断变量：将 `Window_time01`、`SOC`、`LoadCtrl`、`Gamma35`、`Pump34_CTRL`、`Pump32_CTRL`、`Pump33_CTRL`、`Gamma29`、`Gamma14` 输出到 Type65 或 Printer。先抽查一个极端工作日，确认分流比例和三台变频泵流量严格匹配。

2. 做质量守恒检查：窗口内有负荷且水箱未满时，应满足 `Pump34_CTRL + Pump32_CTRL = 1`；非窗口冷机1直供时，应满足 `Pump32_CTRL = Pump33_CTRL = 0.5`；水箱释冷时，应满足 `Pump33_CTRL = 0.5` 且 `Gamma29 = 0`。

3. 对“水箱满后负荷供冷”做替代策略敏感性分析：方案 A 保持本文逻辑，两台冷机全部送负荷；方案 B 满罐后只开冷机1直供；方案 C 满罐后按 `LoadCtrl` 调节负荷支路并关闭多余冷机。比较供水温度、回水温度、冷机启停次数、辅助泵耗和碳排放，选择更符合工程实际的方案。
