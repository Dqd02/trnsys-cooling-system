# 部分蓄冷集中供冷 TRNSYS 系统设备功率、能耗与部分负荷曲线审查

> 审查对象：`S2_3_Partial thermal storage assistance3100` 目录下 2026-07-16 12:56 生成的 `Project11.dck` 及同次仿真输出。  
> 仿真区间：3216–6552 h，时间步长 0.25 h，共 13,345 个时刻、3,336 h。  
> 说明：本报告以当前 DCK 为准。旧报告中“冷机1为 3,100 kW”的结论已不适用于当前模型；当前两台冷机均为 2,000 kW。

## 1. 结论摘要

1. **装机参数**：两台冷机合计额定制冷量 4,000 kW，参考工况额定输入功率约 650.72 kW；两台冷却塔风机合计 114.44 kW；全部水泵合计 320.46 kW。未考虑同时使用系数时，设备连接功率合计约 **1,085.62 kW**。
2. **实际仿真峰值**：根据累计能耗相邻时刻差分反算，15 min 平均总电功率峰值约 **940.25 kW**，出现在两台冷机、两塔、两套冷冻/冷却水泵和蓄冷支路变频泵同时运行时，低于连接功率，控制逻辑上自洽。
3. **冷季电耗**：`any_type_energy.xls` 末行累计电耗为 **453.10 MWh**。其中冷机 197.79 MWh（43.65%）、冷却塔 63.23 MWh（13.96%）、水泵 192.08 MWh（42.39%）。
4. **核心判断**：各设备额定功率的工程量级基本合理，但**水泵能耗占比明显偏高**。冷却塔采用单速风机，塔耗也偏高但可由控制方式解释。当前问题主要在运行策略和水力拓扑，而不是积分单位或某一台设备功率填错。
5. **季节能效**：负荷文件在该区间的冷量需求约 1,281.40 MWh，按需求冷量/全站电耗计算的表观季节系统 COP 约 **2.83**。但有负荷时供水温度超过 7°C 的时刻约占 19.3%，因此该 COP 不能作为最终方案优劣结论，必须在供冷品质相同的前提下比较。
6. **曲线参数**：冷机 PLR 曲线在 25%–100% 范围内总体可用，75% PLR 处效率最高的趋势合理；但 0–25% 区间没有最小稳定负荷和启停损失，会高估低负荷效率。水泵曲线在中低流量下明显偏保守，且 0.1 的常数项使小流量功率过高，是泵耗偏大的重要原因之一。
7. **结果可信度**：日志记录 22 个不收敛时步，占 0.165%，另有少量泵质量平衡失败和 Type31 管内容量警告。对总量的影响可能不大，但研究论文或方案定型前仍应消除并复算。

## 2. 单位与统计口径

- Type666 的 `Rated Capacity` 单位为 kJ/h，冷机额定输入功率按 `制冷量/COP` 折算。
- Type114、Type110 和 Type126 的功率参数/输出单位为 kJ/h，除以 3,600 得到 kW。
- `any_type_energy.xls` 虽然后缀为 `.xls`，实际是 Type65 输出的制表符文本，不是 Excel 工作簿。
- Type24 将设备的瞬时功率（kJ/h）对小时积分，因此各列为**累计能耗 kJ**；末行才是仿真区间总能耗。
- “等效满负荷小时”按 `累计电耗/额定功率` 计算。对定速泵和单速塔可近似看作运行小时；对冷机和变频泵只表示能耗等价值，不等于真实开启时数。

### 4.3 能耗合理性判断

| 指标 | 结果 | 判断 |
|---|---:|---|
| 负荷需求冷量 | 1,281.40 MWh | 来自同区间负荷文件积分 |
| 冷机电耗 | 197.79 MWh | 量级合理 |
| 辅机电耗 | 255.31 MWh | 偏高，为冷机电耗的 1.29 倍 |
| 全站电耗 | 453.10 MWh | 与各模块末值求和一致 |
| 表观季节系统 COP | 2.83 | 对水冷集中供冷系统偏低，主要受辅机拖累 |
| 15 min 平均总功率峰值 | 940.25 kW | 小于连接功率，合理 |

重点问题如下：

1. **泵耗过高**。水泵占全站电耗 42.39%，已经接近冷机电耗。释冷泵与变频泵3合计 92.76 MWh，占全站 20.47%。在当前拓扑中，两者位于同一水箱—负荷—水箱回路的供、回水侧；若真实系统没有换热器或水力分隔，这相当于同一闭式回路串联设置两台输配泵，可能重复计算泵功。若实际设计确有两级泵，则应提供各自承担的扬程和水力边界。
2. **冷却塔风机固定全速**。Type126 为单速塔，冷机一旦开启，塔风机即按 57.22 kW 满功率运行。塔耗占 13.96%，在平均冷机负荷约 55% 的情况下偏高但可解释。用变频塔或分级风机控制后，通常有明显下降空间。
3. **冷机台数控制仍可优化**。窗口内只要蓄冷或有负荷，两台冷机同时启动，两个冷冻水泵、两个冷却水泵和两个塔也同时启动。在低负荷/低蓄冷需求时，先开一台并按需求投第二台，往往比两台同时低负荷更节省定速辅机能耗。
4. **供冷品质尚未等价**。在负荷大于 5 kW 的 5,527 个时刻中，供水温度均值 5.47°C、95 分位值 8.65°C、最大值 10.61°C；超过 7°C 的时刻为 1,069 个（19.3%），超过 8°C 的时刻为 573 个（10.4%）。Type682 会把给定负荷施加到水流上，但高供水温度意味着末端能力和舒适性未必满足，因此不能只用 COP 判断方案更优。
5. **蓄冷罐初始状态不一致**。25 个节点初温均为 15°C，而控制中的暖态参考为 12°C。首个循环含有把水箱从 15°C 拉回工作区间的额外冷量。不同方案比较时必须统一初始 SOC，并尽量保证仿真末端 SOC 与初始 SOC 相同，或扣除水箱净储能变化。

### 4.4 数值可靠性限制

- 22 个时步未收敛，占总时步约 0.165%。
- Unit6、10、19、20、33 分别报告 13、9、12、3、10 个时步的泵质量平衡失败；这些时刻可能重叠。
- 多个 Type31 报告单时间步流量超过管内容量。这通常是 15 min 步长远大于短管停留时间造成的数值模型不适配，不能靠无限放大管径解决。
- 两台 Type666 各有 9 次冷冻水出水温度低于性能数据下限 4°C，模型采用边界值而非外推。

这些警告比例较小，当前总能耗可用于问题定位和初步比较；但在论文、设备定型或经济性结论中，应先修正质量平衡和曲线越界，再以同一初末蓄冷状态复算。

## 5. 冷机 PLR 曲线审查

三份 `WaterCooledChiller_PLR*.Dat` 内容完全相同。当前 DCK 只调用 PLR1 和 PLR2，PLR3 未使用。

| PLR | 满负荷功率比 `P/P_full` | 相对 COP `PLR/(P/P_full)` | 判断 |
|---:|---:|---:|---|
| 0.00 | 0.0000 | — | 停机功率为零，未计待机功耗 |
| 0.25 | 0.2497 | 1.001 | 与满负荷效率基本相同 |
| 0.50 | 0.4956 | 1.009 | 与满负荷效率基本相同 |
| 0.75 | 0.6902 | 1.087 | 效率峰值，比满负荷高约 8.7% |
| 1.00 | 1.0000 | 1.000 | 归一化参考点 |

### 合理之处

- 功率随负荷单调增加，且所有点均满足非负和满负荷归一化。
- 离心式冷水机组在约 60%–80% 负荷附近效率优于满负荷是合理趋势；75% 处约 8.7% 的 COP 提升不算异常。
- 当前仿真中单台峰值约 320.5 kW，没有因 PLR 表产生超过当前工况允许值的功率异常。

### 主要不足

1. **0–25% 区间过于理想化**：Type666 在 0 和 0.25 之间插值时，功率几乎与 PLR 成正比，等价于极低负荷仍保持接近额定 COP。真实冷机通常存在最小稳定 PLR、热气旁通或启停循环损失。
2. **没有启停惩罚**：当前 0 PLR 功率为 0，适用于关机状态，但没有辅助待机功率、油泵/控制功率和频繁启停损失。
3. **数据来源不明**：三台机组的温度性能表和 PLR 表完全相同，适合作为同型号设备的第一版模型，但研究结论应由目标机组厂家选型数据或实测数据校准。
4. **缺少 PLR 时序输出**：现有能耗文件只能反推平均功率，不能统计冷机在 `<0.25`、`0.25–0.5`、`0.5–0.75`、`>0.75` 各区间的运行时长。

### 建议

- 若暂时没有厂家数据，保留 0.25–1.0 曲线作为基准是可接受的，但应把最低稳定 PLR 作为敏感性参数，例如 0.15、0.20、0.25 三档，并在低于最低 PLR 时采用启停循环模型。
- 下一次输出应增加：实际制冷量、可用容量、PLR、冷机功率、冷冻水出水温度、冷却水进水温度和启停次数。
- 若两台设备确为同型号，可以共用同一数据文件，不必保留三份内容完全相同的 PLR 文件；但当前 PLR3 未被调用，不影响结果。

## 6. 变频水泵部分负荷功率曲线审查

三台 Type110 使用相同系数：

```text
P/P_rated = 0.1 + 0.3u + 0.2u² + 0.4u³
```

其中 `u` 为控制信号/流量比。泵关闭时 Type110 由控制逻辑输出零功率；泵开启后，0.1 常数项使低流量仍保留较高功率。

| 控制量 `u` | 当前功率比 | 47.60 kW 泵对应功率 | 纯立方律 `u³` | 判断 |
|---:|---:|---:|---:|---|
| 0.05 | 0.1156 | 5.50 kW | 0.0001 | 常数项完全主导 |
| 0.10 | 0.1324 | 6.30 kW | 0.0010 | 明显偏高 |
| 0.25 | 0.1938 | 9.22 kW | 0.0156 | 偏保守 |
| 0.50 | 0.3500 | 16.66 kW | 0.1250 | 有较高静压/定压差时可出现 |
| 0.55 | 0.3921 | 18.66 kW | 0.1664 | 当前备用直供常用区间附近 |
| 0.75 | 0.6063 | 28.86 kW | 0.4219 | 基本可接受 |
| 1.00 | 1.0000 | 47.60 kW | 1.0000 | 满负荷归一化正确 |

### 判断与权衡

- 与纯立方律相比，当前曲线在中低流量下高很多。但纯立方律只代表无静压、系统阻力随流量平方变化的理想下限，不能直接据此把当前曲线判为错误。
- 与常用的低静压变频泵基准曲线相比，当前曲线在 25% 流量处通常会高出较多，在 50% 流量处也偏高；它更像“维持较高定压差、存在旁通或泵效率下降”的保守假设。
- 当前控制又把最低 `LoadCtrl` 设为 0.05。5% 流量比不等于实际变频器允许的最低频率；真实水泵常受最小转速、最小流量、冷机蒸发器流量和压差传感器设定限制。把 0.05 直接作为物理最小工况缺少依据。
- DCK 第 969 行公式实际上允许 `LoadCtrl` 最大到 1，但行尾注释仍写“最高限制为 0.5”，应更新注释，避免后续误读。

### 建议的校准方法

优先级从高到低如下：

1. **厂家/实测拟合**：收集 100%、75%、50%、25% 流量下的输入功率，按实际管网压差控制策略拟合三次曲线；要求运行段单调、`P(1)=1`，并把停机状态单独处理。
2. **区分三台泵的水力任务**：蓄冷泵、负荷泵和回水泵不应因为额定流量相同就默认使用同一曲线。不同扬程、静压比例和压差复位策略应分别拟合。
3. **设置物理最小控制量**：根据厂家最低频率、最小稳定流量和末端压差确定 `u_min`，而不是固定取 0.05。若低于 `u_min`，应采用停泵/间歇运行或旁通模型。
4. **做曲线敏感性分析**：至少比较当前保守曲线、低静压 VSD 基准曲线和厂家曲线三种情景，并报告泵耗和全站 COP 的变化。

## 7. 建议的修改顺序

| 优先级 | 建议 | 权衡 |
|---|---|---|
| P0 | 修复 22 个不收敛时步及泵质量平衡失败，核对 Type31 与 15 min 步长的适配 | 需要检查水力连接；但这是研究结论可信度的前提 |
| P0 | 统一水箱初始温度与 `T_warm_ref`，并保证方案比较时初末 SOC 等价 | 可能需要预运行或多日循环，计算量会增加 |
| P0 | 将供水温度达标率、未满足冷量/温度小时纳入评价 | 可能使当前看似较好的能效指标下降，但比较才公平 |
| P1 | 核实 Unit6 与 Unit33 是否对应真实两级泵；若同一闭式回路仅有一台实际泵，删除重复泵耗 | 节能潜力最大；必须以真实水力系统为准，不能只为降低能耗而删除 |
| P1 | 冷机按负荷和蓄冷需求分级启停，低需求时先开一台 | 可显著减少定速塔和定速泵耗；需同时约束蓄冷窗口结束前的目标 SOC |
| P1 | 将冷却塔改为变频/分级风机，并按冷却水温或逼近度控制 | 增加控制复杂度，但当前塔耗占比高，值得建模 |
| P1 | 校准三台 Type110 的独立泵曲线和最小控制量 | 需要厂家或实测数据；没有数据时应做敏感性区间而非给单一结论 |
| P2 | 增加冷机 PLR、启停次数、供回水温度、流量、SOC 和模式信号输出 | 输出文件会增大，但能直接解释能耗变化 |

## 8. 最终评价

当前模型已经从设备容量层面形成了两台同规格 2 MW 水冷机组，冷机、单机冷冻水流量、冷却水流量和冷却塔能力总体匹配；各模块累计能耗的单位与积分也正确。**目前不应优先改冷机额定功率，而应优先处理泵网拓扑、泵/塔部分负荷控制、冷机台数控制和供水温度达标问题。**

在完成 P0 项目前，453.10 MWh 和系统 COP 2.83 可作为当前版本的诊断基线，不宜直接作为最终节能率或经济性结果。完成修正后，应以“相同负荷、相同供水温度达标率、相同初末 SOC”为比较边界重新统计各模块电耗。
