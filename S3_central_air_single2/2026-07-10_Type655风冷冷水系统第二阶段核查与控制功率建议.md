# Type655 风冷冷水中央空调系统第二阶段核查与控制、功率建议

核查对象：`S3_central_air_single2/Project11.dck`、`Project11.log`、`Project11.lst`、`Project11.plt`、`load_year_15min_new.csv`

## 1. 结论先行

当前模型已经形成可运行的冷冻水闭环：

```text
Type655 风冷冷水机组
  -> Type682 等效建筑负荷端
  -> Type31 管道
  -> Type110 冷冻水泵
  -> Type655

Type9 -> Type682 负荷
Type15 -> Type655 室外干球温度
```

这证明组件方向和基本连接成立，但审查结论只能是：**有条件通过，适合结构连通测试，尚不适合直接输出最终设备规模和年能耗结论。**

当前需要优先解决的不是增加大量模块，而是以下五项：

1. Type655 和 Type110 的控制输入仍未连接，当前依靠初值 `1.0` 全时段运行；
2. Type655 的通用样本性能表最低室外温度为 `23.89 C`，实际仿真最低 `11.8 C`，41% 的性能表调用越界；
3. Type31 报告管内容量不足，且当前 `0.2 m` 管径在设计流量下流速约 `4.70 m/s`，明显偏高；
4. Type9 当前启用插值，已经把 8:00 附近的启动尖峰平滑，设备峰值校核可能偏低；
5. 当前输出只保存温度，没有保存冷机功率、COP、PLR、满足冷量、泵功率和未满足负荷，无法完成科学验收。

建议的实施顺序为：

```text
先修 Type9 和控制
-> 再修 Type655 性能表
-> 再处理 Type31
-> 再补功率输出和空气侧风机功率
-> 最后扩展多台冷机和变流量控制
```

## 3. Type655 到底是什么

### 3.1 物理含义

Type655 是 TESS HVAC Library 中的**风冷冷水机组性能图谱模型**。它代表真实设备中的：

```text
蒸发器 + 压缩机 + 风冷冷凝器 + 冷凝器风机 + 机组控制
```

但它不逐项模拟制冷剂压力、焓、蒸发器换热面积和压缩机转速，而是用厂家或样本性能表直接计算整机表现。

### 3.2 它是否会自动对水制冷

会。Type655 每个时间步执行的核心逻辑是：

1. 读取冷冻水回水温度 `T_chw_in`；
2. 读取冷冻水质量流量 `m_chw`；
3. 读取供水设定温度 `T_chw_set`；
4. 读取室外干球温度和启停信号；
5. 从 `Samp_C.Dat` 得到当前可用容量修正系数和 COP 修正系数；
6. 从 `Samp_PLR.Dat` 得到部分负荷功率系数；
7. 计算实际满足冷量 `Q_met`；
8. 按下式降低水温：

```text
T_chw_out = T_chw_in - Q_met / (m_chw x Cp)
```

若机组容量足够，出水会达到设定温度；若容量不足，Type655 只提供可用容量，出水温度将高于设定值。

### 3.3 Type655 不会自动完成的事情

Type655 不会自动计算：

- 冷冻水泵扬程与管网压降；
- 建筑房间温湿度；
- 风机盘管或 AHU 风量；
- 新风除湿量与凝结水；
- 多台冷机台数切换；
- 最小流量旁通；
- 工作日启停；
- 水管实际尺寸；
- 末端风机、新风风机电耗。

### 3.4 Type655 功率是否包含风冷冷凝器风机

当前样本性能文件明确写的是 `COP (All Power)`。在当前配置下，应把 Type655 Output 3 理解为整台风冷冷水机组的电功率，通常包括压缩机和机组自带冷凝器风机，不应再单独增加一个“室外冷凝器风机功率”。

前提是正式输入的 `Rated COP` 也采用厂家“整机输入功率”口径。如果以后使用的是压缩机单独 COP，则必须重新统一口径。

`air_con` 中 Type146 表示的是新风风机，不是 Type655 的风冷冷凝器风机。

## 5. Type9 时间序列是当前隐藏的峰值风险

### 5.1 当前设置

```text
START = 3216 h
STOP  = 6552 h
STEP  = 0.25 h
Header Lines to Skip = 12865
Interpolate or not = 1
Average or instantaneous = 1
```

### 5.2 数据事实

原始负荷峰值为：

```text
TIME = 5480.25 h
Q = 3,095.37 kW
```

但当前 `Project11.plt` 在该时刻显示的水温响应明显低于 3,095 kW、5 K 温升应有的结果，表现接近相邻数据点被平均后的负荷。原因是 Type9 开启了插值/平均处理。

这意味着当前仿真会平滑启动尖峰，可能使冷机容量看起来比实际更充足。

### 5.3 建议

若 CSV 每行已经是对应 15 min 区间的平均负荷率，建议把：

```text
Interpolate or not = 0
Multiplication factor = 1.0
```

并用 Type25c 同时输出 `TIME` 和 Unit 22 Output 1，逐行对照 CSV。验收标准是：

```text
TIME = 5480.25 h 时，Unit 22 Output 1 = 11,143,328.98 kJ/h
```

若不相等，再比较 `Header Lines to Skip = 12864` 与 `12865`。不能只用供冷期起点的一串零值判断跳行是否正确，因为两个设置在零负荷时看不出差别。

## 6. Type655 性能表必须修正

### 6.1 当前性能表范围

`Samp_C.Dat` 的室外干球温度点为：

```text
23.89, 29.44, 35.00, 40.56, 46.11 C
```

冷冻水设定温度点为：

```text
4.44, 5.56, 6.67, 7.78, 8.89, 10.00 C
```

当前 `7 C` 供水设定在表内，没问题；但供冷期室外温度范围为 `11.8-35.29 C`，低温端明显超出表格。

Type655 对越界输入采用边界值，不进行真实外推。因此在室外温度低于 23.89 C 时，模型相当于一直使用 23.89 C 的机组性能，年能耗会出现系统偏差。

### 6.2 正式性能表建议

优先向拟选厂家获取下列数据：

- 15、20、25、30、35、40、45 C 室外干球温度；
- 5、6、7、8、9、10 C 冷冻水出水温度；
- 各工况可用制冷量；
- 各工况整机输入功率；
- 25%、50%、75%、100% PLR 的输入功率或 COP；
- 最低环境运行温度、最小冷冻水流量和最小稳定 PLR。

然后按 `Samp_C.Dat` 和 `Samp_PLR.Dat` 的格式换算为容量比、COP 比和满负荷功率比。

没有厂家数据时，可以把当前样本表用于结构测试，但不能把结果表述为具体市场设备的精确年能耗。

## 7. 冷机容量和功率配置建议

### 7.1 负荷统计

| 指标 | 冷负荷 |
|---|---:|
| 非零时段中位数 | 1,239 kW |
| P90 | 2,360 kW |
| P95 | 2,536 kW |
| P99 | 2,742 kW |
| 峰值 | 3,095 kW |

当前 `3,100 kW` 额定容量仅比峰值高约 0.15%，还未考虑泵热、管道热增益、性能表高温修正和设备老化。它在当前典型气象年内可能勉强满足，但不适合作为工程推荐容量。

### 7.2 推荐基准方案

建议把等效总容量设为约 `3,600 kW`，即峰值的 1.16 倍：

```text
Equivalent Rated Capacity = 3,600 kW
                          = 12,960,000 kJ/h
Rated COP baseline        = 3.2
Rated input power         = 1,125 kW
```

`COP = 3.2` 对大型风冷冷水机组属于合理的中性基准。建议同时做 `3.0、3.2、3.4` 三组敏感性分析；最终参数必须以厂家在相同 `35 C 室外、7/12 C 冷冻水` 工况下的整机数据为准。

### 7.3 市场化的模块组合

| 方案 | 组合 | 总容量 | 额定总输入功率，COP 3.2 | 评价 |
|---|---|---:|---:|---|
| A | 3 x 1,200 kW | 3,600 kW | 1,125 kW | 组件较少，推荐作为第一版多机方案 |
| B | 4 x 900 kW | 3,600 kW | 1,125 kW | 部分负荷调节更细，组件和控制更多 |
| C | 4 x 1,100 kW | 4,400 kW | 1,375 kW 装机 | N+1 时剩余 3,300 kW，可覆盖峰值，适合强调可靠性 |

研究设备规模和年能耗时建议先采用方案 A；研究故障冗余时再采用方案 C。不要把 N+1 容量全部当成正常同时运行容量。

### 7.4 3 x 1,200 kW 对应水量

按单机 5 K 温差：

```text
单机额定水量 = 1200 x 3600 / (4.19 x 5)
             ≈ 206,200 kg/h
             ≈ 206 m3/h
```

三台满载总水量约 `619 m3/h`。建筑峰值实际需要约 `532 m3/h`，因此多机系统应采用分级启停或变流量，而不是三台泵始终全速。

## 8. 冷冻水泵功率建议

### 8.1 当前泵是否合理

当前 `531 m3/h、62.61 kW` 对应约 30 m 级扬程，作为整个建筑冷冻水环路的等效泵是合理的。建议第一版继续使用：

```text
Rated flow = 531,000 kg/h
Rated power = 225,400 kJ/h = 62.61 kW
```

正式选泵时必须根据最不利环路压降重新计算：

```text
P_elec = rho x g x Vdot x H / eta_total
```

### 8.2 当前 Type110 功率曲线

当前仅有一个功率系数 `1.0`，因此只适合 0/1 定流量启停：

```text
PumpCtrl = 0 -> 0 功率
PumpCtrl > 0 -> 基本按额定功率计算
```

若后续采用连续变流量，需要改成至少四项功率曲线。没有厂家曲线时，可用项目 S3 已采用的基准：

```text
n = 4
a0 = 0.10
a1 = 0.30
a2 = 0.20
a3 = 0.40
```

对应：

```text
P/P_rated = a0 + a1 r + a2 r^2 + a3 r^3
```

这里 `r` 为 Type110 控制信号和流量比。该曲线仍应通过实际泵样本校准。

### 8.3 多机方案的泵

若采用 `3 x 1,200 kW`，可以设置 3 台约 `206 m3/h、22-25 kW` 的一次泵，总额定功率约 `66-75 kW`。这与当前单台等效泵 `62.61 kW` 在同一量级。

## 9. 空气侧风机功率是当前总能耗边界的缺口

Type682 输入的是建筑热负荷，它不会产生风机电耗。Type655 只覆盖风冷冷水机组，不覆盖室内 FCU/AHU 和新风风机。

`air_con` 原模型的项目内参数合计为：

```text
48 个 Type996 末端风机：59.33 kW
12 个 Type146 新风风机：24.67 kW
空气侧风机合计：84.00 kW
```

由于当前独立模型不再求空气状态，不建议重新接入 Type996/508 来计算同一冷负荷。可以增加一个空气侧风机功率 Equation：

```trnsys
AirSideFanRated_kW = 84.0
AirSideFanPower_kW = AirSideFanRated_kW*PlantEnable
```

这个 `84 kW` 是与原 `air_con` 模型一致的项目基准，约为建筑面积的 `4.38 W/m2`，属于可用的第一版值。建议用 `80、120、150 kW` 做敏感性分析，最终由实际 AHU/FCU 数量、风量和机外余压确定。

采用推荐的 `3,600 kW` 冷机容量时，额定总功率基准约为：

```text
Type655 等效冷机：1,125 kW
冷冻水泵：          62.6 kW
空气侧风机：        84.0 kW
合计：           1,271.6 kW
```

该合计不包括办公设备、照明和其他非空调电耗。

## 10. Type31 管道问题

### 10.1 当前参数的工程问题

```text
Inside diameter = 0.2 m
Length = 10 m
Flow = 531 m3/h
```

对应流速约：

```text
v = 4.70 m/s
```

大型冷冻水总管通常应控制在约 `1.2-2.0 m/s` 的工程范围。按当前流量：

| 目标流速 | 所需内径 |
|---:|---:|
| 1.2 m/s | 0.396 m |
| 1.5 m/s | 0.354 m |
| 2.0 m/s | 0.306 m |

因此工程初值建议采用约 `DN350-DN400`，而不是 DN200。

### 10.2 为什么只加大管径仍可能有警告

15 min 内通过的水量约为：

```text
531 m3/h x 0.25 h = 132.75 m3
```

真实 10 m 管段不可能容纳一个完整时间步的流量，所以 Type31 的容量警告不能靠虚构巨大管径消除。

### 10.3 推荐处理

如果不研究管道热损失和输送延迟：

```text
删除 Unit 9 Type31
Type682 Output 1/2 直接接 Type110 Input 1/2
```

这是当前最推荐的处理。

如果研究管损：

1. 同时建立供水和回水等效管段；
2. 使用实际总长度、DN350-DN400、实际保温参数；
3. 管道环境温度用机房/竖井温度，不要直接使用室外干球温度；
4. 采用更小时间步检查数值稳定性；
5. 只有真实系统有缓冲罐时才增加 Type4 系列，不能为消除警告虚构容积。

## 11. 工作日 8:00-22:00 控制信号

### 11.1 星期偏移核查

对全年负荷逐日检查得到：

- Day 0-4 有负荷；
- Day 5-6 为零；
- 此后每 7 天重复；
- 全年周内索引 0-4 均为工作日，5-6 均为周末。

因此在约定 `0=周一、...、6=周日` 时：

```text
WeekdayOffset = 0
```

与当前 `load_year_15min_new.csv` 一致。

### 11.2 当前系统没有蓄冷

本模型没有 Type534 水箱，因此用户示例中的：

```text
IsChargeTime
ChargeWindow
```

不应放入当前中央空调模型。0:00-8:00 应当是停机时段，不是蓄冷时段。

### 11.3 推荐的第一版 Equation

下面的 `QloadRaw` 取自 Unit 22。建议先将 Type9 插值和时间对齐修正，再使用该控制。

```trnsys
HourOfDay = TIME-24*INT(TIME/24)
DayNum = INT(TIME/24)
WeekIndex0 = DayNum-7*INT(DayNum/7)
WeekdayOffset = 0
RawWeekIndex = WeekIndex0+WeekdayOffset
Weekday = RawWeekIndex-7*INT(RawWeekIndex/7)

IsWorkday = LT(Weekday,5)

IsLoadTime = GE(HourOfDay,8)*LE(HourOfDay,22)

QloadRaw = [22,1]
Qnoise = 3600
HasLoad = GT(QloadRaw,Qnoise)

ScheduleEnable = IsWorkday*IsLoadTime
PlantEnable = ScheduleEnable*HasLoad

QloadCmd = QloadRaw*PlantEnable
TchwSet = 7.0
PumpCtrl = PlantEnable
ChillerCtrl = PlantEnable

AirSideFanRated_kW = 84.0
AirSideFanPower_kW = AirSideFanRated_kW*PlantEnable
```

连接关系：

| Equation 输出 | 连接位置 |
|---|---|
| `QloadCmd` | Type682 Load，替换当前 `[22,1]` 直连 |
| `TchwSet` | Type655 Input 3 |
| `ChillerCtrl` | Type655 Input 5 |
| `PumpCtrl` | Type110 Input 3 |
| `AirSideFanPower_kW` | Type25c/Type65c 输出，不接水环路 |

### 11.4 为什么 22:00 建议用 LE

负荷文件在每天 `22:00` 的时间点仍包含少量非零负荷，全年合计约 `24,590.7 kWh`，占总冷量 `0.493%`。这通常是 `21:45-22:00` 区间在时间戳 22:00 的平均负荷。

若使用：

```trnsys
LT(HourOfDay,22)
```

会把这最后一个 15 min 区间删除。第一版建议使用：

```trnsys
LE(HourOfDay,22)
```

并确认 Type9 的时间戳定义。若你的数据明确把 22:00 行定义为 `22:00-22:15`，才改回 LT。

### 11.5 Qnoise 的含义

当前最小正负荷仅约 `0.008 kW`，属于数值尾差。建议：

```text
Qnoise = 3600 kJ/h = 1 kW
```

低于 1 kW 时不开启 3 MW 级系统，避免由数值噪声触发设备。

### 11.6 是否需要提前启动

当前模型几乎没有真实水系统热惯性，可以在 8:00 同时启泵和启冷机。若以后加入真实管网容积或缓冲罐，可把预启动时间设为 7:45：

```trnsys
IsPreStart = GE(HourOfDay,7.75)*LT(HourOfDay,8)
PreStartEnable = IsWorkday*IsPreStart
PumpCtrl = MAX(PlantEnable,PreStartEnable)
ChillerCtrl = MAX(PlantEnable,PreStartEnable)
```

是否预启动应由 8:00 供水温度能否达到 7 C 决定，不应在无热惯性的模型中人为增加能耗。

## 12. 多台冷机控制的后续版本

若采用 `3 x 1,200 kW`，第一版可按约 1,000 kW 和 2,000 kW 进行保守分级：

```trnsys
Qload_kW = QloadCmd/3600

Chiller1Ctrl = PlantEnable
Chiller2Ctrl = PlantEnable*GT(Qload_kW,1000)
Chiller3Ctrl = PlantEnable*GT(Qload_kW,2000)
```

这只是初始逻辑。正式模型应增加：

- 启停回差；
- 最小开机时间；
- 最小停机时间；
- 每台机组最小 PLR；
- 室外高温容量修正；
- 运行时间均衡；
- 对应支路泵和分流比例。

单台等效 Type655 未完成性能表和输出验证前，不建议立即扩成三台，以免增加不必要的收敛与质量平衡问题。

## 13. 必须新增的输出

新增 Type25c，至少输出：

| 变量 | 来源 |

| 原始负荷 | `[22,1]` |

```trnsys
ChillerPower_kW = [6,3]/3600

ChillerUnmet_kW = MAX(0,ChillerLoadNeed_kW-ChillerLoadMet_kW)

TotalHVACPower_kW = ChillerPower_kW+PumpPower_kW+AirSideFanPower_kW
```

累计电耗可在输出后按 0.25 h 积分，也可以增加 Type24。无论采用哪种方式，必须避免把 `kJ/h` 直接累加成 `kWh`。

## 14. 验收顺序

### 第一步：修 Type9

- 把插值改为 0；
- 输出 Unit 22；
- 用 5480.25 h 峰值验证跳行；
- 确认负荷积分仍约为 `4.988 GWh`。

### 第二步：接控制

- Type682 Load 改接 `QloadCmd`；
- Type655 Input 3、5 显式连接；
- Type110 Input 3 显式连接；
- 夜间和周末泵流量、冷机功率应为 0。

### 第三步：处理 Type31

- 不研究管损时删除；
- 研究管损时用实际供回水管并缩短时间步检查。

### 第四步：修性能表

- 室外温度至少覆盖实际 11.8-35.3 C；
- 冷冻水设定覆盖 7 C；
- PLR 表覆盖实际运行区间；
- 日志不再出现 41% 越界。

### 第五步：功率和守恒

应同时满足：

```text
Type682 Cooling Load Met ≈ QloadCmd
Type655 Load Met ≈ Type655 Load Need
Type655 Outlet Temperature ≈ TchwSet
Type110 inlet flow ≈ outlet flow
夜间和周末设备功率 = 0
```

### 第六步：再做容量和 COP 敏感性分析

建议工况：

| 参数 | 低 | 基准 | 高 |
|---|---:|---:|---:|
| 总制冷容量 | 3,300 kW | 3,600 kW | 4,400 kW，N+1 |
| Rated COP | 3.0 | 3.2 | 3.4 |
| 冷冻水泵额定功率 | 50 kW | 62.6 kW | 75 kW |
| 空气侧风机 | 80 kW | 84-120 kW | 150 kW |

## 15. 最终建议

当前 Type655 + Type682 + Type110 的方向是正确的，可以代表“风冷冷水机组通过冷冻水循环满足已知建筑总冷负荷”。Type655 会自动降低水温，但它只在输入边界、设备容量和性能表可信时才具有物理意义。

本阶段不需要增加冷却塔、冷却水泵或重新接入 Type56。真正影响准确度的优先项是：

```text
Type9 不平滑峰值
+ 工作日 8-22 点明确启停
+ Type655 厂家性能表覆盖实际环境温度
+ 合理的冷机容量和泵功率
+ 空气侧风机电耗
+ 完整的功率、COP、PLR 和守恒输出
```

完成这些以后，再把一台等效 Type655 扩展成 `3 x 1,200 kW` 或 `4 x 900 kW`，仿真精度和工程解释力都会明显高于简单增加大量空气侧模块。
