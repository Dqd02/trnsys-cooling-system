# 1. 为什么不能直接设成 999999999？

因为这会让 Type56 认为：

> 只要室温超过设定值，冷源就可以无限制把热量瞬间拿走。

你文件里也已经明确写到：当前模型的 `POWER=999999999` 是理想无限冷源，会集中释放开机拉降负荷，导致早晨尖峰偏高；8:15 尖峰主要来自 8:00 制冷开启后对夜间蓄热的集中拉降，若用于机组选型或运行电耗，应进一步加入容量、送风温度和控制响应限制。

这对**识别建筑理论冷负荷**可以，但对**评价两台冷机 + 蓄冷罐真实运行**就不科学。因为超过 2200 或 3300 kW 的冷量，在真实系统里不是被无限满足，而是变成：

* 室温升高；
* 未满足冷负荷；
* 后续延迟恢复负荷。

# 2. 如果只是做“建筑冷负荷需求提取”，取多少最合理？

此时你的目的不是模拟冷机，而是问：

> 建筑在 26°C 设定温度下到底需要多少冷量？

那 `POWER` 应该足够大，但不必无限大。

你的当前负荷文件中，8-22 含开机段最大负荷约 3575 kW，其中 9-22 稳态最大负荷约 3025 kW，8:15 尖峰不建议直接作为冷水机组名义容量依据。

因此建议取：

\[

POWER\_\{\text\{ideal}} = 1.2 \sim 1.3 \times Q\_\{\text\{max}}

]

若按最大尖峰 (3575\ \text\{kW})：

\[

3575 \times 1.25 \approx 4469\ \text\{kW}

]

取整为：

\[

4500\ \text\{kW}

]

换算为 TRNSYS 的 kJ/h：

\[

4500 \times 3600 = 16,200,000\ \text\{kJ/h}

]

所以，**建筑需求提取阶段推荐：**

```text
POWER = 16200000
```

这个值比真实设备大，能完整识别建筑需求；但又不像 `999999999` 那么夸张，报告里也更好解释。

# 3. 如果是模拟“真实系统运行”，应该怎么取？

这时不能再用“理想冷源逻辑”。你应该把系统实际供冷能力限制进去。

你的真实系统最大能力不是永远 3300 kW，而是：

\[

Q\_\{\text\{available}} =

Q\_\{\text\{chiller}} + Q\_\{\text\{tank}}

]

其中：

\[

Q\_\{\text\{chiller}} = 2200\ \text\{kW}

]

\[

Q\_\{\text\{tank}} =

\begin\{cases}

1100\ \text\{kW}, & 工作时间且水箱SOC充足&#x20;

0, & 水箱无冷量或不允许放冷

\end\{cases}

]

也就是：

| **时间/状态** | **可用供冷能力**     |
| --------- | -------------- |
| 夜间蓄冷，不供冷  | 不作为建筑供冷能力      |
| 白天水箱有冷量   | **3300 kW**    |
| 白天水箱冷量不足  | **2200 kW**    |
| 非工作时间关闭制冷 | 0 kW 或仅保留保护性设定 |

你之前机组选型文件也建议采用“冷水机组承担稳定基载，水箱承担超过基载的高峰差额”，并推荐白天冷机基载控制在 2000–2200 kW。

所以真实系统评价阶段应使用这个逻辑：

```text
如果 8:00-22:00 且 SOC > SOC_min：
    POWER_total = 11880000   ! 3300 kW
否则如果 8:00-22:00：
    POWER_total = 7920000    ! 2200 kW
否则：
    POWER_total = 0 或关闭制冷
```

# 4. 关键坑：不要把 3300 kW 填给每个热区

这个很重要。

Type56 里的 `POWER` 往往是**热区/airnode 层面的理想制冷能力**。如果你有办公室、会议室、厕所、走廊等多个热区，不能每个热区都填：

```text
POWER = 11880000
```

否则就变成：

> 每个热区都有 3300 kW 制冷能力。

那整个建筑会被你无意中放大成几十 MW 的虚假冷源，模型又回到“无限冷源”的问题。

正确做法有两个。

## 方法 A：保留 Type56 理想负荷，只在系统侧限额

这是我更推荐的做法。

Type56 仍用于输出建筑理论冷负荷，然后在 TRNSYS Studio 里用 Equation/Controller 处理：

\[

Q\_\{\text\{served}} = \min(Q\_\{\text\{load}}, Q\_\{\text\{available}})

]

\[

Q\_\{\text\{unmet}} = \max(0, Q\_\{\text\{load}} - Q\_\{\text\{available}})

]

这种方法最清楚：

* Type56 输出：建筑想要多少冷量；
* 冷机 + 水箱：系统实际能提供多少；
* 两者差值：未满足冷量。

适合你现在做机组选型、蓄冷策略、碳排放优化。

## 方法 B：把总容量分配到各个热区

如果你一定要在 Type56 内部限制 `POWER`，那必须把 2200 或 3300 kW 分配到各热区，保证所有热区 `POWER` 之和等于系统总容量。

最粗略可以按空调面积分配。当前空调服务面积为 19190.8 m²。

### 仅冷机 2200 kW 时

\[

\frac\{2200}\{19190.8}=0.1146\ \text\{kW/m²}

]

即：

\[

114.6\ \text\{W/m²}

]

换算成 TRNSYS：

\[

114.6\ \text\{W/m²} \times 3.6 = 412.6\ \text\{kJ/(h·m²)}

]

### 冷机 + 水箱 3300 kW 时

\[

\frac\{3300}\{19190.8}=0.1720\ \text\{kW/m²}

]

即：

\[

172.0\ \text\{W/m²}

]

换算成 TRNSYS：

\[

172.0\ \text\{W/m²} \times 3.6 = 619.2\ \text\{kJ/(h·m²)}

]

例如按面积粗分：

| **热区类型** | **单区面积** | **仅冷机 2200 kW 分配**       | **冷机+水箱 3300 kW 分配**      |
| -------- | -------- | ------------------------ | ------------------------- |
| 办公室      | 800 m²   | 约 91.7 kW = 330,000 kJ/h | 约 137.6 kW = 495,000 kJ/h |
| 会议室      | 400 m²   | 约 45.9 kW = 165,000 kJ/h | 约 68.8 kW = 248,000 kJ/h  |
| 走廊       | 300 m²   | 约 34.4 kW = 124,000 kJ/h | 约 51.6 kW = 186,000 kJ/h  |

但我不太建议只按面积分，因为会议室人员密度高，峰值负荷显著高于普通办公室。更好的分配方法是：

> 用每个热区的 9-22 P95 理想冷负荷作为权重分配总容量。

公式是：

\[

POWER\_i =

POWER\_\{\text\{total}}

\times

\frac\{Q\_\{i,\text\{P95}}}\{\sum Q\_\{i,\text\{P95}}}

]

这样会议室会得到更多容量，走廊得到较少容量，更符合实际末端配置。

## 1. `Sensible cooling power` 是什么意思？

这里的 **Sensible cooling power** 指的是：

> Type56 为了把房间空气温度维持在设定温度时，允许移除的最大**显冷量**。

也就是只针对温度控制的“显热冷量”，主要对应：

* 降低空气温度；
* 抵消围护结构传热；
* 抵消人员、照明、设备显热；
* 抵消太阳辐射带来的显热。

它不完全等于冷水机组总制冷量，因为冷水机组总制冷量还可能包括：

* 新风冷却负荷；
* 除湿潜热负荷；
* 盘管换热限制；
* 水泵、板换、管网损失；
* 蓄冷罐放冷能力限制。

你图里下面还有 **Dehumidification**，说明湿度控制是单独设置的。所以 `Sensible cooling power` 更准确地说是：

> **Type56 内部理想冷却器的最大显冷能力，不是完整冷冻站总制冷能力。**

## 3. 那我能不能直接在这里设 3300 kW？

**不建议。**

你现在的真实系统能力是：

```text
冷机：2 × 1100 = 2200 kW
水箱最大补冷：1100 kW
水箱有冷量时总能力：3300 kW
```

但是 3300 kW 是**整栋楼冷站侧总能力**，不是每个热区的能力。

如果你在 `COOL001` 里设：

```text
POWER = 3300 kW = 11,880,000 kJ/h
```

而所有办公室、会议室、厕所、走廊都调用同一个 `COOL001`，就可能变成：

```text
办公室1：最多3300 kW
办公室2：最多3300 kW
会议室1：最多3300 kW
……
```

这显然不对。

真正的 3300 kW 应该满足：

\[

\sum\_i Q\_\{cool,i,\max}=3300\ \text\{kW}

]

而不是：

\[

Q\_\{cool,i,\max}=3300\ \text\{kW}

]

这点特别重要。

## 4. 你现在最推荐的做法：Type56 仍用无限冷源，3300 kW 放到系统侧约束

因为你说你现在 Type56 只导出整栋楼负荷，不区分办公室、厕所等热区，那么最稳妥的做法是：

> **Type56 继续作为“建筑理论负荷发生器”；
> 冷机和水箱容量限制放到 TRNSYS Studio 的 Equation 或后处理里做。**

也就是：

```text
Q_load = Type56输出的建筑理论冷负荷
Q_chiller = 2200 kW
Q_tank_max = 1100 kW
```

水箱可用时：

\[

Q\_\{available}=2200+1100=3300\ \text\{kW}

]

水箱不可用时：

\[

Q\_\{available}=2200\ \text\{kW}

]

然后计算：

\[

Q\_\{served}=\min(Q\_\{load},Q\_\{available})

]

\[

Q\_\{unmet}=\max(0,Q\_\{load}-Q\_\{available})

]

这比直接在 Type56 里设 3300 kW 更科学。因为你能清楚地区分：

| **变量**        | **含义**        |
| ------------- | ------------- |
| `Q_load`      | 建筑想要的冷量       |
| `Q_available` | 冷机+水箱实际能提供的冷量 |
| `Q_served`    | 实际满足的冷量       |
| `Q_unmet`     | 未满足冷负荷        |

这正好符合你现在的研究目标：判断 **2×1100 kW 冷机 + 1100 m³ 水箱** 是否足够、何时不足、未满足多少。

你的机组选型文件也明确建议白天冷水机组承担稳定基载，水箱承担超过基载的高峰差额，而不是水箱单独主导全天供冷。

\[

\frac\{Q\_\{i,P95}}\{\sum Q\_\{i,P95}}

]

也就是按每个热区的 P95 理论负荷权重分配。

不过你现在没有分区负荷输出，所以现阶段**别强行在 Type56 内部分配**，否则容易引入新的错误。

## 6. `Electric Power Fraction` 是什么意思？

图中这个参数：

```text
Electric Power Fraction
fraction of actual sensible power: 0
```

它的意思是：

> 把 Type56 实际移除的显冷量，按某个比例换算成“电功率输出”。

大概可以理解为：

\[

P\_\{elec}=f \times Q\_\{sensible}

]

其中 (f) 就是 `Electric Power Fraction`。

例如：

| **设置** | **含义**                     |
| ------ | -------------------------- |
| `0`    | 不计算电功率                     |
| `0.25` | 认为电功率约为显冷量的25%，相当于粗略 COP=4 |
| `0.33` | 认为电功率约为显冷量的33%，相当于粗略 COP=3 |
| `1`    | 电功率等于显冷量，不符合冷机实际，通常不用      |

但是注意你图里红字已经提示了：

```text
The electric power has no influence on the thermal energy balance
```

意思是：

> 这个电功率参数**不影响房间热平衡**，只影响 Type56 输出的电耗统计。

所以它不是冷水机组模型，不会模拟 COP、部分负荷率、冷冻水出水温度、蓄冷工况效率等。

对你现在这个研究，建议：

```text
Electric Power Fraction = 0
```

原因是你后面应该用冷水机组模型，例如 Type666 或性能表，单独计算真实电耗。不要在 Type56 里用一个固定 fraction 粗略代替冷机电耗，否则会和冷机模型重复计算。

## 1. 两个选项分别是什么意思？

### 选项一：`absolute power`

意思是：

> 每一个使用 `COOL001` 的 airnode / zone，都拥有输入框里这个固定制冷能力。

如果你在这里填：

```text
11880000 kJ/h
```

也就是 3300 kW。

那么如果 48 个空调热区都调用 `COOL001`，模型可能会理解成：

```text
每个热区最大 3300 kW
```

那整栋楼总制冷能力就会被放大成几十上百 MW，严重错误。

所以 **absolute power 只适合单一区域模型，或者你已经给每个热区单独建了不同 cooling type，并手动分配了每个区的容量**。

***

### 选项二：`power related to reference floor area`

意思是：

> 按该 airnode 的参考面积 `REFAREA` 自动折算制冷能力。

TRNSYS 官方更新说明也提到，Type56 这类 regime 数据可以把 heating/cooling/ventilation/gains 的 power 或 airflow 定义为相对于 airnode 参考面积的量。()

所以它的逻辑是：

\[

Q\_\{i,\max}=q\_\{\max} \times A\_i

]

其中：

* (Q\_\{i,\max})：第 (i) 个热区最大制冷能力；
* (q\_\{\max})：你输入的单位面积制冷能力；
* (A\_i)：该热区的参考面积 `REFAREA`。

这就比较适合你的模型，因为你的办公室、会议室、厕所、走廊都是多个热区；当前空调服务面积约 19190.8 m²。

## 2. 你如果要把整栋楼限制为 3300 kW，应填多少？

你的总能力是：

\[

Q\_\{\text\{total}}=3300\ \text\{kW}

]

空调面积：

\[

A=19190.8\ \text\{m²}

]

单位面积制冷能力：

\[

q=\frac\{3300}\{19190.8}=0.172\ \text\{kW/m²}

]

也就是：

\[

172\ \text\{W/m²}

]

TRNSYS 这里用的是 kJ/h，所以要换算：

\[

1\ \text\{W}=3.6\ \text\{kJ/h}

]

\[

172 \times 3.6 = 619.2\ \text\{kJ/(h·m²)}

]

因此如果你想代表：

```text
两台冷机 2200 kW + 水箱补冷 1100 kW = 总计 3300 kW
```

你应该选择：

```text
limited
power related to reference floor area
数值填：619
```

注意：界面右侧可能仍然显示 `kJ/h`，但在选择 `power related to reference floor area` 后，它的工程含义应理解为：

```text
kJ/(h·m²)
```

## 5. 但是我要提醒你：固定 3300 kW 仍然不完全真实

你现在的 3300 kW 是：

```text
2200 kW 冷机 + 1100 kW 水箱补冷
```

但水箱不是全天都有 1100 kW 可用。你自己的方案里也已经明确，1,100 m³ 水箱对应约 9,211 kWh 蓄冷量，主要用于白天削峰，而不是全天无限补冷。

所以固定填 619，相当于告诉 Type56：

> 只要制冷开启，整栋楼永远有 3300 kW 制冷能力。

这会高估水箱能力。

更严谨的分法是：

| **工况**    | **Type56 限制** |
| --------- | ------------- |
| 仅冷机供冷     | 填 **413**     |
| 冷机 + 水箱放冷 | 填 **619**     |
| 水箱放完后     | 应回到 **413**   |

但 Type56 的这个界面通常不适合按 SOC 动态切换容量。要动态切换，最好在 Type56 外部的系统侧做控制。
