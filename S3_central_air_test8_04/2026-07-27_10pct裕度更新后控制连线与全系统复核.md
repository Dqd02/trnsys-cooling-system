## 1. 总结论

当前控制逻辑已经**基本实现**您要求的传统集中供冷策略：

- 工作日0:00-8:00，两台冷机同时开启；
- 两台供冷水泵均以信号1运行，总流量 `430000 kg/h`；
- 蓄冷水泵以信号1运行，向蓄冷罐充冷；
- 达到 `SOC>=0.95` 或 `TankFull=1` 后停止蓄冷；
- 工作日8:00后，水箱满足许可条件时优先释冷；
- 释冷泵按建筑需求流量的110%变频；
- 水箱不满足许可条件时停止释冷，切换到两台冷机；
- 两台冷机同时开启，两台供冷泵各承担建筑总需求流量的一半；
- 两台冷却塔与对应冷机进行0/1联锁。

但当前版本仍不能判为“完全满足并通过验收”，有三项必须修正：

1. Unit54冷却水泵2-1错接 `CHWP1_CTRL`，应接 `CHWP2_CTRL`。
2. `IsLoadTime` 使用 `le(HourOfDay,22)`，会额外运行22:00-22:15；严格8:00-22:00应使用 `lt(HourOfDay,22)`。
3. 最新日志仍有8台泵质量不平衡和182个未收敛时步，且比上一版本更严重，不能直接采用当前能耗结果。

另有一个定义边界：当前“水箱冷量不足”并不是用剩余kWh或实时出水温度直接判断，而是用 `SOC>0.1`、未判空和释冷泵流量能力共同代理。它符合您当前选定的简化控制，但不是严格的剩余冷量证明。

## 3. 时间和负荷检查

### 3.1 时间窗口

当前：

```text
IsChargeTime = lt(HourOfDay,8)
IsLoadTime = ge(HourOfDay,8)*le(HourOfDay,22)
```

第一条正确，代表 `[0:00,8:00)`。第二条实际上代表 `[8:00,22:00]`，在15 min仿真中会包含22:00-22:15时步。

严格按照“8:00-22:00”营业时段，应改为：

```text
IsLoadTime = ge(HourOfDay,8)*lt(HourOfDay,22)
```

### 3.2 负荷文件实测结果

对当前 `load_15min_max2.csv` 在 `3216-6552 h` 区间逐点检查：

- 周末非零负荷：0个时步；
- 工作日0:00-8:00非零负荷：0个时步；
- 工作日22:00非零负荷：99个时步；
- 22:00点最大负荷约 `1188.83 kW`。

所以如果您坚持 `[8:00,22:00)`，不仅应把 Equation 改成 `lt(...,22)`，还应处理Unit22/Unit4的22:00负荷：

推荐在负荷文件生成阶段把22:00点归零；或者增加门控负荷：

```text
BuildingLoad = [22,1]*IsWorkday*IsLoadTime
```

并把 Unit4 的 Load 输入由 `[22,1]` 改接 `BuildingLoad`。否则22:00设备关闭，但Type682仍直接收到非零负荷。

## 4. 水箱蓄冷和释冷逻辑

### 4.1 夜间蓄冷

```text
ChargeMode = ChargeWindow*Chg_bySOC
Chiller1_ON = max(ChargeMode,ChillerMode)
Chiller2_ON = max(ChargeMode,ChillerMode)
CHWP1_CTRL = max(ChargeMode,CHW_DAY_CTRL)
CHWP2_CTRL = max(ChargeMode,CHW_DAY_CTRL)
ChargePump_ON = ChargeMode
Gamma14 = 0.5*max(ChargeMode,ChillerMode)
Gamma24 = ChargeMode
```

当 `ChargeMode=1`：

- 冷机1/2均为1；
- Unit51/52均为1，各输出 `215000 kg/h`；
- Unit14把回水各分50%，每台冷机入口也是 `215000 kg/h`；
- Unit15合流为 `430000 kg/h`；
- Unit24全部导向蓄冷支路；
- Unit50以1运行，输出 `430000 kg/h`进入水箱。

这部分流量设计完全匹配您的要求。

### 4.2 “蓄满后停”的局限

当前：

```text
Chg_bySOC = lt(SOC,0.95)*(1-TankFull)
```

达到满罐条件后，`ChargeMode`会变0，设备会停。但该公式没有记忆：如果停机后水箱温度轻微回升，使 `SOC<0.95` 且 `TankFull=0`，同一夜可能再次启动。

最新未收敛警告几乎全部集中在凌晨1:45-7:45，也说明蓄满边界附近的反复启停/迭代是主要问题之一。

若您的要求是“当夜蓄满后一直停到8:00”，应使用Type93、带滞环的控制器或锁存状态，而不是只用无记忆Equation。

### 4.3 白天释冷和10%裕度

```text
MREQ = LoadKW*3600/(4.19*8)
MDCHREQ = 1.10*MREQ
TankFlowOK = le(MDCHREQ,430000)
TankCanCover = Dch_bySOC*TankFlowOK
DCHP_CTRL = TankMode*min(1,MDCHREQ/430000)
```

逻辑正确：Unit49流量为

```text
m_DCH = DCHP_CTRL*430000 = 1.10*MREQ
```

峰值 `3140.26 kW` 时：

```text
MREQ = 337260 kg/h
MDCHREQ = 370986 kg/h
DCHP_CTRL = 0.8628
```

10%裕度下，释冷泵可独立覆盖的最大建筑负荷约：

```text
430000*4.19*8/(3600*1.10) = 3639.8 kW
```

高于当前 `3140.26 kW`峰值，所以峰值不会因为泵流量能力不足而切到冷机。

注意：Type682只提取建筑实际负荷，110%流量不会自动多释放110%的冷量，只会降低水侧实际温差。

### 4.4 “水箱冷量不足”的定义并不严格

当前：

```text
Dch_bySOC = gt(SOC,0.1)*(1-TankEmpty)
TankCanCover = Dch_bySOC*TankFlowOK
```

它只证明：

- SOC仍高于0.1；
-关键节点尚未满足空罐判据；
- 释冷泵额定流量能覆盖110%需求流量。

它没有直接计算剩余可用冷量 `E_remaining`，也没有检查实际出水温度。因此变量名 `TankCanCover` 偏强，更准确可称 `TankAllowed`。

如果继续采用当前简化策略，可以保留；若要严格满足“水箱冷量不足立即切机”，至少增加实时出水温度判据，或者按水箱节点能量计算剩余可用kWh。

## 5. 双冷机直供逻辑

```text
ChillerMode = LoadWindow*(1-TankCanCover)*(1-ChargeMode)
CHW_DAY_CTRL = ChillerMode*min(1,MREQ/(2*MCHWR))
CHWP1_CTRL = max(ChargeMode,CHW_DAY_CTRL)
CHWP2_CTRL = max(ChargeMode,CHW_DAY_CTRL)
Gamma14 = 0.5*max(ChargeMode,ChillerMode)
Gamma24 = ChargeMode
Gamma29 = ChillerMode
```

白天 `ChillerMode=1` 时：

- 两台冷机同时开启；
- Unit14将总回水各分50%；
- Unit51/52使用相同信号，各承担总需求流量的一半；
- Unit15合流后送往建筑；
- Gamma24=0，冷机出水去建筑而不是水箱；
- Gamma29=1，建筑回水返回冷机侧；
- Unit49释冷泵为0。

这部分满足您的要求。

峰值 `3140.26 kW` 时每台泵：

```text
流量 = 168630 kg/h
信号 = 168630/215000 = 0.7843
单台冷机负荷约 = 1570.13 kW
```

两台 `2000 kW` 冷机容量足够。

## 9. 另外发现的未提及问题

### 9.1 Type534仍读取旧目录文件

当前DCK：

```text
ASSIGN ".../S1_tradition_full_storage_cooling3100/Example_534.dat" 32
```

没有明确读取当前 `传统_新修改/Example_534.dat`。应在Studio中改为当前文件或相对路径：

```text
ASSIGN "Example_534.dat" 32
```

### 9.2 冷机4°C设定值未显式连接

Unit9和Unit12的 `CHW Set Point Temperature` 当前未连接，只在初值中写4。建议显式接常数4，避免模型版本或迭代过程中把“初值”误当成持续设定值。

### 9.3 水箱蓄满控制缺少锁存

当前无记忆Equation可能在同一夜停止后重新启动。若论文要准确表述“蓄满后停机直到8点”，应增加有状态控制模块。

### 9.4 Type31管道容量不足

6个管道模块持续报告一个时步流量超过管内容量。它会放大模式切换时的不收敛，需校核管长、直径、管内容积和0.25 h时步，而不是只增大最大迭代次数。

### 9.5 低负荷双机运行

当总负荷低于约1000 kW时，两台冷机各自低于约25%额定负荷，接近或低于现有PLR表下限。它符合您指定的“双机平分”，但全年能耗可能受Type666低PLR钳位影响，应统计低PLR时步数。

## 10. 必须修改清单与复跑标准

### 必须修改

1. Unit54控制信号由 `CHWP1_CTRL` 改为 `CHWP2_CTRL`。
2. `IsLoadTime`由 `le(HourOfDay,22)` 改为 `lt(HourOfDay,22)`。

### 强烈建议

1. 显式定义 `CWP1_CTRL/CWP2_CTRL`，不要用冷冻泵名称直接控制冷却泵。
2. 两台冷机的4°C设定值显式连接常数。
3. 确认每个冷却回路是否真的有两台串联泵。
4. 若必须“蓄满后当夜不再启动”，增加锁存或滞环控制。

### 复跑验收标准

- 8台Type110不再出现 `Pump mass balance failed`；
- `failed to converge`清零；
- 工作日0:00-8:00仅发生蓄冷，建筑负荷为0；
- 工作日8:00-22:00只允许 `TankMode`或`ChillerMode`之一为1；
- 22:00后所有冷源和水泵关闭，Unit4负荷为0；
- 夜间 `[51,2]=[52,2]=215000 kg/h`，`[50,2]=430000 kg/h`；
- 水箱释冷时 `[49,2]=1.10*MREQ`；
- 双冷机时 `[51,2]=[52,2]=MREQ/2`；
- 冷却回路1 `[53,2]=[55,2]`，回路2 `[54,2]=[56,2]`；
- 三种模式满足 `ChargeMode+TankMode+ChillerMode<=1`。

## 11. 最终判定

从Equation的目标逻辑看，当前版本约为**基本满足**；从实际连线与仿真质量看，当前版本为**未通过最终验收**。

最关键的立即修改是Unit54错线和22:00边界。修正后仍需解决夜间满罐边界振荡、8台泵质量不平衡和182个未收敛时步，之后才能使用能耗结果评价传统集中供冷策略。
