# 全蓄冷传统策略控制信号 Equation 指导与审稿式建议

分析日期：2026-06-29  
分析对象：`full_storage_cooling/Project11.dck` 与 `load_year_15min_new.csv`  
系统类型：集中供冷水蓄冷系统，传统全蓄冷策略，工作日夜间蓄冷、工作日白天优先释冷。  
审查身份定位：以建筑与能源系统研究者、审稿人的角度，关注控制逻辑的物理一致性、回路路径正确性、信号互斥性和仿真可解释性。

---

## 1. 控制策略的基本权衡

当前目标是传统全蓄冷：工作日 `0:00-8:00` 两台冷机蓄冷，工作日 `8:00-22:00` 优先由蓄冷罐供冷；当蓄冷罐冷量不足时，只开启冷机1直供，冷机2不参与白天供冷。该策略清晰、便于解释，也符合“削峰填谷”的典型研究设定。

但需要指出一个重要限制：TRNSYS 的普通 `Equation` 是代数计算，本身没有“记忆”。如果要严格实现“水箱低于 0.92 SOC 才启动补冷，启动后一直补到满罐才停止”的迟滞锁存，单靠无状态 Equation 并不严谨。最严谨的做法是增加 Type2 差分控制器、Type93 记忆单元，或等价的带状态控制模块。本文先给出可直接落地的无记忆 Equation 方案，并在最后给出更严谨的优化建议。

## 2. 当前模型关键连接关系复核

### 2.1 Type11f 出口定义

你给出的 Type11f 关系是：

```text
flow2 = flow * gam
flow1 = flow * (1.d0 - gam)
Output1 = tin
Output2 = flow1
Output3 = tin
Output4 = flow2
```

因此必须牢记：

- `outlet1` 对应 `Output1/Output2`，流量为 `flow*(1-gam)`。
- `outlet2` 对应 `Output3/Output4`，流量为 `flow*gam`。
- `gam=0` 表示全部走 outlet1。
- `gam=1` 表示全部走 outlet2。
- `gam=0.5` 表示 outlet1/outlet2 各分一半。

### 2.2 本模型中三个分流阀的实际含义

| 分流阀 | Unit | 入口 | outlet1 去向 | outlet2 去向 | 控制含义 |
|---|---:|---|---|---|---|
| 分流阀-1 | 24 | 管道-1，即冷机供水合流后 | 合流阀-2 Unit26，进入供冷总管 | 蓄冷水泵 Unit32，进入蓄冷罐 | `gam24=1` 蓄冷；`gam24=0` 冷机直供 |
| 分流阀-2 | 14 | 管道-4，即回冷机侧主管 | 冷机1 | 冷机2 | `gam14=0.5` 两台冷机均分；`gam14=0` 只走冷机1 |
| 分流阀-3 | 29 | 回水水泵 Unit33 出口 | 蓄冷罐 Port-1 | 合流阀-3 Unit30，再到管道-4 | `gam29=0` 回水进罐释冷；`gam29=1` 回水回冷机直供 |

特别注意：负荷端回水不是直接进入分流阀-3，而是：

```text
负荷需求端 -> 回水总管 Unit28 -> 回水水泵 Unit33 -> 分流阀-3 Unit29
```

这一点是控制信号设计的关键。只要白天存在有效供冷需求，无论是水箱释冷还是冷机1直供，Unit33 回水水泵都应开启。

## 3. 三种运行模式与水路路径

### 3.1 夜间蓄冷模式

触发条件：工作日 `0:00-8:00`，蓄冷罐未达到满罐判据。

运行设备：

- 冷机1、冷机2开启。
- 供冷水泵-1、供冷水泵-2开启。
- 冷却塔1、冷却塔2开启。
- 冷却水泵1、冷却水泵2开启。
- 蓄冷水泵 Unit32 开启。
- 释冷水泵 Unit6 关闭。
- 回水水泵 Unit33 关闭。

水路：

```text
冷机1/2 -> 供冷水泵1/2 -> 合流阀 Unit15 -> 管道-1 Unit25
-> 分流阀-1 Unit24 outlet2 -> 蓄冷水泵 Unit32 -> 蓄冷罐 Port-2
-> 蓄冷罐 Outlet-2 -> 合流阀-3 Unit30 -> 管道-4 Unit31
-> 分流阀-2 Unit14 -> 冷机1/2
```

分流阀信号：

- Unit24：`gam24=1`，冷机出水全部进入蓄冷水泵和蓄冷罐。
- Unit14：`gam14=0.5`，回冷机流量均分给两台冷机。
- Unit29：无负荷回水流量，信号不影响主回路，建议置 `0` 或仅在直供时置 `1`。

### 3.2 白天蓄冷罐释冷模式

触发条件：工作日 `8:00-22:00`，有负荷，蓄冷罐冷量可用。

运行设备：

- 释冷水泵 Unit6 开启。
- 回水水泵 Unit33 开启。
- 冷机1、冷机2关闭。
- 供冷水泵-1、供冷水泵-2关闭。
- 冷却塔、冷却水泵关闭。
- 蓄冷水泵 Unit32 关闭。

水路：

```text
蓄冷罐 Outlet-1 -> 释冷水泵 Unit6 -> 合流阀-2 Unit26
-> 供冷总管 Unit5 -> 负荷需求端 Unit4 -> 回水总管 Unit28
-> 回水水泵 Unit33 -> 分流阀-3 Unit29 outlet1 -> 蓄冷罐 Port-1
```

分流阀信号：

- Unit29：`gam29=0`，回水全部走 outlet1 回蓄冷罐。
- Unit24：无冷机流量，建议置 `0`。
- Unit14：无冷机流量，建议置 `0`。

### 3.3 白天冷机1直供模式

触发条件：工作日 `8:00-22:00`，有负荷，蓄冷罐冷量不足或已空。

运行设备：

- 冷机1开启。
- 供冷水泵-1开启。
- 冷却塔1开启。
- 冷却水泵1开启。
- 回水水泵 Unit33 开启。
- 冷机2、供冷水泵-2、冷却塔2、冷却水泵2关闭。
- 释冷水泵 Unit6 关闭。
- 蓄冷水泵 Unit32 关闭。

水路：

```text
冷机1 -> 供冷水泵-1 -> 合流阀 Unit15 -> 管道-1 Unit25
-> 分流阀-1 Unit24 outlet1 -> 合流阀-2 Unit26
-> 供冷总管 Unit5 -> 负荷需求端 Unit4 -> 回水总管 Unit28
-> 回水水泵 Unit33 -> 分流阀-3 Unit29 outlet2
-> 合流阀-3 Unit30 -> 管道-4 Unit31
-> 分流阀-2 Unit14 outlet1 -> 冷机1
```

分流阀信号：

- Unit24：`gam24=0`，冷机1出水全部走 outlet1 到供冷总管。
- Unit29：`gam29=1`，负荷回水全部走 outlet2 回冷机侧。
- Unit14：`gam14=0`，回水全部走 outlet1 到冷机1。

## 4. 建议 Equation 变量与公式

以下公式可作为一个完整 Equation 组使用。实际写入 TRNSYS Studio 时，需要确认 Equation 数量与变量数量一致，并把输出变量连接到对应设备输入端。

```text
T_cold_sp = 4
! 供冷与蓄冷目标冷水温度；当前冷机 CHW Set Point 宜统一使用 4 C。

T_warm_ref = 12
! 蓄冷罐暖态参考温度；对应设计回水温度 12 C，用于估计 SOC。

dT_dead = 1
! 温度判断死区；用于削弱节点温度单步波动导致的频繁启停。

LoadRaw = [22,1]
! Unit22 读取的负荷原始值；当前 load_year_15min_new.csv 按 kJ/h 处理。

LoadKW = LoadRaw/3600
! 将负荷由 kJ/h 折算为 kW；便于与 3100 kW 机组能力比较。

HasLoad = gt(LoadKW,5)
! 有效制冷需求判断；5 kW 用于过滤数值噪声，避免零负荷时误开泵。

T_tank_avg = [7,5]
! Type534 输出 5，蓄冷罐平均温度；用于估算整体蓄冷状态。

T_node_top = [7,18]
! 当前模型中用于代表冷端/顶部状态的水箱节点温度；用于判断是否已形成足够冷区。

T_node_mid = [7,30]
! 当前模型中部节点温度；用于判断温跃层是否推进到水箱中部。

T_node_bot = [7,42]
! 当前模型暖端/底部节点温度；用于判断释冷是否接近耗尽。

SOC_raw = (T_warm_ref-T_tank_avg)/(T_warm_ref-T_cold_sp)
! 按平均温度估算的原始蓄冷状态；平均温度越接近 4 C，SOC 越高。

SOC = max(0,min(1,SOC_raw))
! 将 SOC 限定在 0-1；0 表示接近暖态空罐，1 表示接近满冷状态。

TankFull = lt(T_node_top,T_cold_sp+dT_dead)*lt(T_node_mid,T_cold_sp+1.5)
! 顶部/冷端和中部都接近 4 C，认为水箱已基本蓄满；比只看平均温度更可靠。

TankEmpty = gt(T_node_bot,T_warm_ref-dT_dead)*gt(T_node_mid,T_warm_ref-3)
! 底部/暖端和中部都偏暖，说明温跃层已基本耗尽，不宜继续优先释冷。

SOC_DischargeMin = 0.10
! 低于 10% SOC 时认为水箱可用冷量不足，应切换为冷机直供。

SOC_ChargeStop = 0.985
! 无记忆 Equation 版本的蓄冷停止近似阈值；接近满罐时停止，避免过冷和频繁迭代。

Chg_bySOC = lt(SOC,SOC_ChargeStop)*(1-TankFull)
! 允许蓄冷判据；SOC 未接近满罐且节点满罐判据未满足时允许蓄冷。

Dch_bySOC = gt(SOC,SOC_DischargeMin)*(1-TankEmpty)
! 允许释冷判据；SOC 足够且水箱未空时，白天优先由蓄冷罐释冷。

HourOfDay = time-24*int(time/24)
! 当前仿真时刻在一天内的小时数；例如 0-8 为夜间蓄冷窗口。

DayNum = int(time/24)
! 从 TRNSYS 绝对仿真时间得到日序号；需与负荷文件首日星期对应关系校准。

WeekIndex0 = DayNum-7*int(DayNum/7)
! 未校准的周内索引，范围 0-6 循环。

WeekdayOffset = 0
! 星期偏移量；必须根据 load_year_15min_new.csv 的首日实际星期校准。

RawWeekIndex = WeekIndex0+WeekdayOffset
! 加入偏移量后的周内索引。

Weekday = RawWeekIndex-7*int(RawWeekIndex/7)
! 归一化后的周内索引；建议约定 0=周一，1=周二，...，6=周日。

IsWorkday = lt(Weekday,5)
! 工作日判断；周一到周五为 1，周六周日为 0。

IsChargeTime = lt(HourOfDay,8)
! 夜间蓄冷时间窗；0:00-8:00 为 1，其余时间为 0。

IsLoadTime = ge(HourOfDay,8)*lt(HourOfDay,22)
! 工作日白天供冷时间窗；8:00-22:00 为 1，其余时间为 0。

ChargeWindow = IsWorkday*IsChargeTime
! 仅工作日夜间允许蓄冷；周末不蓄冷，避免无需求日重复充放。

LoadWindow = IsWorkday*IsLoadTime*HasLoad
! 仅工作日 8:00-22:00 且负荷大于噪声阈值时进入供冷判断。

ChargeMode = ChargeWindow*Chg_bySOC
! 蓄冷模式；夜间、工作日且水箱未满时，两台冷机和蓄冷泵开启。

TankMode = LoadWindow*Dch_bySOC*(1-ChargeMode)
! 水箱释冷模式；白天有负荷且水箱可用时优先释冷，同时与蓄冷模式互斥。

ChillerMode = LoadWindow*(1-Dch_bySOC)*(1-ChargeMode)
! 冷机1直供模式；白天有负荷且水箱不可用时立即开启冷机1。

OffMode = (1-ChargeMode)*(1-TankMode)*(1-ChillerMode)
! 停机模式；不直接连接设备，仅用于检查三种运行模式是否互斥完整。
```

## 5. 设备启停信号

```text
Chiller1_ON = max(ChargeMode,ChillerMode)
! 冷机1在夜间蓄冷和白天冷机直供时开启。

Chiller2_ON = ChargeMode
! 冷机2只在夜间蓄冷时开启；白天冷机直供只允许冷机1运行。

CHWPump1_ON = Chiller1_ON
! 供冷水泵-1与冷机1同步，避免冷机1无流量运行。

CHWPump2_ON = Chiller2_ON
! 供冷水泵-2与冷机2同步，避免冷机2无流量运行。

ChargePump_ON = ChargeMode
! Unit32 蓄冷水泵只在夜间蓄冷模式开启。

DischargePump_ON = TankMode
! Unit6 释冷水泵只在蓄冷罐白天释冷模式开启。

ReturnPump_ON = max(TankMode,ChillerMode)
! Unit33 回水水泵在所有白天供冷模式开启；夜间蓄冷无负荷回水，关闭。

CondPump1_ON = Chiller1_ON
! 冷却水泵1与冷机1同步。

CondPump2_ON = Chiller2_ON
! 冷却水泵2与冷机2同步。

Tower1_ON = Chiller1_ON
! 冷却塔1与冷机1同步，冷机1不开时不应开塔。

Tower2_ON = Chiller2_ON
! 冷却塔2与冷机2同步，白天冷机1直供时冷却塔2保持关闭。
```

## 6. 分流阀控制信号

```text
Gamma24 = ChargeMode
! Unit24 分流阀-1：蓄冷时 gam=1，全部走 outlet2 到蓄冷水泵；冷机直供时 gam=0，全部走 outlet1 到供冷总管。

Gamma29 = ChillerMode
! Unit29 分流阀-3：水箱释冷时 gam=0，回水走 outlet1 回蓄冷罐；冷机直供时 gam=1，回水走 outlet2 回冷机侧。

Gamma14 = 0.5*ChargeMode
! Unit14 分流阀-2：蓄冷时 gam=0.5，两台冷机各 50%；冷机1直供时 gam=0，全部回冷机1。
```

建议连接关系：

| 信号 | 连接到 | 物理含义 |
|---|---|---|
| `Gamma24` | Unit24 Control Signal | 冷机出水去负荷还是去蓄冷罐 |
| `Gamma29` | Unit29 Control Signal | 负荷回水回蓄冷罐还是回冷机 |
| `Gamma14` | Unit14 Control Signal | 回冷机侧流量分配给冷机1/冷机2 |

## 8. 策略宏观检查

### 8.1 互斥性检查

设计上三种主模式满足：

```text
ChargeMode = 夜间蓄冷
TankMode = 白天水箱释冷
ChillerMode = 白天冷机1直供
```

由于 `ChargeWindow` 和 `LoadWindow` 在时间上互斥，夜间蓄冷不会与白天供冷同时发生。`TankMode` 与 `ChillerMode` 通过 `Dch_bySOC` 和 `1-Dch_bySOC` 互斥。因此宏观上不会出现“水箱释冷和冷机直供同时抢流”的问题。

### 8.2 水路路径检查

蓄冷模式：

- Unit24 必须 `gam=1`，否则冷机冷水会错误进入供冷总管。
- Unit14 必须 `gam=0.5`，否则两台冷机不能均分回水。
- Unit32 必须开启，否则冷机供水无法进入蓄冷罐。

释冷模式：

- Unit6 必须开启，Unit32 必须关闭。
- Unit33 必须开启，因为负荷回水必须经回水水泵后进入 Unit29。
- Unit29 必须 `gam=0`，否则回水不会回到蓄冷罐。

冷机1直供模式：

- Unit24 必须 `gam=0`，冷机1出水才能进入合流阀-2和供冷总管。
- Unit29 必须 `gam=1`，负荷回水才能进入合流阀-3、管道-4和冷机侧。
- Unit14 必须 `gam=0`，回水全部进入冷机1，冷机2支路无流量。
- 冷却塔1和冷却水泵1必须与冷机1同步；冷却塔2和冷却水泵2必须关闭。

### 8.3 可能的残余风险

1. `WeekdayOffset` 若未校准，工作日/周末判断可能错位。负荷文件没有显式日期列时，这是最容易被忽略的风险。

2. 无记忆 Equation 版本不能严格实现“低 SOC 启动、满罐停止”的迟滞锁存。当前 `SOC_ChargeStop=0.985` 是可运行的近似方案，但不如带状态控制器严谨。

3. 当水箱从释冷切换到冷机1直供的瞬间，Unit6 关闭、Unit10/9 开启、Unit24/29/14 同时切换，可能出现一个时间步的温度/流量瞬态。建议用 Type65 输出模式信号和关键流量检查。

## 10. 3 点可执行优化建议

1. 将 `SOC`、`ChargeMode`、`TankMode`、`ChillerMode`、`Gamma24`、`Gamma29`、`Gamma14` 输出到 Type65 或 `.plt` 文件，先检查一周典型时段。重点看工作日 0-8 是否只蓄冷，8-22 是否先释冷，水箱空后是否只开启冷机1。

2. 用一个典型工作日做逐时流量核对：蓄冷时 Unit24 outlet2、Unit14 两个 outlet 均应有流量；释冷时 Unit29 outlet1 应有流量、outlet2 应为零；冷机1直供时 Unit24 outlet1、Unit29 outlet2、Unit14 outlet1 应有流量。

3. 若论文或报告需要更强严谨性，增加一个带迟滞的蓄冷许可状态：例如 `SOC < 0.92` 触发补冷，持续运行到 `TankFull=1` 或 `SOC > 0.985` 后停止。这个逻辑建议用 Type2/Type93 等有状态模块实现，而不是只依赖代数 Equation。
