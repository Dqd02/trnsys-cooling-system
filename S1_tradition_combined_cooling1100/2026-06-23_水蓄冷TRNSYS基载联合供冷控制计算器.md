## 1. 先说权衡和总判断

你这次的策略从“水箱优先、冷机后备”改成了更工程化的“冷机基载 + 水箱削峰”。这个方向更符合集中供冷水蓄冷系统：冷机白天不完全停机，而是承担稳定基载；负荷超过冷机能力一定幅度后，水箱释放冷量参与联合供冷。

但当前模型仍有两个必须先处理的水力问题：

1. Unit 36 联合水泵目前在 `Project11.dck` 中入口温度、入口流量、控制信号全部悬空，但初值为开启。这会直接造成 Unit 36 的质量平衡报警。
2. 如果联合供冷时要让总回水 `3300 kW` 级流量经过分流阀-3，再按 `1100:2200` 分成水箱回水和冷机回水，则 Unit 29 的入口必须是联合水泵 Unit 36 的出口，或者是 Unit 33/Unit 36 并联后经过合流器的出口。当前 Unit 29 仍接 Unit 33，无法实现 `354000 kg/h` 总回水分流。

所以，新的控制 Equation 可以写，但在实际连线没有调整前，它只能给信号，不能让联合供冷水路真实成立。

## 3. WeekdayOffset 是否继续等于 0

如果仿真第一天就是周一，那么 `WeekdayOffset = 0` 可以继续。

但必须注意：当前 `START=3216`，如果控制方程直接写：

```text
DayNum = INT(TIME / 24)
WeekIndex0 = DayNum - 7 * INT(DayNum / 7)
```

在仿真开始时：

```text
TIME = 3216
DayNum = 134
134 mod 7 = 1
```

这样会把仿真第一天算成周二，而不是周一。正确做法是用仿真相对时间：

```text
SimStartHour = 3216
SimHour = TIME - SimStartHour
DayNum = INT(SimHour / 24)
```

此时 `SimHour=0` 的第一天就是周一，`WeekdayOffset=0` 才成立。

### 4.3 白天联合供冷：工作日 8:00-22:00，负荷超过阈值且水箱可释冷

你提出的触发条件是“当前承担负荷超过两台冷机联合供冷最大量的 10%”。两台冷机合计：

```text
BaseCap_kW = 2200
Threshold_kW = 2200 * 1.10 = 2420
Threshold_kJh = 2420 * 3600 = 8712000
```

当负荷 `Load_kW > 2420` 且水箱未空时，开启联合供冷。

目标流量分配：

| 支路 | 目标冷量 | 目标流量 |
|---|---:|---:|
| 冷机基载 | `2200 kW` | `236000 kg/h` |
| 水箱释冷 | `1100 kW` | `118000 kg/h` |
| 负荷总流量 | `3300 kW` | `354000 kg/h` |

分流阀-3的比例应为：

```text
outlet1 -> 水箱 Port1: 118000 / 354000 = 1/3
outlet2 -> 合流阀-3/冷机: 236000 / 354000 = 2/3
```

由于 Type11f Mode 2：

```text
outlet1 flow = inlet flow * (1 - gamma)
outlet2 flow = inlet flow * gamma
```

所以联合供冷时：

```text
Gamma_U29 = 2/3 = 0.666667
```

预期流路：

```text
冷机 2200 kW 出水 -> Unit 24 outlet1 -> Unit 26
水箱 1100 kW 出水 -> Unit 6 -> Unit 26
Unit 26 混合 -> Unit 5 -> Unit 4 负荷
-> Unit 28 -> Unit 36 联合水泵
-> Unit 29
   outlet1: 118000 kg/h -> 水箱 Port1 entry Node1
   outlet2: 236000 kg/h -> Unit 30 -> Unit 31 -> Unit 14 -> 冷机
```

## 5. 你担心的“水箱无泵支路会不会自己流动”

### 5.1 分流阀-3 outlet1 能不能主动进入蓄冷罐

在 TRNSYS 这类流量信号模型里，水不是由真实压差网络自动求解的，而是由上游组件输出的质量流量传给下游组件。

如果 Unit 36 已经接在 Unit 28 和 Unit 29 之间，并且 Unit 36 开启输出 `354000 kg/h`，那么 Unit 29 按 `gamma=0.6667` 会给 outlet1 分出 `118000 kg/h`。这个 outlet1 接到水箱 Port1 inlet，因此水箱会接收这 `118000 kg/h`，不需要在 Unit 29 和水箱之间再加水泵。

真正需要的泵是在分流阀-3上游，也就是 Unit 36。它提供总回水流量边界。

### 5.2 蓄冷水泵关闭、释冷水泵开启时，水会不会从水箱 Port2 流到合流阀-3

当前水箱连接是：

| 水箱端口 | 入口来自 | 出口去向 |
|---|---|---|
| Port1 | Unit 29 outlet1 | Unit 6 释冷水泵 |
| Port2 | Unit 32 蓄冷水泵 | Unit 30 合流阀-3 |

联合供冷时，Unit 32 蓄冷水泵应关闭，Unit 24 也应 `gamma=0`，所以 Port2 inlet 流量应为 0。Type534 的 port outlet flow 与对应 port inlet flow相关；Port2 没有入口流量时，理论上 Port2 outlet 到 Unit 30 的流量也应为 0。

因此，在信号正确的情况下，水箱不会同时从 Port2 额外流出到合流阀-3。联合供冷时真正流出水箱的是 Port1 outlet，经 Unit 6 到合流阀-2。

但如果 Unit 32 没有关、Unit 24 仍有 outlet2 流量，或者 Unit 30 的初值/上游残余流量没有消除，就可能出现非物理混流。你的控制信号必须保证：

```text
联合供冷时：
Unit32 = 0
Gamma_U24 = 0
Unit6 = 1
Gamma_U29 = 0.666667
```

## 6. 当前拓扑必须补的连接

现在 Unit 36 是这样：

```text

0,0  ! Inlet fluid temperature
0,0  ! Inlet fluid flow rate
0,0  ! Control signal
0,0  ! Overall pump efficiency
0,0  ! Motor efficiency
```

它没有接到任何水路，所以不能实现联合供冷。

### 6.1 推荐连接方式 A：并联回水泵 + 合流后进 Unit 29

这是最接近你当前意图的做法：

```text
Unit28 回水总管
  -> Unit33 用户回水泵 236000 kg/h
  -> Unit36 联合水泵 354000 kg/h
Unit33 / Unit36 出口
  -> 新增 Type11h 合流阀
  -> Unit29 分流阀-3
```

运行方式：

| 模式 | Unit 33 | Unit 36 | 新合流阀输出 |
---|---:|---:|---:|
| 基载冷机供冷 | 1 | 0 | `236000 kg/h` |
| 联合供冷 | 0 | 1 | `354000 kg/h` |

这种方式的优点是保留 Unit 33 和 Unit 36 两个不同额定流量的单速泵。缺点是要新增一个合流阀，并修改 Unit 29 的入口连接。

### 6.2 推荐连接方式 B：用可变流量泵替代 Unit 33/36

如果你后续愿意换泵模型，用一个可变流量泵会更干净：

```text
Unit28 -> 可变流量回水泵 -> Unit29
```

基载模式给 `236000 kg/h`，联合模式给 `354000 kg/h`。这比两个单速泵并联更接近真实系统的变频泵逻辑，也更少出现质量平衡问题。

如果现在只想少改模型，先用方式 A。

## 7. 新控制计算器 Equation

下面这版按当前新策略写。它假设：

- 仿真第一天是周一。
- 当前 `START=3216`，所以用 `SimHour = TIME - 3216` 计算周内时间。
- 负荷来自 Unit 22，单位为 `kJ/h`。
- 白天冷机始终作为基载开启。
- 负荷超过 `2420 kW` 且水箱未空时，进入联合供冷。
- 水箱蓄满后夜间停止蓄冷。

```text
* ================================================================
* 水蓄冷系统：冷机基载 + 水箱削峰控制计算器
* ================================================================
EQUATIONS 58

! ---------- 基本参数 ----------
SimStartHour = 3216
T_cold_sp  = 4
T_warm_ref = 12
dT_dead    = 1

BaseCap_kW = 2200
PeakAssist_kW = 1100
JointCap_kW = 3300
AssistStart_kW = BaseCap_kW * 1.10

BaseFlow = 236000
AssistFlow = 118000
JointFlow = 354000

! ---------- 负荷读取 ----------
Load_kJh = [22,1]
Load_kW  = Load_kJh / 3600

NeedAssist = GT(Load_kW, AssistStart_kW)

! ---------- 水箱状态 ----------
SOC = MAX(0, MIN(1, (T_warm_ref - [7,5]) / (T_warm_ref - T_cold_sp)))

T_top = [7,18]
T_mid = [7,30]
T_bot = [7,42]

TankFull  = LT(T_top, T_cold_sp + dT_dead) * LT(T_mid, T_cold_sp + 1.5)
TankEmpty = GT(T_bot, T_warm_ref - dT_dead) * GT(T_mid, T_warm_ref - 3)

CanCharge    = LT(SOC, 0.90) * (1 - TankFull)
CanDischarge = GT(SOC, 0.10) * (1 - TankEmpty)

Q_remain_kJ  = 1000 * 1100 * 4.19 * (T_warm_ref - [7,5])
Q_remain_kWh = Q_remain_kJ / 3600

! ---------- 时间判断 ----------
SimHour = TIME - SimStartHour
HourOfDay = SimHour - 24 * INT(SimHour / 24)
DayNum = INT(SimHour / 24)

WeekIndex0 = DayNum - 7 * INT(DayNum / 7)
WeekdayOffset = 0
RawWeekIndex = WeekIndex0 + WeekdayOffset
Weekday = RawWeekIndex - 7 * INT(RawWeekIndex / 7)

IsWorkday = LT(Weekday, 5)
IsChargeTime = LT(HourOfDay, 8)
IsLoadTime = GE(HourOfDay, 8) * LT(HourOfDay, 22)

ChargeWindow = IsWorkday * IsChargeTime
LoadWindow = IsWorkday * IsLoadTime

! ---------- 模式判定 ----------
ChargeMode = ChargeWindow * CanCharge

BaseOnlyMode = LoadWindow * (1 - NeedAssist)
JointMode = LoadWindow * NeedAssist * CanDischarge

! 如果需要削峰但水箱不可释冷，则退回冷机基载直供
BaseFallbackMode = LoadWindow * NeedAssist * (1 - CanDischarge)

BaseSupplyMode = MIN(1, BaseOnlyMode + BaseFallbackMode)
LoadChillerMode = MIN(1, BaseSupplyMode + JointMode)

ChillerMode = MIN(1, ChargeMode + LoadChillerMode)

! ---------- 设备启停 ----------
Sig_Chiller1 = ChillerMode
Sig_Chiller2 = ChillerMode

Sig_CHWP1 = ChillerMode
Sig_CHWP2 = ChillerMode

Sig_CWP1 = ChillerMode
Sig_CWP2 = ChillerMode

Sig_CT1 = ChillerMode
Sig_CT2 = ChillerMode

Sig_ChargePump32 = ChargeMode
Sig_DischargePump6 = JointMode

Sig_UserReturnPump33 = BaseSupplyMode
Sig_JointReturnPump36 = JointMode

! ---------- 分流阀 ----------
Gamma_U14 = 0.5

! Unit24: 0 -> 供冷总管, 1 -> 蓄冷水泵/水箱
Gamma_U24 = ChargeMode

! Unit29: outlet1 = 1-gamma 去水箱, outlet2 = gamma 去冷机
Gamma_U29 = 1 - JointMode * (AssistFlow / JointFlow)

! ---------- 冷机出水设定 ----------
CHW_Set = T_cold_sp

! ---------- 统计与诊断 ----------
UnmetBase_kW = MAX(0, Load_kW - BaseCap_kW)
UnmetJoint_kW = MAX(0, Load_kW - JointCap_kW)
AssistFlowFrac = AssistFlow / JointFlow
ChillerFlowFrac = BaseFlow / JointFlow
```
