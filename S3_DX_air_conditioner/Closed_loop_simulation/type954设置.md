你的初步建议方向是对的，但有两个**致命硬伤**会导致模型直接崩溃或结果完全失真：一是**单位错误**，二是**风量严重偏小**。

基于你上传的 Type954 源码和 130kW 峰值负荷、26℃/60%RH 的控制目标，以下是科学且符合市场实际的参数设置逻辑。

### 🚨 两个必须纠正的硬伤

1. **单位陷阱（最易错）**：
   Type954 的容量和功率参数单位**不是 kW，而是 kJ/h**！
   `1 kW = 3600 kJ/h`。如果你把 130 直接填进容量参数里，模型会认为你的空调只有 36W，系统会瞬间过热。
2. **风量严重不足**：
   你建议的 300 L/s 只能承担约 3~4 kW 的显热负荷。要带走 130kW 的热量，300 L/s 的风量会导致送风温差达到几百度，完全违背物理规律。130kW 的系统，总风量至少在 **9000 L/s** 左右。

### 🧠 核心参数科学推演

#### 1. 容量与功率（考虑安全系数与市场主流）
峰值 130kW，工程选型不能顶格，需考虑 1.1~1.2 的安全系数以及高温工况衰减。建议额定冷量选 **150 kW**。
目前市场主流分体机/多联机的制冷 COP 在 3.0~3.5 之间，我们取 **3.2**。
- **额定总冷量 (Rated total cooling)**：150 kW × 3600 = **540,000 kJ/h**
- **额定总功率 (Rated cooling power)**：(150 / 3.2) × 3600 = **168,750 kJ/h**

#### 2. 显热比 (SHR) 与显热冷量
目标 26℃/60%RH，空调必然在除湿。显热负荷占比（SHR）取决于建筑类型：
- 普通办公/商业：SHR 约 0.75 ~ 0.80
- 人员密集（会议室/餐厅）：SHR 约 0.65 ~ 0.70
这里取中位数 **0.75**。
- **额定显热冷量 (Rated sensible cooling)**：150 kW × 0.75 × 3600 = **405,000 kJ/h**

#### 3. 风量计算（基于物理公式）
显热冷量 112.5 kW (150×0.75)。假设合理送风温差 $\Delta T = 10℃$（26℃ 送 16℃ 的风）。
根据公式 $V = \frac{Q_s}{\rho \cdot c_p \cdot \Delta T}$：
$V = \frac{112500}{1.2 \times 1005 \times 10} \approx 9.33 m^3/s = 9330 L/s$。
- **总风量 / 额定风量 (Total/Rated air flow rate)**：填 **9300 L/s**。（如果是多台内机，请按比例拆分到各个 Type954 中）。

#### 4. 风机功率分配
风机功率通常占总输入功率的 15%~20%。
- **室内风机功率 (Rated indoor fan power)**：约 10% -> 4.6 kW = **16,500 kJ/h**
- **室外风机功率 (Rated outdoor fan power)**：约 5% -> 2.3 kW = **8,300 kJ/h**

#### 5. 湿度控制逻辑（关键 Insight）
你希望维持 60% RH，建议把 `Minimum %RH for latent heat transfer` 设为 **55**，而不是 60。
**原因**：源码中 `If (RH_in <= RH_minimum)` 会触发纯显热模式（停止除湿）。如果设为 60，当湿度刚降到 60% 时，机器停止除湿但继续降温，导致相对湿度进一步下降，随后机器又被迫重启除湿。这会在 60% 临界点引发**剧烈震荡**。设为 55 可以提供一个合理的控制死区，允许湿度在 55%~65% 之间自然波动，这才是符合真实空调控制逻辑的做法。

### ⚠️ Type954 的“隐藏坑点”
Type954 **不是一个简单的 COP 效率模型**，它是一个**查表模型**。
你填入的上述 `Rated_xxx` 参数仅仅是**基准缩放因子**。模型实际输出的冷量和功率，是这些基准值乘以外部数据文件（Catalog data）中插值得到的修正系数。
**因此，你必须确保 `LU_cool` 指向的性能数据文件是准确的**（包含不同室外干球温度、室内干/湿球温度下的容量和功率修正系数）。如果没有真实厂家的数据文件，至少需要构建一份以额定点（如室外 35℃，室内 27℃/19℃）为 1.0 的标准衰减曲线，否则仿真结果将毫无意义。

### Rated sensible cooling capacity

你设 `SHR = 0.75` 是可以的。SHR 是 sensible heat ratio，即显热比：

```
SHR = 显冷量 / 总冷量
```

所以：

```
Rated_sensible_c = SHR × Rated_total_c
```

如果：

```
Rated_total_c = 207000 kJ/hSHR = 0.75
```

那么：

```
Rated_sensible_c = 155250 kJ/h
```

对于办公室、会议室这类人员和新风负荷都存在的区域，`SHR=0.75` 是一个比较稳妥的初值。若后面发现 RH 长期偏高，说明潜热能力不足，可以把 SHR 降到 `0.70` 或 `0.65`；如果房间湿度很低、除湿过强，可以提高到 `0.80` 左右。

注意：**Rated sensible cooling capacity 不能大于 Rated total cooling capacity。** Type954 源码中也有检查显冷量、总冷量、功率等非法值的逻辑。

## Minimum %RH for latent heat transfer 是什么意思？

这个参数非常容易误解。它**不是室内湿度设定值**，也不是“我要把房间控制在多少 RH”。

它的真实含义是：

```
当进入 Type954 的回风相对湿度低于这个阈值时，模型停止计算潜热除湿，只做显热冷却。
```

Type954 源码开头也写了：当 RH 低于用户指定设定值时，会锁定/关闭潜热冷却。 在制冷计算里，代码判断 `RH_in <= RH_minimum` 时，会令 `Q_total_c = Q_sensible_c`，也就是不再产生潜冷量，出风含湿量保持不变。

举例：

```
Minimum %RH for latent = 20
```

表示只要回风 RH 大于 20%，模型都可能除湿。这会导致除湿很积极，房间湿度可能被拉得偏低。

```
Minimum %RH for latent = 55
```

表示当回风 RH 低于 55% 时，停止除湿。这样更接近舒适性控制，不会无限制拉低湿度。

针对你的建筑闭环，我建议：

```
初始调试：Minimum %RH for latent = 50正式工况：50–60如果目标室内 RH ≈ 60%，可取 55 或 60 做对比
```

但一定要记住：它只是“除湿下限保护”，不是完整湿度控制器。如果你要严格控制 RH=60%，还需要单独湿度控制逻辑。
