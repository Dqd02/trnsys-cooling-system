# Type682 总负荷直连的四功能区分体式空调闭环搭建指南

日期：2026-07-13  
适用软件：TRNSYS 18 + TESS HVAC Library  
负荷数据：`building_simulation_new` 下 4 个 `*_kj_hr.csv`  
参考模型：`DX/Closed_loop_simulation/Untitled_imported.dck`

## 1. 采用的方案与模型口径

本指南采用以下明确方案：

> 每个 CSV 热区列中的“显热+潜热总冷负荷”不再拆分，直接以正值、kJ/h 接入 Type682 的 Load 输入；Type682 将总负荷等效为回风流股温升，Type954a 负责实际制冷，Type2b 根据 Type682 出口温度控制压缩机启停。

该方案的主要优点是模块少、连线清楚、与现有 Type954a 闭环工程接近，适合先完成四个功能区各 1 套原型，再扩展到 48 套。

本方案只保留一个必要边界：Type682 是流股负荷模型，不是 Type56 建筑热平衡模型。因此本文中的 Type682 出口温度统一称为“等效回风温度”。它可以用于闭环控制和设备能力比较，但不单独作为建筑室温、湿度舒适性结论。

## 2. 建模目标和验收目标

### 2.1 核心目标

不用 Type56，用已有逐热区总冷负荷驱动 Type682 与 Type954a，形成：

```text
负荷文件 -> Type682 等效负荷端 -> Type954a 分体式空调 -> Type682
```

先建立办公室、会议室、厕所、走廊各 1 套，验证：

1. 总负荷读取正确；
2. Type682 总负荷方向和单位正确；
3. Type954a 能根据等效回风温度启停；
4. 制冷量、功率、COP 和未满足负荷能够输出；
5. 四套原型稳定后可复制为 48 套。

### 2.2 四个代表热区

选择 08:30-22:00 稳态窗口内最不利热区作为原型：

| 功能区 | 文件 | 原型热区 | Type9e 目标输出 | 稳态最大负荷 | 建议额定总冷量 |
|---|---|---|---:|---:|---:|
| 办公室 BGS | `BGS_kj_hr.csv` | N6 | Output 13 | 70.37 kW | 80 kW |
| 会议室 HYS | `HYS_kj_hr.csv` | NM6 | Output 13 | 43.26 kW | 50 kW |
| 厕所 CS | `CS_kj_hr.csv` | PO6 | Output 13 | 32.76 kW | 37.78 kW |
| 走廊 ZL | `ZL_kj_hr.csv` | SO6 | Output 7 | 31.33 kW | 36 kW |

这些容量约有 13.7%-15.6% 的稳态峰值余量。08:15 的启动尖峰可能仍超过设备能力，应作为短时未满足负荷输出，不建议据此把全部设备大幅放大。

## 3. 总体闭环结构

每个热区的主闭环如下：

```text
                    Type15 天气
                         |
                         v
Type9e -> Qload -> Type682 -> T_return -> Type2b -> CoolCtrl
                    ^          |                     |
                    |          +---------------------+----> Type954a
                    |                                |
                    +---- T_supply, m_air <-----------+
```

详细信号方向：

```text
Type9e 负荷输出
    -> Equation：Qload、LoadEnable
    -> Type682 Input 3 Load

Type954a Output 1 送风温度
    -> Type682 Input 1 入口温度

Type954a Output 4 送风干空气质量流量
    -> Type682 Input 2 入口流量

Type682 Output 1 等效回风温度
    -> Type954a Input 1 回风温度
    -> Type2b 温控输入

Type682 Output 2 回风流量
    -> Type954a Input 4 回风流量

Type2b Output 1
    -> Type954a Input 11 制冷控制

LoadEnable
    -> Type954a Input 13 风机控制
```

有负荷时风机保持运行，压缩机由 Type2b 回差控制。这样压缩机关闭时仍有流量通过 Type682，负荷能够形成等效回风温升并重新触发制冷。

### 4.2 四套共用模块

| 模块 | 数量 | 功能 |

## 5. Type9e 负荷读取

四个文件都是制表符分隔的 TRNSYS 打印文件：

- 第一列为 `TIME`；
- 后面 12 列为热区总冷负荷；
- 时间范围 0-8760 h；
- 时间步长 0.25 h；
- 负荷单位 kJ/h；
- 每个文件 35,041 个数据行。

### 5.1 Type9e 参数

每个功能区放 1 个 Type9e：

| 参数 | 建议值 | 说明 |
|---|---:|---|
| Mode | 5 | 文件第一行数据对应 time=0，非零 START 时自动跳行 |
| Header Lines to Skip | 1 | 跳过列名 |
| No. of values to read | 13 | TIME + 12 个热区 |
| Time interval of data | 0.25 h | 与 CSV 一致 |
| Interpolate or not | -1 | 15 min 内保持该负荷，不线性插值 |
| Multiplication factor | 1 | 已经是 kJ/h |
| Addition factor | 0 | 不平移 |
| Average or instantaneous | 0 | 按时间步平均值读取 |
| Free format mode | -1 | 自由格式、制表符分隔 |
| Logical Unit | 唯一 | 可用 150-153，不能与性能文件 LU 重复 |

### 5.2 目标输出映射

Type9e 会把 `TIME` 作为 Output 1：

| 文件 | Output 2-13 对应热区 | 原型输出 |
|---|---|---|
| BGS | S1-S6、N1-N6 | N6 = Output 13 |
| HYS | Sm1-Sm6、NM1-NM6 | NM6 = Output 13 |
| CS | WO1-WO6、PO1-PO6 | PO6 = Output 13 |
| ZL | SO1-SO6、NO1-NO6 | SO6 = Output 7 |

### 5.3 负荷 Equation

办公室 N6 示例：

```text
Qload_BGS = max([BGS_LoadReader,13],0)
LoadEnable_BGS = gt(Qload_BGS,1.0)
Qload_BGS_kW = Qload_BGS/3600
```

会议室和厕所仍取 Output 13，走廊 SO6 改取 Output 7。`Qload` 保持 kJ/h 直接接 Type682，不除以 3.6，也不除以 3600。

在连接 Type682 前，先用 Type65/Type25 核对 3216.00、3216.25 和 5480.25 h 的时间及负荷值，确认没有整体错位 0.25 h。

## 6. Type682 设置

Type682 路径通常为：

```text
Loads and Structures (TESS)
  -> Flowstream Loads
  -> Other Fluids
  -> Type682
```

### 6.1 参数

```text
Fluid Specific Heat = 1.006 kJ/(kg.K)
```

这里的流股是空气，所以不能使用冷冻水的 4.19 kJ/(kg.K)。

### 6.2 五个输入

| Type682 输入 | 连接来源 | 初始值/说明 |
|---:|---|---|
| 1 Inlet Temperature | Type954a Output 1 | 空调送风温度，初始可设 16 C |
| 2 Inlet Flowrate | Type954a Output 4 | 干空气质量流量，kg/h |
| 3 Load | Type9e 经 Equation 的 `Qload` | 总冷负荷正值，kJ/h |
| 4 Minimum Heating Temperature | 常数 -999 C | 本项目不供热 |
| 5 Maximum Cooling Temperature | 40 C 起步 | 限制异常升温，剩余量进入 Output 6 |

正式稳定运行后，可把 Maximum Cooling Temperature 从 40 C 提高到 50 C 做敏感性测试。若直接设为 999 C，容量不足或控制失稳时等效回风温度可能迅速越出 Type954a 性能表范围。

### 6.3 关键输出

| 输出 | 名称 | 用途 |
|---:|---|---|
| 1 | Outlet Temperature | 等效回风温度，反馈 Type954a 和 Type2b |
| 2 | Outlet Flowrate | 回风流量，反馈 Type954a Input 4 |
| 3 | Heating Load Met | 制冷模型中应为 0 |
| 4 | Cooling Load Met | 流股实际吸收的总等效负荷 |
| 5 | Heating Load Met by Auxiliary | 应为 0 |
| 6 | Cooling Load Met by Auxiliary | 温度上限导致的虚拟备用冷量 |

Type682 的基本关系为：

```text
Q682_met = m_air*1.006*(T_return-T_supply)
```

且应满足：

```text
Qload = Type682 Output 4 + Type682 Output 6
```

Output 6 不是 Type954a 的实际供冷量。本文把它作为“容量不足或温度上限触发的虚拟备用冷量”输出；正常稳定工况应尽量接近 0。

### 7.1 四套首轮参数

| Type954a 参数 | BGS-N6 | HYS-NM6 | CS-PO6 | ZL-SO6 |
|---|---:|---:|---:|---:|
| 1 Humidity mode | 2 | 2 | 2 | 2 |
| 10 Total air flow rate, L/s | 4640 | 3100 | 1900 | 2240 |

参数 10 和参数 18 必须同步。参数 13-15 的单位是 kJ/h，不是 kW。


这些文件是 TESS 归一化样本数据。正式论文应说明它们不是具体厂家产品曲线。

| 输入 | 来源/数值 |
|---:|---|
| 1 Return air temperature | Type682 Output 1 |
| 2 Return air humidity ratio | 常数/初值 0.012 |
| 3 Return air %RH | 常数 0.60 |
| 4 Return air flow rate | Type682 Output 2 |
| 5 Inlet pressure | 1 atm |
| 6 Fan pressure rise | 0 atm |
| 7 Outside air temperature | Type15 Output 1 |
| 8 Outside air humidity ratio | Type15 Output 6 |
| 9 Outside air %RH | Type15 Output 7 |
| 10 Ambient sink temperature | Type15 Output 1 |
| 11 Cooling control signal | `CoolCtrl`，来自 Type2b |

| 输出 | 含义 |

| 1 | 送风温度，接 Type682 Input 1 |

| 3 | 送风 RH，仅作诊断 |
| 4 | 送风干空气质量流量，接 Type682 Input 2 |
| 6 | 实际总制冷量，kJ/h |

| 8 | 实际潜冷量，kJ/h |

| 17 | 室外风机功率 |
| 18 | 压缩机功率 |
| 21 | 冷凝水流量，kg/h |

根据本机 `Type954.f90`，参数 15 和 Output 13 已包含室内外风机功率。不要把 Output 16、17、18 再加到 Output 13 上，否则会重复计算。

## 8. Type2b 温控器

选择：

```text
Controllers
  -> Differential Controller w/ Hysteresis
  -> Complex Control Strategies
  -> Solver 0
  -> Type2b
```

### 8.1 参数

```text
No. of oscillations = 5
High limit cut-out = 100
```

### 8.2 输入设置

目标控制区间为 25.5-26.5 C：

| Type2b 输入 | 连接/数值 |
|---:|---|
| 1 Upper input temperature Th | Type682 Output 1 |
| 2 Lower input temperature Tl | 常数 25.5 C |
| 3 Monitoring temperature Tin | Type682 Output 1 |
| 4 Input control function | `LoadEnable` |
| 5 Upper dead band dT | 1.0 K |
| 6 Lower dead band dT | 0.0 K |

预期逻辑：

```text
T_return >= 26.5 C -> 压缩机开启
T_return <= 25.5 C -> 压缩机关闭
25.5-26.5 C       -> 保持上一状态
```

Equation：

```text
CoolCtrl_BGS = [BGS_Controller,1]*LoadEnable_BGS
FanCtrl_BGS = LoadEnable_BGS
```

Cooling control 接 `CoolCtrl`；Fan control 接 `FanCtrl`。不要把风机也只接 `CoolCtrl`，否则压缩机关闭时 Type682 没有空气流量，负荷不能形成温升。

| 序号 | 起点 | 终点 |

## 11. 推荐搭建步骤

### 11.1 第一步：只验证负荷读取

1. 放置 BGS Type9e；
2. 读取 13 个值；
3. 输出 TIME 和 N6；
4. 确认负荷单位为 kJ/h；
5. 确认 15 min 时间对齐。

验收：Type9e 输出与 CSV 同一行完全一致。

### 11.2 第二步：单独验证 Type954a

暂时使用固定输入：

```text
T_return = 26 C
w_return = 0.012
RH_return = 0.60
Cooling control = 1
Fan control = 1
OA damper = 0
```

接入 Type15，运行盛夏 24 h。输出 Type954a 的 1、4、6、7、8、13、14、16-18。

验收：冷量和功率为正，Output 13 约等于 16+17+18，COP 合理，性能文件无 Fatal Error。

### 11.3 第三步：用常数负荷验证 Type682

先不要接 CSV，使用办公室常数负荷：

```text
Qload = 144000 kJ/h = 40 kW
```

Type954a Output 1/4 接 Type682 Input 1/2，Type682 Input 3 接常数负荷。

验收：

```text
Type682 Output 4 + Output 6 = 144000 kJ/h
Type682 Output 1 > Type954a Output 1
```

### 11.4 第四步：闭合温度与流量环

把 Type682 Output 1/2 接回 Type954a Input 1/4，暂时让制冷和风机均为 1。

验收：连续运行 24 h，无 Fatal Error；Type682 温升方向正确；Type954a 回风温度等于 Type682 出口温度。

### 11.5 第五步：加入 Type2b

1. Type682 Output 1 接 Type2b；
2. Type2b 输出接 Type954a Cooling control；
3. 风机控制保持 1 或接 `LoadEnable`；
4. 使用 Solver 0；
5. 观察温度、控制信号、制冷量和功率。

验收：温度在控制带附近变化，压缩机能开关，风机在有负荷时不停止。

### 11.6 第六步：恢复逐时 N6 负荷

把 Type682 Load 从常数切回 `Qload_BGS`，先跑典型盛夏工作日，再跑一周。

办公室稳定后再复制 HYS、CS、ZL，避免四套同时出现问题时无法定位。

## 13. Equation 汇总

以 BGS-N6 为例：

```text
Qload_BGS = max([Load_BGS,13],0)
LoadEnable_BGS = gt(Qload_BGS,1.0)
CoolCtrl_BGS = [Ctrl_BGS_N6,1]*LoadEnable_BGS
FanCtrl_BGS = LoadEnable_BGS

Qload_BGS_kW = Qload_BGS/3600
Qcool_BGS_kW = [DX_BGS_N6,6]/3600
P_BGS_kW = [DX_BGS_N6,13]/3600
Qmet682_BGS_kW = [Zone_BGS_N6,4]/3600
Qaux682_BGS_kW = [Zone_BGS_N6,6]/3600

Balance_BGS = Qload_BGS-[Zone_BGS_N6,4]-[Zone_BGS_N6,6]
```

其余三套仅替换 Unit、输出列和变量后缀。

如果使用 Type24 积分：

```text
E_load_input = Qload_kW
E_cooling_input = Qcool_kW
E_power_input = P_kW
E_aux_input = Qaux682_kW
```

Type24 对 kW 随小时积分，输出即 kWh。

## 14. 必须输出的变量

### 14.1 单热区最小输出集

| 类别 | 输出 |

## 15. 验收标准

### 15.1 Type682 守恒

```text
epsilon_682 = abs(Qload-Qmet682-Qaux682)/max(Qload,1)
```

建议：

```text
epsilon_682 < 0.1%
```

并检查：

```text
Qmet682 = m_air*1.006*(T_return-T_supply)
```

### 15.2 控制和设备

1. 有负荷时风机流量不能为 0；
2. Type2b 输出只在 0 和 1 之间；
3. 等效回风温度主要位于 25.5-26.5 C 附近；
4. Type954a Output 6、13 不为负；
5. Output 13 约等于 Output 16+17+18；
6. COP 不应长期为 0 或异常大值；
7. 性能表不应连续越界或被钳制；
8. Message 441 不应连续出现。

### 15.3 负荷满足

完整供冷期统计：

- Type682 Output 6 大于 0 的小时数；
- Type682 Output 6 累计 kWh；
- 等效回风温度超过 28 C 的时间；
- Type954a 连续满负荷运行时间；
- 08:15 启动尖峰对应的虚拟备用冷量；
- 总冷量与总电耗。

若 Output 6 只在少量 08:15 时间步出现，可将其解释为启动尖峰造成的短时能力缺口；若白天稳定时段长期出现，应检查容量、风量、性能表或控制逻辑。

## 17. 常见错误

1. **把 CSV 负荷除以 3600 后接 Type682。** Type682 Load 单位就是 kJ/h，CSV 直接连接。
2. **Type682 比热填 4.19。** 这是水的比热；空气流股使用约 1.006。
3. **正冷负荷取负号。** Type682 正冷负荷会使流股升温，本方案不取负。
4. **风机控制与压缩机完全相同。** 压缩机停机后流量归零，Type682 无法形成温升。
5. **Return air RH 填 60。** Type954a 输入要求 0.60；只有参数 20 填 50 这类百分数。
6. **Outside air damper 不为 0。** 会重复计入新风负荷。
7. **参数 10 与参数 18 不一致。** 会改变性能表风量比。
8. **把 Output 13 与 16、17、18相加。** Output 13 已经是总功率。
9. **把 Type682 Output 6 当作 Type954a 实际供冷。** 它是虚拟辅助/备用量。
10. **一开始就复制 48 套。** 列号、LU 或单位错误会很难定位。

## 18. 论文中的建议表述

可写为：

> 采用预计算的逐热区总冷负荷作为外部边界，利用 TESS Type682 将该负荷等效施加于分体式空调循环空气流股。Type954a 根据室外气象与等效回风温度计算送风状态、制冷量及电功率，Type2b 通过回差控制实现单速机组启停。每个热区配置一套等效分体式空调系统。

英文可表述为：

> The pre-calculated total cooling load of each thermal zone was imposed on the recirculating air stream using TESS Type682. A Type954a split-system heat pump calculated the supply-air state, cooling output, and electric power, while a Type2b differential controller regulated on/off operation based on the equivalent return-air temperature.

需要避免写成：

> Type682 independently calculated the dynamic indoor temperature and humidity of the building.

Type682 在本模型中承担的是总负荷流股转换，不是完整建筑热湿计算。

## 20. 推荐结论

对当前研究阶段，最直接且可执行的结构是：

```text
Type9e 总负荷
  -> Type682 总负荷温升
  -> Type954a 分体式空调制冷
  -> Type682
```

控制上使用 Type682 等效回风温度驱动 Type2b；有负荷时维持室内风机运行，压缩机按 25.5-26.5 C 回差启停。四个功能区先采用 N6、NM6、PO6 和 SO6 原型，额定总冷量分别为 80、50、37.78 和 36 kW。完成负荷读取、Type682 守恒、Type954a 功率和控制稳定性验证后，再按相同模板复制到其余 44 个热区。
