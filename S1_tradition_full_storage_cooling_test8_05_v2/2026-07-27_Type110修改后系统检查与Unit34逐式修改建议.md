检查日期：2026-07-27

## 1. 先说权衡与结论

### 1.1 权衡

当前模型已经把全部 8 台水泵替换为 Type110，并保留了原额定流量和额定功率。这个修改方向正确。您设置的功率参数：

```text
Number of power coefficients = 3
Power coefficient-1 = 0.2
Power coefficient-2 = 0.3
Power coefficient-3 = 0.5
```

在 Type110 中对应：

```text
P/P_rated = 0.2 + 0.3*u + 0.5*u^2    (u > 0)
P = 0                                  (u <= 0)
```

其优点是三项系数之和为 `1.0`，所以 `u=1` 时泵耗恰好等于额定功率，参数格式和额定点都正确。代价是常数项为 `0.2`：信号只要略大于 0，泵耗就立刻接近额定功率的 20%，低流量节能幅度偏小。若这组系数来自厂家拟合，应保留；若只是暂定值，应在论文中注明，并做功率曲线敏感性分析。

### 1.2 当前系统结论

当前版本判定为：**组件替换完成，但控制尚未满足要求，仿真结果暂不能用于最终能耗比较。**

主要原因：

1. Unit49-56 的 Type110 第 3 输入仍接原来的 0/1 启停信号，运行时只有 0 或 100% 流量，实际上尚未形成白天负荷跟随变频。
2. Unit34 仍采用“白天水箱用完后只开冷机1”的旧策略，不符合“两台冷机各承担一半”的新要求。
3. 最新日志中 8 台 Type110 全部报告质量不平衡，且有 133 个时步未收敛。
4. `CondPump1_ON`、`CondPump2_ON` 以 `CON` 开头，触发 TRNSYS 保留字警告，必须改名。
5. 冷却侧每台冷机仍有两台串联 Type110。若为真实串联泵可以保留，但同一回路两台泵必须使用完全相同的信号；若是重复模块，会重复计算泵耗。
6. Unit7 的 Type534 数据文件仍用绝对路径指向旧的 `S1_tradition_full_storage_cooling3100/Example_534.dat`，当前目录里的同名文件未必被读取。

## 4. Unit34 推荐替换公式

### 4.1 修改前的连接动作

在改 Equation 前，先在 Studio 中把 8 台泵第 3 输入改接为以下变量：

| Unit | 第3输入应连接 |
|---:|---|
| 49 释冷泵 | `DCHP_CTRL` |
| 50 蓄冷泵 | `CHGP_CTRL` |
| 51 供冷泵1 | `CHWP1_CTRL` |
| 52 供冷泵2 | `CHWP2_CTRL` |
| 53、55 冷却回路1两台串联泵 | `CWP1_CTRL` |
| 54、56 冷却回路2两台串联泵 | `CWP2_CTRL` |

Type126 冷却塔仍分别接 `Tower1_ON`、`Tower2_ON`，不要接连续泵信号。

### 4.2 建议将 Unit34 的 Equation 数量从 39 改为 52

```text
T_cold_sp = 4
T_warm_ref = 12
dT_dead = 1
CpW = 4.19
DTCHW = 8
M_CHW_R = 215000
M_DCH_R = 430000

T_tank_avg = [7,5]
T_node_top = [7,18]
T_node_mid = [7,30]
T_node_bot = [7,42]
SOC = max(0,min(1,(T_warm_ref-T_tank_avg)/(T_warm_ref-T_cold_sp)))
TankFull = lt(T_node_top,T_cold_sp+0.5)*lt(T_node_mid,T_cold_sp+dT_dead)
TankEmpty = gt(T_node_bot,T_warm_ref-dT_dead)*gt(T_node_mid,T_warm_ref-3)
Chg_bySOC = lt(SOC,0.95)*(1-TankFull)
TankOutletOK = le([7,1],5.0)
TankAvailable = gt(SOC,0.1)*(1-TankEmpty)*TankOutletOK

LoadKW = max(0,[22,1]/3600)
HasLoad = gt(LoadKW,5)
MREQ = LoadKW*3600/(CpW*DTCHW)
DCH_CTRL_RAW = 1.05*MREQ/M_DCH_R

HourOfDay = time-24*int(time/24)
DayNum = int(time/24)
WeekIndex0 = DayNum-7*int(DayNum/7)
WeekdayOffset = 0
RawWeekIndex = WeekIndex0+WeekdayOffset
Weekday = RawWeekIndex-7*int(RawWeekIndex/7)
IsWorkday = lt(Weekday,5)
IsChargeTime = lt(HourOfDay,8)
IsLoadTime = ge(HourOfDay,8)*lt(HourOfDay,22)
ChargeWindow = IsWorkday*IsChargeTime
LoadWindow = IsWorkday*IsLoadTime*HasLoad

ChargeMode = ChargeWindow*Chg_bySOC
TankFlowOK = le(DCH_CTRL_RAW,1)
TankCanCover = TankAvailable*TankFlowOK
TankMode = LoadWindow*TankCanCover*(1-ChargeMode)
ChillerMode = LoadWindow*(1-TankCanCover)*(1-ChargeMode)
OffMode = (1-ChargeMode)*(1-TankMode)*(1-ChillerMode)

DCHP_CTRL = TankMode*min(1,DCH_CTRL_RAW)
CHW_DAY_CTRL = ChillerMode*min(1,MREQ/(2*M_CHW_R))
CHWP1_CTRL = max(ChargeMode,CHW_DAY_CTRL)
CHWP2_CTRL = max(ChargeMode,CHW_DAY_CTRL)
CHGP_CTRL = ChargeMode

Chiller1_ON = max(ChargeMode,ChillerMode)
Chiller2_ON = max(ChargeMode,ChillerMode)
CWP1_CTRL = CHWP1_CTRL
CWP2_CTRL = CHWP2_CTRL
Tower1_ON = Chiller1_ON
Tower2_ON = Chiller2_ON

Gamma24 = ChargeMode
Gamma29 = ChillerMode
Gamma14 = 0.5*max(ChargeMode,ChillerMode)
```

## 5. 修改后关键工况复算

### 5.1 极端峰值 3140.26 kW

```text
总需求流量 = 3140.26*3600/(4.19*8)
             = 337259 kg/h

每台供冷泵流量 = 337259/2
                 = 168630 kg/h

每台供冷泵信号 = 168630/215000
                 = 0.784

每台冷机承担负荷 = 3140.26/2
                   = 1570.13 kW
```

结论：两台 `2000 kW` 冷机能够覆盖，单台泵约为额定流量的 78.4%，不是小流量工况。

若水箱可用：

```text
释冷泵信号 = 1.05*337259/430000 = 0.824
```

所以水箱流量能力同样足够覆盖该峰值。

### 5.2 稳定峰值 1960.69 kW

```text
总需求流量 = 210575 kg/h
每台流量 = 105288 kg/h
每台供冷泵信号 = 0.490
每台冷机负荷 = 980.35 kW
```

### 5.3 低负荷风险

当总负荷低于约 `1000 kW` 时，两台冷机各自低于额定容量的 25%。现有 PLR 文件最低点为 0.25，所以严格执行“双机始终各一半”可能使 Type666 在低负荷时钳位或循环运行。该策略可按您的研究要求执行，但必须在结果中单独检查低于最小 PLR 的时步数。

### 6.3 质量不平衡的直接原因

Type110 强制：

```text
m_out = control*m_rated
```

当前控制只有0/1，模式切换时泵会立即从0跳到额定流量；但上游冷机、阀门、Type534 和管道的入口流量未必在同一迭代立即等于该值，所以 Type110 记录质量不平衡。白天旧控制又只开冷机1、Unit14 全部回水给冷机1，与新的“双机各一半”目标不一致。

推荐公式通过让每条闭式回路中的串联泵使用同一连续信号，并让 Unit14 的流量分配与两台供冷泵相匹配，解决结构性不平衡。切换瞬间若仍有少量警告，需再增加带滞环或锁存的模式控制，而不是放宽收敛容差掩盖问题。
